\begin{abstract}
Subset sum asks whether some of the given integers add up to a target value.
The best known algorithm that works on every input takes about $2^{n/2}$ steps
for $n$ integers, and nobody knows whether $2^{n/3}$ is possible. This note
does not answer that question. It sets up a clean, checked starting point for
anyone who wants to work on it. We explain the problem and the notation, then
describe and prove correct three exact solvers: meet-in-the-middle, a
dynamic program over all reachable sums, and the Schroeppel--Shamir algorithm.
On inputs with no
solution, the measured running time grows like $2^{n/2}$ for both
meet-in-the-middle and Schroeppel--Shamir, and Schroeppel--Shamir uses memory
that grows only like $2^{n/4}$. We also note the easy case where the numbers
are small: if their absolute values add up to at most $2^{n/3}$, the dynamic
program already runs in about $2^{n/3}$ steps. That case is textbook material
and says nothing about the general question.
\end{abstract}
\begin{IEEEkeywords}
subset sum, knapsack, exact algorithms, meet-in-the-middle, Schroeppel--Shamir
\end{IEEEkeywords}

\section{Introduction}
Suppose you have $n$ integers and a target. Can you pick some of them so that
the picked numbers add up exactly to the target? This is the \emph{subset sum}
problem. For the numbers $3,5,8,13$ and target $16$ the answer is yes, in two
ways: $3+13$ and $3+5+8$. For target $2$ the answer is no.

Written as an equation, given integers $a_1,\dots,a_n$ and $b$, we ask whether
\begin{equation}\label{eq:problem}
\exists x\in\{0,1\}^n:\quad\sum_{i=1}^{n}a_i x_i=b.
\end{equation}
Each $x_i$ says whether $a_i$ is picked ($x_i=1$) or not ($x_i=0$). This is the
same as the yes/no version of the 0--1 knapsack problem.

\subsection{Why it matters}
Subset sum is one of the standard NP-complete problems, so nobody expects a
polynomial-time algorithm. It also shows up in practice. Early public-key
schemes such as the Merkle--Hellman knapsack cryptosystem~\cite{mh} based
their security on it, and ideas from subset sum algorithms are still used in
attacks on code-based and lattice-based schemes. Many budgeting and packing
questions reduce to it as well.

Because a polynomial algorithm is not expected, the interesting question is
how fast the exponential part can be. Trying every subset costs $2^n$ steps.
The meet-in-the-middle method of Horowitz and Sahni~\cite{hs} brings this down
to about $2^{n/2}$, and that is still the best known bound that holds for
every input, 50 years later. The difference between exponents is large in
practice. For $n=60$, $2^{n/2}$ is about $10^9$ while $2^{n/3}$ is about
$10^6$. For $n=100$ the gap is about $10^{15}$ versus $10^{10}$.

\subsection{What is known}
Schroeppel and Shamir~\cite{ss} kept the $2^{n/2}$ time and cut the memory to
$2^{n/4}$. Chen, Jin, Randolph and Servedio~\cite{chen} shaved a polynomial
factor off the time, to $2^{n/2}/n^{0.5023}$, but the exponent is still $1/2$.
On \emph{random} inputs, the representation technique of
Howgrave-Graham and Joux~\cite{hgj} and Becker, Coron and Joux~\cite{bcj} is
much faster, about $2^{0.291n}$, but those bounds rely on assumptions about how
random inputs behave and do not hold for every input. Randolph and
W\k{e}grzycki~\cite{rw} recently beat $2^{n/2}$ for every input on several
related problems, but not for subset sum itself. So whether $2^{n/3}$ (or
anything below $2^{n/2}$) is possible for every input is still open. We make no
claim about it.

\subsection{What this note does}
This note covers the problem, the notation, and the classical exact
algorithms, with proofs and measurements. Its contents are:
\begin{itemize}
\item a self-contained introduction to the problem and its notation
(Section~\ref{sec:prelim});
\item correctness and running-time proofs for meet-in-the-middle, a signed
dynamic program, and Schroeppel--Shamir
(Sections~\ref{sec:mitm}--\ref{sec:ss});
\item measurements of running time and memory on inputs with no solution
(Section~\ref{sec:measure}).
\end{itemize}
Section~\ref{sec:goal} states what a real $2^{n/3}$ result would have to show.

\section{Preliminaries}\label{sec:prelim}
This section collects the definitions used in the rest of the paper. Readers
who already know the area can skip it.

\subsection{Inputs}
The input is a list $a_1,\dots,a_n$ of integers and a target $b$. We allow
negative numbers and a negative target. If the same value appears twice, the
two copies count as different items, and each item can be used at most once.
The empty selection is allowed and has sum $0$, so the answer for $b=0$ is
always yes.

A solver can answer in two ways. The \emph{decision} answer is just yes or no.
The \emph{search} answer also returns a \emph{witness}: the positions of the
picked items. A witness is easy to check by adding the numbers, so every solver
in this note returns one when the answer is yes.

\subsection{Subsets and their sums}
We write $[n]=\{1,\dots,n\}$ for the positions. For a set of positions
$S\subseteq[n]$ let $w(S)=\sum_{i\in S}a_i$ be its sum. There are $2^n$
subsets, so there are $2^n$ subset sums, although some of them may be equal.

For a list $A$ we write $S(A)$ for the list of all its subset sums, keeping
repeats. It is built one item at a time:
\begin{align}
S([\,])&=[0],\\
S(a::A)&=S(A)\mathbin{+\!+}[\,a+s : s\in S(A)\,].
\end{align}
Here $a::A$ is the list with first item $a$ and rest $A$, and $+\!+$ joins two
lists. Each step doubles the length, so $S(A)$ has $2^{|A|}$ entries.

\subsection{Measuring cost}
We count running time as a function of $n$, the number of items. The size of
each number matters too. Adding two $1000$-bit numbers costs more than adding
two small ones. We write $\Oh^*(f(n))$ for a bound of the form
$f(n)\cdot p$, where $p$ is a polynomial in $n$ and in the number of bits of
the input. For example, $\Oh^*(2^{n/2})$ allows $n^2\cdot2^{n/2}$ steps, and
also allows the cost of handling large numbers. We use this notation because
the open question is about the exponent; polynomial factors do not change it.

\subsection{Worst case, average case, and small numbers}
A \emph{worst-case} bound must hold for every input of size $n$. An
\emph{average-case} bound only holds for inputs drawn from some random
distribution, usually with a small chance of failure. The $2^{n/3}$ question is
about the worst case.

The size of the numbers also matters. Let $W=\sum_i|a_i|$. Every subset sum
lies between $-W$ and $W$, so a table with $2W+1$ cells is enough to record
which sums are reachable. This gives an algorithm with about $nW$ steps
(Section~\ref{sec:dp}). Such a bound is called \emph{pseudopolynomial}: it is
fast when the numbers are small and slow when they are large. The hard inputs
are therefore the ones with large numbers, roughly $n$ bits each. Inputs whose
numbers are much larger are easy for a different reason: powers of two such as
$1,2,4,8,\dots$ can be solved by reading the binary digits of the target.

\subsection{A worked example of meet-in-the-middle}
The idea behind the $2^{n/2}$ bound fits in one example. Take
$a=(3,5,8,13)$ and $b=16$. Split the items into a left half $(3,5)$ and a right
half $(8,13)$. List all subset sums of each half:
\[
\text{left: } 0,3,5,8 \qquad \text{right: } 0,8,13,21.
\]
A solution picks some items from each half, so it exists exactly when some left
sum $u$ and right sum $v$ satisfy $u+v=16$. Sort the right list. For each left
sum $u$, look up $16-u$ with binary search: $u=3$ finds $13$, and $u=8$ finds
$8$. These are the two solutions $3+13$ and $3+5+8$. Each half has only
$2^{n/2}$ sums, so the whole search costs about $2^{n/2}$ steps instead of
$2^n$. Section~\ref{sec:mitm} turns this into a proof.

\section{Enumeration and Meet-in-the-Middle}\label{sec:mitm}
We first show that the list $S(A)$ captures exactly the reachable sums, and
that a solution splits cleanly across any division of the items. All proofs
are in Appendix~\ref{app:proofs}.

\begin{lemma}[Enumeration correctness]\label{lem:enum}
$b\in S(A)$ if and only if $A$ has a 0--1 selection summing to $b$.
Also, $|S(A)|=2^{|A|}$.
\end{lemma}

\begin{lemma}[Split correctness]\label{lem:split}
For any lists $L,R$, a selection of $L+\!+R$ sums to $b$ if and only if there
are $u\in S(L)$ and $v\in S(R)$ with $u+v=b$.
\end{lemma}

Algorithm~\ref{alg:mitm} is the worked example of Section~\ref{sec:prelim} in
general form. Each sum carries a bit mask that records which items produced it,
so a match gives a witness directly.

\begin{algorithm}[t]
\caption{Sorted meet-in-the-middle}
\label{alg:mitm}
\begin{algorithmic}[1]
\Require numbers $a_1,\dots,a_n$; target $b$
\Ensure positions of a subset summing to $b$, or $\bot$ if none exists
\State $k \gets \lfloor n/2 \rfloor$
\State $L \gets \textsc{Enumerate}(a_1,\dots,a_k)$
\State $R \gets \textsc{SortBySum}(\textsc{Enumerate}(a_{k+1},\dots,a_n))$
\For{$(u,m_L)\in L$}
  \State $p \gets$ first position in $R$ with sum $\ge b-u$ \Comment{binary search}
  \If{$p\le |R|$ and $R[p].\mathrm{sum}=b-u$}
     \State \Return the indices in $m_L \mid (R[p].\mathrm{mask}\ll k)$
  \EndIf
\EndFor
\State \Return $\bot$
\end{algorithmic}
\end{algorithm}

\begin{theorem}[General baseline]\label{thm:mitm}
There is a deterministic algorithm that solves \eqref{eq:problem} on every
input, returns a witness when one exists, and uses $\Oh^*(2^{n/2})$ time and
memory.
\end{theorem}

\section{Signed Dynamic Programming}\label{sec:dp}
When the numbers are small, a table of reachable sums is faster than listing
subsets. Let $W=\sum_i|a_i|$. Every partial sum lies in $[-W,W]$, so we keep one
cell per value in that range. A cell is either empty or holds a bit mask of a
subset that reaches that value. At the start only the cell for $0$ is filled.
Item $a_i$ updates the table by
\begin{equation}\label{eq:dp}
D_i(s)=D_{i-1}(s)\ \lor\ D_{i-1}(s-a_i),
\end{equation}
where cells outside $[-W,W]$ count as empty. In words, a value is reachable
after item $i$ if it was reachable before, or if it is $a_i$ more than a value
that was reachable before. The new table is written to a separate buffer, so an
item is never used twice. Algorithm~\ref{alg:dp} gives the details.

\begin{algorithm}[t]
\caption{Dense signed-sum dynamic programming}
\label{alg:dp}
\begin{algorithmic}[1]
\Require numbers $a_1,\dots,a_n$; target $b$
\Ensure positions of a subset summing to $b$, or $\bot$ if none exists
\State $W \gets \sum_{i}|a_i|$
\If{$|b|>W$} \State \Return $\bot$ \EndIf
\State $D \gets [\bot] \times (2W+1)$; \quad $D[W]\gets 0$
\Statex \hspace{\algorithmicindent}\textit{\small cell $p$ represents sum $p-W$}
\For{$i\gets 1$ to $n$}
   \State $D' \gets$ copy of $D$
   \For{position $p$ with $D[p]\neq\bot$}
      \State $q \gets p + a_i$
      \If{$0\le q\le 2W$ and $D'[q]=\bot$}
         \State $D'[q] \gets D[p] \mid (1\ll (i-1))$
      \EndIf
   \EndFor
   \State $D \gets D'$
\EndFor
\State \Return the indices in $D[b+W]$, or $\bot$ if unreachable
\end{algorithmic}
\end{algorithm}

\begin{theorem}[Signed dynamic programming]\label{thm:dp}
Algorithm~\ref{alg:dp} solves \eqref{eq:problem} correctly and returns a valid
witness after $\Oh(n(2W+1))$ cell visits.
\end{theorem}

\section{The Easy One-Third Case}
The dynamic program gives a $2^{n/3}$ bound when the numbers are small. We
state it to make clear what it does and does not cover.
\begin{theorem}[Small numbers]\label{thm:restricted}
If $W\le 2^{\lfloor n/3\rfloor}$, then \eqref{eq:problem} can be solved in
$\Oh^*(2^{n/3})$ time.
\end{theorem}

This is the standard pseudopolynomial argument and not a new algorithm. It
does not reach the hard inputs. For $a_i=2^{i-1}$, for example, $W=2^n-1$, far
above the assumption. Those powers of two also give $2^n$ different subset
sums, so removing duplicate sums cannot help in general. Splitting the items
into three blocks of $n/3$ does not help either: each block is cheap to list,
but combining two block lists naively already produces $2^{2n/3}$ pairs. These
remarks rule out particular approaches. They are not lower bounds.

\section{Schroeppel--Shamir}\label{sec:ss}
Meet-in-the-middle stores $2^{n/2}$ sums. Schroeppel and Shamir get the same
time with far less memory. They split the items into four blocks and generate
the sums of block pairs one at a time instead of storing them. Each of the four
block lists has about $2^{n/4}$ entries and is sorted. A heap produces the sums
of blocks $0$ and $1$ in increasing order, and a second heap produces the sums
of blocks $2$ and $3$ in decreasing order. Two pointers then walk the two
streams toward each other, as in the classic search for two numbers with a
given sum in sorted arrays (Algorithm~\ref{alg:ss}). Each stream moves at most
$2^{n/2}$ times.

\begin{algorithm}[t]
\caption{Schroeppel--Shamir with streamed pair sums}
\label{alg:ss}
\begin{algorithmic}[1]
\Require numbers $a_1,\dots,a_n$; target $b$
\Ensure positions of a subset summing to $b$, or $\bot$ if none exists
\State partition the entries into four contiguous blocks $G_0,\dots,G_3$ of sizes $\lfloor n/4\rfloor$ or $\lceil n/4\rceil$
\For{$t\gets 0$ to $3$}
   \State $S_t \gets \textsc{SortBySum}(\textsc{Enumerate}(G_t))$ \Comment{masks use global positions}
\EndFor
\State $U \gets \textsc{MergeAscending}(S_0,S_1)$ \Comment{streams $u_0+u_1$ increasing}
\State $V \gets \textsc{MergeDescending}(S_2,S_3)$ \Comment{streams $v_0+v_1$ decreasing}
\State $u\gets \textsf{next}(U)$; \quad $v\gets \textsf{next}(V)$
\While{$u\neq\bot$ and $v\neq\bot$}
   \If{$u.\mathrm{sum}+v.\mathrm{sum}=b$}
      \State \Return the indices in $u.\mathrm{mask}\mid v.\mathrm{mask}$
   \ElsIf{$u.\mathrm{sum}+v.\mathrm{sum}<b$}
      \State $u\gets \textsf{next}(U)$
   \Else
      \State $v\gets \textsf{next}(V)$
   \EndIf
\EndWhile
\State \Return $\bot$
\end{algorithmic}
\end{algorithm}

\begin{theorem}[Schroeppel--Shamir]\label{thm:ss}
Algorithm~\ref{alg:ss} correctly decides \eqref{eq:problem} and returns a valid
witness in $\Oh^*(2^{n/2})$ time and $\Oh^*(2^{n/4})$ space.
\end{theorem}

\section{Measurements}\label{sec:measure}
We run the three methods on inputs that have no solution, because a solver may
stop early when it finds a match and that would hide its real cost. To build
such inputs, every number is even and the target is odd, so no subset can hit
it. We use two families: \emph{bounded} numbers in $[-100,100]$, where the
dynamic program's table fits in memory, and \emph{wide} numbers in
$[-2^{40},2^{40}]$, where it does not. Each time is the best of three runs, and
memory is the peak allocated during the run. All runs are single-threaded, on
CPython~3.12 under Linux with an Intel Core i9-8950HK CPU at 2.9\,GHz.
Figure~\ref{fig:states} also reports a machine-independent \emph{work count}:
the number of half-list sums built for meet-in-the-middle, the number of heap
steps for Schroeppel--Shamir, and the number of table cells visited for the
dynamic program.

Meet-in-the-middle and Schroeppel--Shamir take about the same time, and both
grow like $2^{n/2}$. Schroeppel--Shamir is a little slower because of its heap
operations. Their memory use is very different: meet-in-the-middle grows like
$2^{n/2}$, while Schroeppel--Shamir grows like $2^{n/4}$ and uses about 200
times less memory at $n=32$ (Table~\ref{tab:memory}). Nederlof and
W\k{e}grzycki~\cite{nw} show that the memory can be pushed slightly below
$2^{n/4}$ with randomization, at the same $2^{n/2}$ time. On bounded numbers the
dynamic program's time grows roughly linearly in $n$, and from $n=28$ on it is
the fastest method. On wide numbers it cannot run at all, because the table
would need on the order of $n\cdot2^{40}$ cells. Its peak memory is not
monotone in $n$ because the table width $2W+1$ depends on the random input.
These are finite measurements. They match the proven bounds but do not prove
anything about larger $n$.

\section{What a $2^{n/3}$ Result Would Need}\label{sec:goal}
A real improvement needs an algorithm that provably finishes in
$\Oh^*(2^{n/3})$ steps on \emph{every} input, with the cost of arithmetic on
large numbers counted. If it uses randomness, the proof must also bound its
chance of failure. Good benchmark numbers cannot replace that proof, and
neither can an average-case analysis, because both leave out the hardest inputs.
The closest recent progress is the worst-case result of Randolph and
W\k{e}grzycki~\cite{rw} for related problems, which uses the representation
technique; whether it can be adapted to plain subset sum is open. The algorithms
in this note are the baseline that any such result has to beat.

\appendices
\section{Proofs}\label{app:proofs}
This appendix proves the results stated in the main text. Throughout, a
\emph{selection} of a list is a choice of some of its positions, each used at
most once, and its sum is the sum of the chosen entries.

\subsection{Proof of Lemma~\ref{lem:enum}}
We use induction on the length of $A$.

\emph{Base case.} If $A$ is empty, its only selection is the empty one, with
sum $0$, and $S([\,])=[0]$. So $b\in S([\,])$ exactly when $b=0$, and
$|S([\,])|=1=2^0$.

\emph{Step.} Let $A=a::A'$ and assume the claim for $A'$. Every selection of
$A$ either leaves out the first entry or uses it.
\begin{itemize}
\item If it leaves it out, it is a selection of $A'$. By the induction
hypothesis its sum $b$ is in $S(A')$, which is the first part of $S(A)$.
\item If it uses it, the rest is a selection of $A'$ with some sum $s$, and
$b=a+s$. Since $s\in S(A')$, the value $a+s$ is in the second part of $S(A)$.
\end{itemize}
Conversely, a value in the first part of $S(A)$ is a sum of some selection of
$A'$, which is also a selection of $A$. A value $a+s$ in the second part comes
from a selection of $A'$ with sum $s$; adding the first entry gives a selection
of $A$ with sum $a+s$. The first entry was not used before, so no position is
used twice. This proves the equivalence.

For the length, $|S(A)|=|S(A')|+|S(A')|=2\cdot2^{|A'|}=2^{|A|}$. The list keeps
repeated values, so equal sums do not change the count. \hfill$\square$

\subsection{Proof of Lemma~\ref{lem:split}}
The positions of $L+\!+R$ are the positions of $L$ followed by the positions
of $R$, and the two groups do not overlap.

Suppose a selection of $L+\!+R$ has sum $b$. Let $u$ be the sum of its chosen
positions inside $L$ and $v$ the sum of its chosen positions inside $R$. Then
$u+v=b$. The positions inside $L$ form a selection of $L$, so
$u\in S(L)$ by Lemma~\ref{lem:enum}; in the same way $v\in S(R)$.

Now suppose $u\in S(L)$ and $v\in S(R)$ with $u+v=b$. By
Lemma~\ref{lem:enum} there is a selection of $L$ with sum $u$ and a selection
of $R$ with sum $v$. Taking both together gives a selection of $L+\!+R$ with sum
$u+v=b$. No position is used twice because the two groups are disjoint. The
argument does not use the signs or the distinctness of the entries.
\hfill$\square$

\subsection{Proof of Theorem~\ref{thm:mitm}}
We show that Algorithm~\ref{alg:mitm} has the stated properties.

\emph{Correctness.} Let $k=\lfloor n/2\rfloor$, $L=(a_1,\dots,a_k)$ and
$R=(a_{k+1},\dots,a_n)$. By Lemma~\ref{lem:split}, a solution exists if and
only if some $u\in S(L)$ and $v\in S(R)$ satisfy $v=b-u$. The algorithm tries
every $u\in S(L)$ and uses binary search on the sorted list $S(R)$ to decide
whether $b-u$ is present. Binary search on a sorted list finds a value exactly
when it is present, so the algorithm answers yes exactly when a solution
exists.

\emph{Witness.} Each entry of the two lists stores, next to its sum, a bit mask
of the positions that produced it. When $u$ and $v=b-u$ match, the left mask
describes a selection of $L$ with sum $u$ and the right mask, shifted by $k$,
describes a selection of $R$ with sum $v$. Their union is a selection of the
whole input with sum $b$.

\emph{Cost.} Let $P=2^k$ and $Q=2^{n-k}$ be the list lengths
(Lemma~\ref{lem:enum}). Building the lists takes $\Oh(P+Q)$ additions and mask
updates. Sorting the right list takes $\Oh(Q\log Q)$ comparisons, and the $P$
binary searches take $\Oh(P\log(Q+1))$ comparisons. Since $k$ and $n-k$ are at
most $\lceil n/2\rceil$, both $P$ and $Q$ are at most $2^{\lceil n/2\rceil}$ and
$\log Q\le n$, so the total is $\Oh(n\,2^{\lceil n/2\rceil})$ operations on
$\Oh(2^{\lceil n/2\rceil})$ stored records. Each sum has absolute value at most
$\sum_i|a_i|$, so its bit length is at most the input length plus $\log_2 n$,
and each mask has $n$ bits. Every operation therefore costs a
polynomial factor, which gives $\Oh^*(2^{n/2})$ time and memory. The algorithm
makes no random choices. \hfill$\square$

\subsection{Proof of Theorem~\ref{thm:dp}}
Write $D_i$ for the table after the first $i$ items. We prove the following
invariant by induction on $i$:

\begin{quote}
$(\star)$ For every $s\in[-W,W]$, the cell for $s$ in $D_i$ is filled if and
only if some selection of $a_1,\dots,a_i$ has sum $s$, and in that case the
stored mask is such a selection.
\end{quote}

\emph{Base case.} With no items, the only selection is the empty one, with sum
$0$. The algorithm fills only the cell for $0$, with the empty mask.

\emph{Step.} Assume $(\star)$ for $D_{i-1}$. A selection of $a_1,\dots,a_i$
either skips $a_i$ or uses it. If it skips $a_i$, it is a selection of the
first $i-1$ items, so its sum $s$ is filled in $D_{i-1}$ and the copy keeps it
in $D_i$. If it uses $a_i$, the rest has sum $s-a_i$, which is filled in
$D_{i-1}$; the update writes the cell for $s$, with the old mask plus bit $i$.
In both cases the cell for $s$ is filled in $D_i$. Conversely, every cell filled
in $D_i$ was either copied from $D_{i-1}$ (a selection that skips $a_i$) or
written by the update from a filled cell $s-a_i$ (a selection that uses $a_i$,
added once because the update reads only the old table). In both cases the
stored mask is a selection with the right sum. This proves $(\star)$ for $D_i$.

Every partial sum $s$ of a selection satisfies $|s|\le\sum_i|a_i|=W$, so no
reachable value falls outside the table. By $(\star)$ for $D_n$, the answer is
yes exactly when the cell for $b$ is filled, and its mask is a witness. If
$|b|>W$ no selection can reach $b$, and the algorithm correctly answers no.

\emph{Cost.} Each of the $n$ rounds copies the table and scans its $2W+1$
cells once, so the total is $\Oh(n(2W+1))$ cell visits. \hfill$\square$

\subsection{Proof of Theorem~\ref{thm:restricted}}
Run Algorithm~\ref{alg:dp}. It is correct by Theorem~\ref{thm:dp} and makes
$\Oh(n(2W+1))$ cell visits. If $W\le2^{\lfloor n/3\rfloor}$, then
\[
n(2W+1)\le n\bigl(2\cdot2^{\lfloor n/3\rfloor}+1\bigr)\le 3n\cdot2^{n/3}.
\]
Each cell visit handles a mask of $n$ bits and a sum of $\Oh(n)$ bits, so it
costs a polynomial number of bit operations. The total is therefore
$\Oh^*(2^{n/3})$. \hfill$\square$

\subsection{Proof of Theorem~\ref{thm:ss}}
\emph{Reduction to two streams.} Apply Lemma~\ref{lem:split} three times: to
split the input into $G_0+\!+G_1$ and $G_2+\!+G_3$, and then to split each of
these. A solution exists if and only if there are $u_0\in S(G_0)$,
$u_1\in S(G_1)$, $v_0\in S(G_2)$ and $v_1\in S(G_3)$ with
$(u_0+u_1)+(v_0+v_1)=b$. Let $U$ be the list of all values $u=u_0+u_1$ and $V$
the list of all values $v=v_0+v_1$.

\emph{The streams are sorted.} The heap for $U$ holds one candidate for each
$u_0\in S(G_0)$: the next unused value $u_0+u_1$, taken in increasing order of
$u_1$ in the sorted list $S(G_1)$. Each such row is increasing, so the smallest
heap entry is always the smallest value not yet output. Hence $U$ is produced in
increasing order, and it contains every pair exactly once. The same argument
with the order reversed shows that $V$ is produced in decreasing order.

\emph{The two-pointer walk is complete.} Suppose $u^\ast\in U$ and
$v^\ast\in V$ satisfy $u^\ast+v^\ast=b$, and suppose the walk stops without a
match. Then at some step it moves one pointer past its target value; consider
the first such step.
\begin{itemize}
\item If the $U$ pointer leaves $u^\ast$, the walk saw $u^\ast+v<b$ for the
current $v$. Then $v<v^\ast$, so the $V$ pointer had already moved past
$v^\ast$, which contradicts the choice of the first step.
\item If the $V$ pointer leaves $v^\ast$, the walk saw $u+v^\ast>b$ for the
current $u$. Then $u>u^\ast$, so the $U$ pointer had already moved past
$u^\ast$, again a contradiction.
\end{itemize}
So the walk stops with some pair whose sum is $b$. If no solution exists, no
pair sums to $b$, and the walk ends when a stream runs out. The masks stored
with $u$ and $v$ give a witness by the same argument as in
Theorem~\ref{thm:mitm}.

\emph{Cost.} The four sorted lists have $\Oh(2^{n/4})$ entries each, and each
heap holds one entry per row, so memory is $\Oh(2^{n/4})$ records. Each stream
has at most $2^{\lceil n/2\rceil}$ values, so the walk takes at most
$2\cdot2^{\lceil n/2\rceil}$ steps. Each step is one heap operation costing
$\Oh(\log 2^{n/4})=\Oh(n)$ comparisons. With polynomial bit costs per
operation, the time is $\Oh^*(2^{n/2})$ and the memory is $\Oh^*(2^{n/4})$.
\hfill$\square$
