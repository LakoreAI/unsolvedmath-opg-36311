## Meet-in-the-Middle (MITM) for Subset Sum

- **name** (Basic): Meet-in-the-Middle (MITM) for Subset Sum
- **category** (Basic): algorithmic-family
- **description** (Basic): The meet-in-the-middle family for exact Subset Sum: Horowitz and Sahni (JACM 1974) split the n inputs into two halves, enumerate and sort all 2^(n/2) subset sums of each half, and find a complementary pair by a linear merge/two-pointer scan, giving O(2^(n/2)) time and O(2^(n/2)) space and yielding an explicit witness. Schroeppel and Shamir (SIAM J. Comput. 1981, earlier FOCS 1979) keep the same O(2^(n/2)) time while reducing space to O(2^(n/4)) by splitting into four blocks of n/4 and generating the needed pair sums lazily in sorted order with two priority queues (a 'sorted-matrix' / heap trick), instead of materializing all 2^(n/2) sums. These are the classical baselines that every claimed improvement toward O*(2^(n/3)) must beat.
- **worst_case_time** (Complexity): O*(2^(n/2)) = O(2^(n/2) * poly(n)); Horowitz-Sahni O(2^(n/2)) on standard RAM models, Schroeppel-Shamir T = O(2^(n/2)) (their paper writes O(2^(n/2)*(n/4)) up to polynomial factors). No improvement in the time exponent is known: the best worst-case exponent remains 0.5; the only known gain is a polynomial factor 2^(n/2)/n^gamma with gamma >= 0.5023 (Chen-Jin-Randolph-Servedio, RANDOM 2023).
- **space_complexity** (Complexity): Horowitz-Sahni: O*(2^(n/2)) (one sorted list of 2^(n/2) subset sums per half). Schroeppel-Shamir: O*(2^(n/4)) using heap-generated pair sums. The generalized Schroeppel-Shamir tradeoff is T = O(2^n / S^2) time for any space budget S <= O*(2^(n/4)). Nederlof-Wegrzycki (STOC 2021) reduced the space exponent to O*(2^(0.249999n)) while keeping O*(2^(n/2)) time.
- **model** (Complexity): Unit-cost RAM and standard word RAM / circuit RAM (word size O(log(sum of inputs))); Horowitz-Sahni and Schroeppel-Shamir are usually stated on the RAM/unit-cost model, and the O(2^(n/2)) bound can be realized in standard word RAM or circuit RAM. Not a quantum result.
- **randomized_or_deterministic** (Complexity): Deterministic (both Horowitz-Sahni and Schroeppel-Shamir). The recent polynomial-factor log-shaving improvement of Chen-Jin-Randolph-Servedio (RANDOM 2023) is randomized/Monte Carlo.
- **numerical_exponent_and_record_year** (Complexity): Time exponent 0.5 (Horowitz-Sahni, 1974; Schroeppel-Shamir retain 0.5 in 1981). Space exponent 0.25 (Schroeppel-Shamir, 1981), improved to 0.249999 (Nederlof-Wegrzycki, STOC 2021). Worst-case time exponent has stood at 0.5 for ~50 years; only polynomial-factor gains exist (Chen-Jin-Randolph-Servedio, 2023).
- **problem_variant** (Scope): Vanilla exact/decision Subset Sum (given n integers and target t, is there a subset summing to t?). Schroeppel-Shamir state their method as general-purpose for several NP-complete problems: knapsack, exact satisfiability, and set covering, in addition to subset sum. It also applies to Partition and the search/witness version.
- **applies_to** (Scope): Exact worst-case Subset Sum decision and search (witness recovery); Horowitz-Sahni also treat the 0-1 knapsack optimization. Schroeppel-Shamir's general-purpose algorithm covers knapsack, exact satisfiability, and set covering. No density restriction: MITM works for all input densities.
- **coefficient_set** (Scope): C = {0,1} for standard Subset Sum (each item chosen at most once). In the balanced/balancing formulation the coefficient set is {0,1} (for Subset Sum) or {-1,0,1} (for Equal Subset Sum / Partition); |C| = 2 for Subset Sum.
- **density_regime** (Scope): Density-agnostic. The classical complexity O*(2^(n/2)) holds for every density d = n / log2(max |a_i|), including low density, d ~ 1, and dense instances; MITM does not exploit density. Historically it was the fallback for density ~1 knapsacks where lattice low-density attacks fail.
- **solution_regime** (Scope): General decision problem with no promise of a solution (and search when one exists). No pigeonhole/numerous-solution promise is assumed.
- **cardinality_constraint** (Scope): No fixed-cardinality constraint is part of the base problem. However, cardinality matters for the running time: balanced solutions (|subset| ~ n/2 +/- o(n)) are the hardest case for MITM, while unbalanced solutions can be found faster than 2^(n/2) by folklore modifications that exploit the small solution size.
- **key_technique** (Method): Split-and-list enumeration with sorting and matching (Horowitz-Sahni): enumerate all subset sums of each half, sort one list, and binary-search / two-pointer merge for t - s. Schroeppel-Shamir use a four-way split plus a lazy sorted-matrix generator: pair sums of two n/4-blocks are produced in sorted order on demand via two min-heaps, so only O(2^(n/4)) entries are ever stored; matching uses the same complementary-pair scan.
- **core_idea** (Method): Every subset is the union of two half-subsets, so a target t is hit iff some sum of the first half equals t minus some sum of the second half. Enumerating 2^(n/2) sums per half and matching two sorted lists costs O(2^(n/2)) time; this is the 'birthday' square-root phenomenon (2^(n/2) = sqrt(2^n)). Schroeppel-Shamir observe that the 2^(n/2) pairs of the four n/4-blocks can be streamed in sorted order with small memory, decoupling time from space and showing the space need not be the binding constraint.
- **reduction_pipeline** (Method): No reduction: direct enumeration and matching. Conceptually it is 2-list k-SUM (k = 2) over two sets of size 2^(n/2), or equivalently a sumset A + B containing t. The (unrealized) route toward 2^(n/3) is a three-block split reducing Subset Sum to a structured 3-SUM/4-SUM over 2^(n/3)-sized sets, which is blocked by 3SUM/4SUM-type quadratic barriers.
- **constructive_vs_existential** (Method): Fully constructive: the algorithms return an explicit witness subset when one exists (the matched pair decodes to the indicator vector).
- **search_vs_decision_witness** (Method): Both. Decides feasibility, and returns an explicit witness (the subset). Constructivity is direct and unconditional.
- **obstacle_to_2n3** (Frontier): MITM is not known to be optimal, but its 2^(n/2) time comes from explicitly touching ~2^(n/2) half-sums; a 2^(n/3) algorithm would need to compare three blocks of size 2^(n/3), i.e., solve a structured 3-SUM/4-SUM over adversarially constructed sets, for which only quadratic-time algorithms are known and for which 3SUM/4SUM conjectures predict no substantially subquadratic algorithm. Absent such structure exploitation, MITM hits an apparent barrier: all known worst-case improvements over it are only polynomial factors, and the informal 'Meet-in-the-Middle / Subset Sum hypothesis' (no O*(2^((1/2-eps)n)) worst-case algorithm) remains open and unproven.
- **potential_to_break_mitm** (Frontier): Medium overall for the broader line, low for pure MITM itself. Plain MITM has no internal slack and has resisted an exponent improvement for ~50 years; genuinely beating 2^((1/2-eps)n) in the worst case is expected to require the representation/mixing machinery or fundamentally new structure, not a tuning of MITM.
- **barrier_evidence** (Frontier): No unconditional 2^(Omega(n)) lower bound for Subset Sum is known. ETH only implies no 2^(o(n)) algorithm; it does not rule out 2^((1/2-eps)n). Under SETH, Abboud, Bringmann, Hermelin, Shabtay and coauthors prove Subset Sum cannot be solved in O(t^(1-eps) * 2^(delta n)) time (a pseudo-polynomial conditional lower bound), and the k-SUM conjecture predicts meet-in-the-middle optimality for k-SUM (O(n^(ceil(k/2))) is optimal). The 3SUM/4SUM conjectures constrain the structured-matching step a 2^(n/3) algorithm would need. The 'Meet-in-the-Middle hypothesis' / 'Subset Sum hypothesis' for the 2^(n/2) exponent is itself an unproved conjecture, not a theorem.
- **open_questions** (Frontier): Is there a worst-case O*(2^((1/2 - eps)n))-time Subset Sum algorithm? Can Subset Sum be reduced to structured 3-SUM/4-SUM over 2^(n/3)-sized sets and solved subquadratically? Can the O(2^(n/2)/n^gamma) polynomial-factor shaving be turned into a constant-factor exponent improvement? Under what hypotheses is the 2^(n/2) exponent optimal? Can either-or / structure-vs-randomness approaches be extended to general subset sum (not only the either-or variant)?
- **conditional_hypothesis** (Assumptions): ETH (implies no 2^(o(n)) algorithm), SETH (pseudo-polynomial lower bounds via Abboud-Bringmann et al.), the k-SUM conjecture (hardness of O(n^(ceil(k/2)-eps)) for k-SUM), and the 3SUM/4SUM conjectures for the matching step. The specific claim that 2^(n/2) is worst-case optimal (the informal Meet-in-the-Middle / Subset Sum hypothesis) is conjectural and not established by any of the above.
- **worst_case_vs_average_case_guarantee** (Assumptions): Worst-case guarantee. Horowitz-Sahni and Schroeppel-Shamir are deterministic and their O*(2^(n/2)) time holds on every instance.
- **cryptographic_regime** (Assumptions): Highly relevant to knapsack cryptanalysis. Schroeppel-Shamir's abstract notes the algorithm can break knapsack-based cryptosystems (e.g., Merkle-Hellman-type) with up to n = 100 generators; MITM is the standard attack on density ~1 knapsacks where lattice low-density (LLL/BKZ) attacks do not apply. The exponent governs feasible key sizes in knapsack-based schemes.
- **pseudopolynomial_interaction** (Assumptions): Complementary, not combined in the base algorithm: MITM ignores the numeric magnitude of items, whereas pseudo-polynomial DP costs poly(n) * max|a_i|. HYBRID strategies choose DP/pseudo-polynomial methods for small items / bounded sums and fall back to MITM otherwise, and the worst-case lower bounds treat them as competing algorithms.

## Representation Technique / Dissection (Howgrave-Graham-Joux, Becker-Coron-Joux)

- **name** (Basic): Representation Technique / Dissection (Howgrave-Graham-Joux, Becker-Coron-Joux)
- **category** (Basic): average-case-technique
- **description** (Basic): The representation technique for hard (density ~1) knapsacks, introduced by Howgrave-Graham and Joux (EUROCRYPT 2010) and refined by Becker-Coron-Joux (EUROCRYPT 2011) and Bonnetain-Bricout-Schrottenloher-Shen (ASIACRYPT 2020). Instead of a two-way MITM split, the solution vector is represented in many different ways (e.g., as a signed/4-valued combination of partial vectors, allowing overlaps and the value 2), which 'bloats' the search space but multiplies the number of encodings of each true solution even more. By counting representations and filtering pseudo-solutions with modular/parity constraints, the enumeration per side is reduced. For random knapsacks of density close to 1 this gives heuristic running times O*(2^(0.337n)) (HGJ, 2010; long-version analysis 2^(0.3113n)), O*(2^(0.291n)) (BCJ, 2011), and O*(2^(0.283n)) (Bonnetain et al., 2020). The method is average-case/heuristic: the representation-counting argument needs random-like instances and is not a worst-case algorithm.
- **worst_case_time** (Complexity): No worst-case bound: the representation method is heuristic/average-case. Its running times are stated for random hard knapsacks of density ~1: O*(2^(0.337n)) (HGJ 2010; the ePrint long version 2010/189 states 2^(0.3113n) for almost all density-1 knapsacks), improved to O*(2^(0.291n)) (BCJ 2011) and O*(2^(0.283n)) (Bonnetain et al. 2020). For arbitrary worst-case instances no O*(2^((1/2-eps)n)) guarantee follows.
- **space_complexity** (Complexity): HGJ: O*(2^(0.256n)) memory (per BCJ's citation). BCJ retain low memory and additionally give a constant-memory variant based on cycle finding running in O(2^(0.72n)) time, plus an explicit time-memory tradeoff. Bonnetain et al. also discuss memory reductions. Schroeppel-Shamir-style O*(2^(n/4)) space is the prior baseline for the density-1 setting.
- **model** (Complexity): Classical RAM / word RAM (heuristic, with modular arithmetic). The same representation framework has been adapted to quantum walk algorithms (Bernstein-Jeffery-Lange-Meurer), but the HGJ/BCJ algorithms themselves are classical.
- **randomized_or_deterministic** (Complexity): Randomized, and heuristic/Monte Carlo: the complexity estimates assume random instances of density ~1 and the analysis is not fully rigorous for arbitrary inputs. There is no proven worst-case success guarantee; the algorithms are expected to succeed with high probability on random instances.
- **time_space_tradeoff_curve** (Complexity): BCJ present a time-memory tradeoff and a constant-memory variant (cycle finding) at O(2^(0.72n)) time; the main point is O~(2^(0.291n)) time with O~(2^(0.256n)) memory. Dissection (a closely related family, Dinur et al.) provides explicit worst-case time-space tradeoffs, unlike the basic representation method.
- **numerical_exponent_and_record_year** (Complexity): 0.337n (Howgrave-Graham-Joux, 2010, EUROCRYPT; the ePrint long version gives 0.3113n); 0.291n (Becker-Coron-Joux, 2011, EUROCRYPT); 0.283n (Bonnetain-Bricout-Schrottenloher-Shen, 2020, ASIACRYPT, using representations with values in {-1,0,1,2}).
- **problem_variant** (Scope): Hard knapsack / random Subset Sum with density close to 1 (the cryptanalytic regime). Not the general worst-case vanilla Subset Sum, and not a promised-solution pigeonhole variant, though solutions exist with constant probability for density-1 instances.
- **applies_to** (Scope): Random (or 'almost all') density-~1 knapsacks, i.e., cryptographic hard-knapsack instances; also generalized subset-sum/balancing settings after adaptation. Requires overlap-friendly representations, so it does not directly cover worst-case {0,1} Subset Sum.
- **coefficient_set** (Scope): The original Subset Sum has C = {0,1}. The representation scheme represents each solution with coefficient vectors over larger signed sets: HGJ/BCJ use overlaps with values in {-1,0,1} (and related); Bonnetain et al. use {-1,0,1,2}. The effective 'coefficient set' is a design parameter of the representation, not the input domain.
- **density_regime** (Scope): Density d = n / log2(max |a_i|) close to 1 (the hard-knapsack regime), where lattice-based low-density attacks fail. The method is designed for this density; low-density instances are easy by lattice reduction.
- **solution_regime** (Scope): Assumes solutions (or many solutions) with overwhelming probability, as holds for random density-1 instances; it is a hard-instance/random-instance algorithm rather than a general decision procedure.
- **cardinality_constraint** (Scope): Yes, in effect: balanced (fixed Hamming-layer) solutions are central. Representations are built around a chosen weight (e.g., splitting a weight-n/2 solution into weight-n/4 halves), and the representation count is a binomial coefficient such as C(n/2, n/4) ~ 2^(n/2)/sqrt(n). Cardinality/weight constraints are the main lever.
- **key_technique** (Method): Representation bloat plus filtering: (1) choose a representation format (overlaps, signed coefficients, and value 2) so a single solution has many encodings; (2) count the expected number of representations to choose parameters; (3) impose modular/parity filters that eliminate 'pseudo-solutions' (candidate pairs that satisfy the sum condition but combine to an invalid coefficient vector); (4) search the reduced, filtered lists. Related dissection recursively splits the problem into constrained subproblems; Nederlof-Wegrzycki and Chen-Jin-Randolph-Servedio adapted these ideas to worst-case and to Orthogonal Vectors.
- **core_idea** (Method): MITM matches two 2^(n/2) lists. If instead one deliberately enlarges the candidate space (e.g., allowing overlaps or signed coefficients), a genuine solution acquires exponentially many representations, more than the extra candidates added. Filtering then leaves only a small fraction to compare, so the per-side enumeration can be below 2^(n/2). BCJ further use pseudo-solutions to prune, and 4-valued representations (Bonnetain et al.) lower the exponent to 0.283. The intuition is that structure (many representations of one solution) beats the brute-force 2^(n/2) wall on random instances.
- **reduction_pipeline** (Method): Reduce Subset Sum to finding many collision/representation pairs, typically after a modular filter (mod 2^k) or low-weight representation constraint; equivalent to a generalized-birthday/collision problem and related to Wagner's algorithm. Dissection recursively generates lists; the worst-case adaptations reduce to Orthogonal Vectors (Nederlof-Wegrzycki) and to pseudo-solution recovery (Randolph-Wegrzycki).
- **constructive_vs_existential** (Method): Constructive (returns a witness vector when the heuristic succeeds), but the guarantee is only heuristic/average-case; constructivity is not proved for arbitrary worst-case inputs.
- **search_vs_decision_witness** (Method): Search/witness: returns the knapsack solution vector. Correctness/constructivity holds with high probability on random density-1 instances; no worst-case witness guarantee.
- **obstacle_to_2n3** (Frontier): The technique relies essentially on average-case structure: the representation-counting step needs each solution to have enough encodings, which random density-1 instances provide but structured/worst-case instances (notably {0,1} Subset Sum, Partition, C={-1,1}) may not. So it yields no worst-case O*(2^((1/2-eps)n)) bound, let alone 2^(n/3). Moreover its exponents (0.337 -> 0.291 -> 0.283) are still far above 1/3 and the analyses are heuristic. Reaching 2^(n/3) would need a rigorous worst-case representation theory (mixing, flexible representations, pseudo-solution recovery) and a way to guarantee representations for adversarial inputs; Randolph-Wegrzycki (STOC 2026) achieve worst-case mixing for many coefficient sets but explicitly cannot break the MITM barrier for C={-2,-1,1,2} and C={-1,1} (Partition).
- **potential_to_break_mitm** (Frontier): Low for worst-case Subset Sum (the method is inherently average-case); high for cryptanalytic average-case knapsacks (where it is state of the art). The worst-case transfer is a separate, harder line (mixing/flexible representations) and remains blocked for {0,1} Subset Sum and Partition.
- **barrier_evidence** (Frontier): The representation method's analysis is heuristic and explicitly average-case; no worst-case improvement follows. Worst-case representation arguments require the solution to have many encodings, which adversarially structured instances can deny. The k-SUM/3SUM/4SUM conjectures and SETH-based pseudo-polynomial lower bounds bound what structure exploitation can do; ETH only rules out 2^(o(n)). Randolph-Wegrzycki show the representation technique can be made worst-case for many constant coefficient sets but not for C={-1,1} (Partition) or C={-2,-1,1,2}; Equal Subset Sum needed separate progress. This is direct evidence that the average-case technique does not automatically carry over.

## worst_case_representation_mixing

- **name** (Basic): worst_case_representation_mixing
- **category** (Basic): worst-case-technique
- **description** (Basic): The Randolph-Wegrzycki line brings the Howgrave-Graham-Joux representation technique from average-case to worst-case instances of Subset Balancing, the family of problems asking for a nonzero coefficient vector c in C^n with c.x = 0 (Subset Sum is C={-1,1}, Equal Subset Sum is C={-1,0,1}). The core new ingredients are (1) mixing dichotomies, which show that if candidate solution pairs do not 'mix' (spread out) across residue classes modulo a random prime, then the instance must have either an unbalanced solution or exponentially many solutions - cases solvable by other methods; (2) coefficient shifting, factoring C as a sumset C1+C2 so that coefficient sets without 0 (C=[+-d]) admit flexible representations; and (3) a near-linear compatibility test that recovers a valid solution pair from a list that may contain invalid 'pseudosolution pairs'. For C=[-d:d], d>1 and C=[+-d], d>2 this yields O(|C|^{(0.5-eps)n}) worst-case time, the first worst-case break of the |C|^{n/2} Meet-in-the-Middle barrier on these coefficient sets. Equal Subset Sum (C=[-1:1]) is improved to O(1.7067^n), but the two natural cases C=[+-1] (Partition/Subset Sum) and C=[+-2] remain unresolved.
- **worst_case_time** (Complexity): O(|C|^{(0.5 - eps)n}) with a constant eps = eps(C) > 0 depending only on C, for C = [-d:d] (d > 1) and C = [±d] (d > 2); O(1.7067^n) for Equal Subset Sum C = [-1:1]. Baseline Meet-in-the-Middle is O(|C|^{n/2}). The two exceptions C = [±1] (Partition/Subset Sum) and C = [±2] are not improved.
- **model** (Complexity): Word RAM / circuit RAM with unit-cost operations on input integers (the paper assumes standard integer operations take constant time, reconcilable with a realistic RAM model via O* notation; this follows the Chen-Jin-Randolph-Servedio model).
- **randomized_or_deterministic** (Complexity): Monte Carlo with one-sided error (never returns false positives); success probability is inverse polynomial and can be amplified to 1 - 2^{-Omega(n)} by repetition.
- **time_space_tradeoff_curve** (Complexity): Single point per coefficient set; the paper focuses on shaving the exponential time exponent and explicitly does not optimize space or constant factors.
- **numerical_exponent_and_record_year** (Complexity): Equal Subset Sum (C=[-1:1]): O(1.7067^n), improving the previous O(1.7088^n) (Mucha-Nederlof-Pawlewicz-Wegrzycki, ESA 2019); record year 2025 (arXiv Nov 2025). For general C=[-d:d] and C=[±d] only the symbolic exponent |C|^{0.5-eps} with unspecified constant eps > 0 is given; record year 2025.
- **problem_variant** (Scope): Subset Balancing (c.x = 0 for c in C^n), which generalizes Subset Sum/Partition (C = {-1,1}), Equal Subset Sum (C = {-1,0,1}) and average-case Subset Balancing.
- **applies_to** (Scope): Worst-case exact Subset Balancing for coefficient sets C = [-d:d] = {-d,...,d} with d > 1 (includes 0) and C = [±d] = {-d,...,-1,1,...,d} with d > 2 (excludes 0). Does not apply to C = [±1] (Partition/Subset Sum) or C = [±2].
- **coefficient_set** (Scope): Constant-size coefficient set C subset of Z. Two families: [-d:d] with |C| = 2d+1 and [±d] with |C| = 2d. Results hold for d > 1 ([-d:d]) and d > 2 ([±d]) with a constant eps depending only on C. The unresolved cases are [±1] and [±2].
- **density_regime** (Scope): Worst-case / dense arbitrary integer inputs; no density or distributional assumption. (Contrast: the earlier Chen-Jin-Randolph-Servedio result assumed uniformly random inputs from an exponential range.)
- **solution_regime** (Scope): General decision/search regime, not a promised numerous-solution (pigeonhole) regime. The mixing dichotomy handles instances that have a single balanced solution by proving that poor mixing forces either an unbalanced solution or exponentially many solutions.
- **cardinality_constraint** (Scope): No explicit fixed cardinality constraint, but the algorithm guesses the 'solution profile' (the frequency of each coefficient in C) and separately handles unbalanced profiles vs approximately balanced profiles.
- **key_technique** (Method): Worst-case adaptation of the Howgrave-Graham-Joux representation technique, combining: (1) mixing dichotomies (poor mixing implies an unbalanced solution or exponentially many solutions); (2) coefficient shifting, expressing C as a sumset C1 + C2 to create flexible representations for coefficient sets without 0; (3) representations admitting pseudosolutions plus compatibility certificates (a sparse-OV-style near-linear compatibility test, generalizing Belova-Chukhin-Kulikov-Mihajlin) to rule out invalid pairs; and (4) a folklore fast algorithm for epsilon-unbalanced instances.
- **core_idea** (Method): The representation technique filters a large ambient set of candidate vectors down to a smaller set Z by keeping only vectors whose dot product with the input equals a fixed random residue r modulo a random prime p, so that any solution pair survives with good probability. This requires candidate pairs to 'mix well' (fall into many residue classes). For worst-case inputs mixing may fail; the mixing dichotomy converts that failure into structure (unbalanced solution or many solutions) solvable by other means, while for well-mixing instances the filtered space drops below |C|^{n/2}, beating Meet-in-the-Middle.
- **reduction_pipeline** (Method): No reduction to an external problem; the method works directly by modular filtering of candidate vector sets. Coefficient shifting is an internal algebraic reduction C = C1 + C2 (e.g. {0,1} + {-3,-2,1,2} = [±3]). The compatibility-certificate subroutine is inspired by a sparse Orthogonal Vectors technique.
- **constructive_vs_existential** (Method): Constructive: the algorithms are fully algorithmic and output a solution.
- **search_vs_decision_witness** (Method): Returns an explicit witness (a nonzero coefficient vector c in C^n with c.x = 0); constructivity is proved, not merely existential.
- **obstacle_to_2n3** (Frontier): The method only reduces the coefficient base, yielding |C|^{(0.5-eps)n}; it does not approach a 2^{n/3} time bound for {0,1} Subset Sum. Two natural worst-case cases are left unbroken: C = [±1] (Partition/Subset Sum itself) and C = [±2]. Since a faster algorithm for [±1] would imply one for [±2] (by a blow-up self-reduction), the technique as presented cannot reach further until the no-zero coefficient sets are handled. Moreover the 2^{n/3} regime is currently established only for Pigeonhole Equal Subset Sum (a total-search regime with guaranteed many solutions), not for general worst-case Subset Sum.
- **potential_to_break_mitm** (Frontier): Medium for the general Subset Balancing family (many coefficient sets now broken in the worst case), but low-to-medium for collapsing all the way to 2^{n/3}: C = [±1] and C = [±2] are explicitly named as remaining barriers, and the authors frame the result as strengthening the 'circumstantial case' rather than solving Partition.
- **barrier_evidence** (Frontier): No proven lower bound rules out beating Meet-in-the-Middle; the hardness is the unproven MITM conjecture. The concrete barrier in this work is the pair of unresolved coefficient sets C = [±1] (Partition/Subset Sum) and C = [±2], with [±1] implying [±2]. SETH gives lower bounds only for the pseudopolynomial regime, not this one. The paper notes that additional insights may be needed if [±2] is genuinely hard.
- **open_questions** (Frontier): (1) Break the Meet-in-the-Middle barrier in the worst case for C = [±1] (Partition/Subset Sum) and C = [±2]. (3) Tighten the integration of compatibility certificates with the [-d:d] and [±d] algorithms for further runtime gains. (4) Derive a time-space tradeoff for these worst-case balancing algorithms. (5) Determine whether the representation/mixing framework can yield a single-exponential improvement visible for {0,1} Subset Sum.
- **conditional_hypothesis** (Assumptions): No conditional hypothesis is needed for the upper bounds; they are unconditional. The hardness of the remaining cases rests only on the unproven Meet-in-the-Middle conjecture (whether O(2^{(0.5-eps)n}) worst-case Subset Sum exists). SETH is relevant only to pseudopolynomial lower bounds.
- **worst_case_vs_average_case_guarantee** (Assumptions): Worst-case. This is precisely the advance over Chen-Jin-Randolph-Servedio (SODA 2022), which obtained the same type of improvement only in the average case.
- **cryptographic_regime** (Assumptions): The representation technique originates in knapsack cryptanalysis (Howgrave-Graham-Joux, CRYPTO 2010) and low-density Subset Sum is polytime-solvable; however these worst-case results do not themselves break knapsack cryptosystems, which rely on the average-case low-density regime. No concrete density/sample parameters are given.

## schroeppel_shamir_orthogonal_vectors

- **name** (Basic): schroeppel_shamir_orthogonal_vectors
- **category** (Basic): technique
- **description** (Basic): Nederlof and Wegrzycki (STOC 2021) give the first improvement over the space complexity of the 40-year-old Schroeppel-Shamir Subset Sum algorithm while keeping the same O*(2^{n/2}) time. They reduce worst-case n-integer Subset Sum to the Orthogonal Vectors (OV) problem in a space-efficient way, and design a new OV algorithm for the hard support-size d/4 regime. The reduction combines the Schroeppel-Shamir four-way-split priority-queue method with the Howgrave-Graham-Joux representation technique (a random-prime modular filter), while the OV algorithm refines the representative-families framework of Fomin-Lokshtanov-Panolan-Saurabh. The resulting randomized algorithm runs in O*(2^{0.5n}) time and O*(2^{0.249999n}) space, improving Schroeppel-Shamir's O*(2^{n/4}) space. The construction exposes a tight two-way relation between Subset Sum and OV: any improvement of the OV algorithm would immediately improve the Subset Sum running time, which remains the long-standing open barrier.
- **worst_case_time** (Complexity): O*(2^{0.5n}) = O*(2^{n/2}); the Schroeppel-Shamir time bound is matched, not beaten.
- **space_complexity** (Complexity): O*(2^{0.249999n}), improving the previous O*(2^{n/4}) = O*(2^{0.25n}) of Schroeppel-Shamir; later improved to O*(2^{0.246n}) by Belova-Chukhin-Kulikov-Mihajlin (ESA 2024).

- **time_space_tradeoff_curve** (Complexity): The result is a single point at time O*(2^{0.5n}), space O*(2^{0.249999n}). Context: Schroeppel-Shamir gives a general tradeoff with space S and time about 2^n / S^2 for S <= O*(2^{n/4}); this work improves the low-space endpoint at S = 2^{0.249999n}. The tight SS-OV relation means an improvement of the OV algorithm would improve either the time or the space of this tradeoff.
- **numerical_exponent_and_record_year** (Complexity): Time exponent 0.5 (2^{0.5n}) remains unbeaten since Schroeppel-Shamir (FOCS 1979 / SIAM 1981); space exponent improved from 0.25 to 0.249999 in 2021 (STOC 2021), then to 0.246 in 2024.
- **problem_variant** (Scope): Vanilla worst-case Subset Sum (n-integer decision/search), equivalent to Partition; the reduction targets the general worst-case instance rather than a promised/dense variant.
- **applies_to** (Scope): Exact worst-case n-integer Subset Sum instances, including dense instances; the algorithmic core is a reduction to the Orthogonal Vectors problem on {0,1}^d vectors of support size d/4.
- **coefficient_set** (Scope): Not a balancing/coefficient-set result: it concerns {0,1} subset selection (the indicator vector). In Subset Balancing notation this is C = [±1] (Partition/Subset Sum).

- **core_idea** (Method): Schroeppel-Shamir achieve O*(2^{n/4}) space by splitting into four lists and lazily generating pair sums with priority queues, avoiding materializing 2^{n/2} sums. Nederlof-Wegrzycki keep the 2^{n/2} time but replace the memory bottleneck with a space-efficient OV reduction: the representation technique filters candidate vectors modulo a random prime so only O*(2^{0.249999n}) objects need to be stored, and a specialized OV algorithm resolves the remaining matching step. The support-size d/4 OV regime is the hard case, and the representative-families machinery currently yields no sub-2^{0.5n} SS time. ## Space-Efficient Exact Algorithms for Subset Sum (reduced-space Schroeppel-Shamir family)

- **name** (Basic): Space-Efficient Exact Algorithms for Subset Sum (reduced-space Schroeppel-Shamir family)
- **category** (Basic): algorithmic-family
- **description** (Basic): A line of work on exact worst-case Subset Sum that preserves the Schroeppel-Shamir O*(2^{0.5n}) time bound while pushing the space usage down. Schroeppel and Shamir (FOCS 1979) solved n-integer Subset Sum in O*(2^{0.5n}) time and O*(2^{0.25n}) space. Nederlof and Wegrzycki (STOC 2021) gave the first space improvement, to O*(2^{0.249999n}), by combining the representation technique (Howgrave-Graham-Joux) with a new reduction to and algorithm for Orthogonal Vectors. Belova, Chukhin, Kulikov and Mihajlin (ESA 2024) further reduce the space to O*(2^{0.246n}) and simplify the algorithm by filtering the family of subsets with a random prime (an idea of Howgrave-Graham and Joux) and then running Schroeppel-Shamir's sorted sum enumeration inside the representation technique, reducing one Subset Sum instance to many instances of Weighted Orthogonal Vectors. In parallel, a polynomial-space line solves Subset Sum in exponential time: Bansal-Garg-Nederlof-Vyas (SODA 2018) get O*(2^{0.86n}) time with poly(n, log t) space (assuming random read-only access to random bits); Kane (2010) gave a log-space algorithm with e^{O(n^3 t + n^{2.025} t^{1.025})} time; Jin and Vyas (SODA 2021) give fast low-space algorithms with explicit time-space tradeoffs.
- **worst_case_time** (Complexity): O*(2^{0.5n}) for the reduced-space algorithms (Belova et al. ESA 2024; Nederlof-Wegrzycki STOC 2021), matching Schroeppel-Shamir FOCS 1979. The polynomial-space line has much larger time: O*(2^{0.86n}) (Bansal-Garg-Nederlof-Vyas SODA 2018), while Chen-Jin-Randolph-Servedio (APPROX/RANDOM 2023) give O(2^{n/2} * n^{-0.5023}) time, the first sub-2^{n/2} worst-case time for classical meet-in-the-middle.
- **space_complexity** (Complexity): O*(2^{0.246n}) for Belova-Chukhin-Kulikov-Mihajlin (ESA 2024), improving O*(2^{0.249999n}) (Nederlof-Wegrzycki STOC 2021) and O*(2^{0.25n}) (Schroeppel-Shamir FOCS 1979). Polynomial-space algorithms use poly(n, log t) space (Bansal-Garg-Nederlof-Vyas 2018) or O(log(nt)) space (Kane 2010).
- **time_space_tradeoff_curve** (Complexity): The best reduced-space result is essentially a single point: time O*(2^{0.5n}), space O*(2^{0.246n}). More broadly there is a tradeoff family. Schroeppel-Shamir: O*(2^{0.5n}) time, O*(2^{0.25n}) space. Jin-Vyas (SODA 2021): fast low-space algorithms with an explicit time-space tradeoff, e.g. time 2^{n/2}/poly(n) at roughly 2^{n/4} space and polynomial-space variants. Bansal-Garg-Nederlof-Vyas: O*(2^{0.86n}) time at polynomial space. Abboud-Bringmann-Hermelin-Shabtay (STOC 2019) give SETH-based lower bounds constraining simultaneous low time and low space (when T = S one cannot beat about t^{1-eps} 2^{o(n)}).
- **numerical_exponent_and_record_year** (Complexity): Space exponent 0.246*n (Belova-Chukhin-Kulikov-Mihajlin, ESA 2024); previous record 0.249999*n (Nederlof-Wegrzycki, STOC 2021); original 0.25*n (Schroeppel-Shamir, FOCS 1979). Time exponent has stayed at 0.5*n since 1979; only polynomial factors were shaved in 2023 (2^{n/2} * n^{-0.5023}, Chen-Jin-Randolph-Servedio).
- **problem_variant** (Scope): Vanilla worst-case Subset Sum (decision). The same machinery also applies to Knapsack, k-SUM and binary integer programming with few constraints.
- **applies_to** (Scope): Worst-case instances of Subset Sum with n integers and a target t; also Knapsack, k-SUM (Bansal-Garg-Nederlof-Vyas), and Weighted Orthogonal Vectors, which is used as the inner problem by Nederlof-Wegrzycki and Belova et al.
- **coefficient_set** (Scope): Not applicable for vanilla Subset Sum, which uses C = {0,1}. The related subset-balancing / generalized subset-sum family uses larger constant coefficient sets C, but that is a different line of work.
- **density_regime** (Scope): Density-independent, general worst case. The random-prime / Howgrave-Graham-Joux filtering idea historically targets density around 1 (knapsack cryptanalysis), but the ESA 2024 and STOC 2021 results are stated for arbitrary worst-case instances.
- **solution_regime** (Scope): General decision problem (no promise of many solutions). The representation technique still relies on a solution having many representations in the enlarged search space.
- **cardinality_constraint** (Scope): No fixed-cardinality constraint. Internally, however, the representation technique splits the search space into Hamming-weight layers and Schroeppel-Shamir enumerates subset sums in cardinality layers, which is what enables the low space bound.
- **key_technique** (Method): Random-prime modular filtering of the family of subsets (Howgrave-Graham-Joux, CRYPTO 2010), combined with Schroeppel-Shamir's low-space sorted sum enumeration and the representation technique; the filtered instance is reduced to many instances of Weighted Orthogonal Vectors.
- **core_idea** (Method): Pick a random prime p and keep only subsets whose sum matches the target modulo p; a genuine solution then has many modular representations, so each filtered smaller instance is easier to solve. Because Schroeppel-Shamir can enumerate subset sums in sorted order using only O*(2^{n/4}) memory, running it inside this filter lowers the space bound while keeping O*(2^{n/2}) time. Belova et al. additionally use the prime-filter structure to simplify and sharpen the analysis, obtaining 0.246n.
- **reduction_pipeline** (Method): Subset Sum -> random-prime modular filter (one instance into many smaller instances) -> Weighted Orthogonal Vectors -> representation-technique combination; Schroeppel-Shamir serves as the inner sum-enumeration primitive.
- **constructive_vs_existential** (Method): Constructive: the algorithms decide feasibility and standard self-reduction recovers the witness. The underlying works prove that a solution is preserved by the modular filter.
- **search_vs_decision_witness** (Method): Primarily decides feasibility; self-reduction yields an explicit witness, and constructivity is established in the works (the filter is designed so that a solution is not lost).
- **obstacle_to_2n3** (Frontier): These results only reduce space and do not touch the O*(2^{0.5n}) time bottleneck. The algorithms still enumerate or process about 2^{n/2} subset sums (or 2^{n/2} representations), so no parameter choice can push them to O*(2^{n/3}). Reaching 2^{n/3} would require a genuine time breakthrough (beating meet-in-the-middle in time), which space improvements alone cannot provide.
- **potential_to_break_mitm** (Frontier): low
- **barrier_evidence** (Frontier): Abboud, Bringmann, Hermelin and Shabtay (STOC 2019) prove SETH-based conditional lower bounds for Subset Sum and time-space tradeoffs (when time equals space, t^{1-eps}2^{o(n)} time and space would refute SETH). The O*(2^{n/2}) worst-case time barrier for Subset Sum is a central open problem independent of space.
- **open_questions** (Frontier): Can the space exponent be pushed below 0.246*n, or all the way to polynomial, while keeping O*(2^{0.5n}) time? Can the time be improved below 2^{n/2} simultaneously with low space? Is there a matching lower bound on the time-space tradeoff for the exact decision problem (analogous to the ABHS lower bounds)? Can the random-prime filter be derandomized?
- **conditional_hypothesis** (Assumptions): SETH is used only for the conditional time-space lower bounds (Abboud-Bringmann-Hermelin-Shabtay). The upper-bound space results are unconditional (randomized) and do not rest on lattice, 3-SUM, or k-SUM assumptions.

## Structured 3SUM/4SUM over Subset-Sum Sets (Three-Block Split)

- **name** (Basic): Structured 3SUM/4SUM over Subset-Sum Sets (Three-Block Split)
- **category** (Basic): technique
- **description** (Basic): A proposed fine-grained route toward an O*(2^{n/3}) worst-case algorithm for exact Subset Sum. Split the n input items into three blocks of about n/3 items each. Enumerate the subset-sum set of every block; each has cardinality 2^{n/3}. A subset summing to the target t exists iff there are a in A, b in B, c in C with a+b+c = t, i.e. a 3-SUM instance over the three structured sets A, B, C. If this 3-SUM can be decided in near-linear time in N = 2^{n/3} - by exploiting the additive structure of subset-sum sets and, for bounded integers, boolean or min-plus convolution - then Subset Sum would run in O*(2^{n/3+o(n)}). The central question is whether subquadratic 3SUM/4SUM algorithms, which for arbitrary sets are limited by the 3SUM and k-SUM conjectures, can exploit sumset structure enough to beat the generic N^2 = 2^{2n/3} bound and the 2^{n/2} meet-in-the-middle barrier. A four-block variant reduces to combining two lists of size 2^{n/2} (the meet-in-the-middle bound).
- **worst_case_time** (Complexity): No algorithm achieves O*(2^{n/3}). The three-block split followed by a generic 3-SUM decision costs O*(N^2) = O*(2^{2n/3}) (sorting plus two-pointer or hashing), which is worse than meet-in-the-middle. A four-block split reduces to a 2-list convolution/2-SUM over 2^{n/2}-sized sets, recovering the meet-in-the-middle bound. Current best worst-case Subset Sum upper bound: O*(2^{n/2}) (Horowitz-Sahni 1974; Schroeppel-Shamir 1979; Chen-Jin-Randolph-Servedio 2023 shave a 1/poly factor: O(2^{n/2} n^{-0.5023})). Dense / value-sensitive regime: O~(|S(X,t)|^{4/3}) (Bringmann-Nakos STOC 2020) and O~(|S(X,t)| sqrt(n)) (Bringmann-Fischer-Nakos SODA 2025).
- **model** (Complexity): Word RAM / unit-cost integer RAM; real RAM for the additive-combinatorics variants (Fischer, SODA 2025). The 3SUM and k-SUM conjectures are normally stated in a random-access word-RAM model with hashing; comparison-based (real RAM) deterministic bounds are weaker.
- **randomized_or_deterministic** (Complexity): The known subquadratic 3SUM algorithms are randomized (Gronlund-Pettie, Chan, Freund, Gold-Sharir) or give only a 1/polylog deterministic improvement; bounded-integer and n-fold boolean convolution methods are randomized. No deterministic truly subquadratic 3SUM algorithm is known.
- **time_space_tradeoff_curve** (Complexity): k-SUM is conjectured to require N^{ceil(k/2)-o(1)} time. Wagner's k-list algorithm gives time/space about 2^{n/(1+log k)} for the modular generalized-birthday formulation (which is the basis of low-memory subset-sum/knapsack attacks). For subset sum specifically, SETH yields a time-space tradeoff lower bound (Abboud-Bringmann-Hermelin-Shabtay).
- **numerical_exponent_and_record_year** (Complexity): Target exponent 1/3 ~ 0.333 (unreached). Three-block naive reduction exponent 2/3 ~ 0.667. Four-block / meet-in-the-middle exponent 1/2 = 0.5 (Horowitz-Sahni 1974, Schroeppel-Shamir 1979; polynomial-factor shaving in 2023).
- **problem_variant** (Scope): Subset Sum reduced to k-SUM (k = 3, 4) over subset-sum sets / sumsets; bounded-integer 3SUM and boolean / min-plus convolution; closely related to Subset Balancing and Equal-Subset-Sum (which use coefficient sets rather than C = {0,1}).
- **applies_to** (Scope): Worst-case exact Subset Sum decision. Via subset-balancing coefficient sets the same structured-k-SUM viewpoint applies to Partition and Equal-Subset-Sum. The accelerator techniques target bounded-integer 3SUM and (min,+) / boolean convolution.
- **coefficient_set** (Scope): Not applicable to vanilla Subset Sum (C = {0,1}). The related Generalized Subset Sum / Subset Balancing family uses a constant-size coefficient set C in Z, with meet-in-the-middle cost |C|^{n/2}; that family is where worst-case meet-in-the-middle barriers have recently been broken for some C (Chen-Jin-Randolph-Servedio SODA 2022 average case; Randolph-Wegrzycki 2025 worst case for C = {-d,...,d}, d>1 and C = {-d,...,d}\{0}, d>2).
- **density_regime** (Scope): The structure is most exploitable in the dense / bounded-integer regime (small universe U, where 3SUM is solvable in O(N+U) and sumsets are dense intervals) and generally where the input has small doubling / high additive energy. In the sparse or superincreasing worst case the subset-sum sets are close to arbitrary and no exploitable structure is apparent.
- **solution_regime** (Scope): General decision. The pigeonhole / numerous-solution regime (Equal-Subset-Sum, Pigeonhole Equal Subset Sum) behaves differently and has its own recent algorithms (e.g. Jin-Williams-Zhang, ESA 2025, O*(2^{0.4n}) for Pigeonhole ESS).
- **cardinality_constraint** (Scope): No fixed-cardinality constraint in the three-block reduction; Hamming-weight layers appear only inside the representation technique used by the underlying sum-enumeration algorithms.
- **key_technique** (Method): Three-block (or four-block) split of the item set; exhaustive enumeration of each block's subset-sum set (2^{n/3} or 2^{n/4} elements); then a structured k-SUM / 3SUM decision over those sets. Candidate accelerators: subquadratic 3SUM, bounded-integer boolean convolution, additive combinatorics (small doubling / sumset bounds, additive energy), and fast n-fold boolean convolution.
- **core_idea** (Method): If a 3-SUM instance over three size-2^{n/3} structured sets can be decided in near-linear time N^{1+o(1)}, then Subset Sum runs in O*(2^{n/3+o(n)}). Unlike worst-case 3SUM, subset-sum sets are highly structured, especially for bounded or slowly growing integers, so additive-combinatorics machinery might exploit this. But for arbitrary (e.g. superincreasing) inputs the three sets can be essentially arbitrary, and then the k-SUM conjecture blocks any N^{2-eps} algorithm, leaving the split no better than 2^{2n/3}.
- **reduction_pipeline** (Method): Subset Sum -> partition items into 3 blocks -> subset-sum sets A, B, C each of size 2^{n/3} -> 3SUM / 4SUM decision (does a+b+c = t hold) -> optionally bounded-integer boolean convolution or min-plus convolution. Four-block variant: check A+B against -(C+D), a 2-list convolution of 2^{n/2}-sized sets (meet-in-the-middle).
- **constructive_vs_existential** (Method): Algorithmic in principle, but the O*(2^{n/3}) endpoint is currently only a conjectural / structural research direction; no proved algorithm reaches it.
- **search_vs_decision_witness** (Method): Decision first; standard self-reduction would yield an explicit witness if the structured k-SUM decision were solved efficiently. No witness construction is currently proved for the three-block route.
- **obstacle_to_2n3** (Frontier): The generic 3SUM / k-SUM conjecture says 3-SUM on N = 2^{n/3} elements requires N^{2-o(1)} = 2^{2n/3-o(n)} time, so the straightforward split cannot beat meet-in-the-middle. Reaching 2^{n/3} requires a near-linear-time 3-SUM, i.e. exploiting sumset structure strongly enough to overcome the k-SUM-conjecture barrier; no such structure theorem or algorithm is known for worst-case subset-sum sets. Moreover, subset-sum sets can be exponentially sparse in their universe, which defeats bounded-integer convolution since those algorithms run in time polynomial in the universe size.
- **potential_to_break_mitm** (Frontier): low (medium only for restricted dense / bounded-integer or bounded-doubling instances)
- **barrier_evidence** (Frontier): The 3SUM conjecture (Gajentaan-Overmars 1995; modern integer form with hashing) and the k-SUM conjecture (Abboud-Lewi, ICALP 2013) forbid N^{2-eps}-time 3-SUM for every eps > 0. SETH-based lower bounds constrain Subset Sum time and time-space tradeoffs (Abboud-Bringmann-Hermelin-Shabtay, SODA 2019). Subset Sum is subquadratically equivalent to (min,+)-convolution in the approximation regime (Bringmann-Kunnemann-Wegrzycki, SODA 2020), tying it to convolution hardness.
- **open_questions** (Frontier): Is there a truly subquadratic 3SUM algorithm restricted to subset-sum sets (sumsets) of bounded size? Can small-doubling / additive-energy bounds on |A+B| be converted into an algorithm for the three-block Subset Sum instance? Can bounded-integer convolution be adapted to exponentially sparse sumsets via hashing / clustering? Does the three-block formulation yield new SETH-hardness for a structured k-SUM variant? Can the representation technique's pseudosolution pairs be combined with a block split to break the meet-in-the-middle time barrier in the worst case?
- **conditional_hypothesis** (Assumptions): 3SUM conjecture, k-SUM conjecture, SETH (for Subset Sum time-space lower bounds), and the subquadratic equivalence with (min,+)-convolution / min-plus convolution.
- **worst_case_vs_average_case_guarantee** (Assumptions): The structure that would be exploited is a property of dense, bounded-integer or random instances (and of related balancing problems whose meet-in-the-middle barrier was broken first in the average case, Chen-Jin-Randolph-Servedio SODA 2022, then in the worst case for some coefficient sets, Randolph-Wegrzycki 2025). For genuine worst-case superincreasing inputs the structure disappears.
- **cryptographic_regime** (Assumptions): Relevant to knapsack cryptanalysis at density around 1: the three/four-list split and the Howgrave-Graham-Joux representation technique underlie modern low-memory subset-sum/knapsack attacks, and Wagner-style k-list algorithms give the low-memory tradeoff. Bounded-integer convolution ideas connect to lattice and birthday-style attacks, but the three-block 3SUM route is not itself a demonstrated cryptanalytic break.
- **pseudopolynomial_interaction** (Assumptions): Strongly coupled. Bounded-integer 3SUM is solved by FFT / convolution in O(N+U) or O(U log U); Bellman's DP is O(|S(X,t)|*n); Bringmann-Nakos achieve O~(|S(X,t)|^{4/3}) (STOC 2020) and Bringmann-Fischer-Nakos O~(|S(X,t)|*sqrt(n)) (SODA 2025). These are precisely the tools one would combine with the block split in dense regimes.

## Additive-Combinatorics Density Dichotomy for Subset Sum (sumsets, additive energy, Kneser/AP structure)

- **name** (Basic): Additive-Combinatorics Density Dichotomy for Subset Sum (sumsets, additive energy, Kneser/AP structure)
- **category** (Basic): additive-combinatorics
- **description** (Basic): A line of work that solves Subset Sum in near-linear time on dense instances by exploiting additive structure of sumsets. Bringmann-Wellnitz (SODA 2021) revived and improved Galil-Margalit (SICOMP 1991): if the target t is large relative to the item sizes (roughly t >> a_max * Sigma_X / n^2), then dense Subset Sum is solvable in near-linear time OTilde(n) for the decision problem, using sparse convolution plus sumset estimates and an adaptation of Sarkozy's addition theorem. Chen-Mao-Zhang (STOC 2025) then gave constructive proofs of Sarkozy's finite addition theorems, yielding an OTilde(n)-time algorithm that actually returns a long arithmetic progression inside the sumset plus, for each term, an explicit representation as a sum of input elements; this upgrades dense Subset Sum and Unbounded Subset Sum from decision to search. The same additive-combinatorics toolkit (Kneser's theorem for n-fold Boolean convolution, sumset/additive-energy/doubling structure) also underlies the pseudopolynomial algorithm OTilde(n + sqrt(a_max t)) of Chen-Lian-Mao-Zhang (FOCS 2024). The dichotomy is: dense instances are easy (near-linear, poly space) and sparse (density ~ 1, random-knapsack-like) instances have no long progressions and are not touched, so this line does not improve the general O*(2^{n/2}) worst-case bound.
- **worst_case_time** (Complexity): On dense / large-target instances: OTilde(n) time (near-linear) for the decision problem (Bringmann-Wellnitz, SODA 2021) and now for the search problem (Chen-Mao-Zhang, STOC 2025); Unbounded Subset Sum solvable in O(n log a_max) for all t >= c * a_max^2 / n. On general instances (arbitrary density) this approach gives no sub-2^{n/2} bound; the state of the art remains O*(2^{n/2}) (Horowitz-Sahni meet-in-the-middle). Pseudopolynomial cousin: OTilde(n + sqrt(a_max * t)) for the decision problem (Chen-Lian-Mao-Zhang, FOCS 2024).
- **time_space_tradeoff_curve** (Complexity): single point
- **numerical_exponent_and_record_year** (Complexity): Dense regime: base-2 exponent 0 (linear up to polylog), records 2021 (decision) and 2025 (search/witness). General worst-case: unchanged exponent 1/2 (i.e. 2^{n/2}); this line contributes no constant c > 0 for 2^{(1/2-c)n}.
- **problem_variant** (Scope): Dense Subset Sum (large target / polynomial-size items); Unbounded Subset Sum; decision and search versions; related to bounded-integer convolution and n-fold Boolean convolution.
- **applies_to** (Scope): Positive-integer Subset Sum instances in the dense regime, i.e. item sizes and target bounded by poly(n) or with t >> a_max * Sigma_X / n^2; Unbounded Subset Sum for t >= c * a_max^2 / n. Does not apply to sparse, low-density, or random-knapsack-style instances ({0,1} subset sum at density ~ 1).
- **coefficient_set** (Scope): {0,1} for vanilla Subset Sum; {0,1,2,...} (unbounded multiplicities) for Unbounded Subset Sum; general bounded integer coefficients in the convolution formulations.
- **density_regime** (Scope): High density / dense: d = n / log2(max|a_i|) large (items and target polynomial in n), equivalently t >> a_max * Sigma_X / n^2. The complementary low-density regime (d ~ 1 or less, e.g. cryptographic knapsacks) is explicitly outside the reach of this method.
- **solution_regime** (Scope): General decision, extended by Chen-Mao-Zhang (STOC 2025) to the search/witness version for dense instances; not a promised/numerous-solution (pigeonhole) regime.
- **cardinality_constraint** (Scope): No fixed-cardinality constraint; solutions may use any number of items.
- **key_technique** (Method): Additive combinatorics of sumsets: long arithmetic progressions in subset sums (Sarkozy's finite addition theorems), sumset size / Freiman-type structure, small doubling and additive energy, and Kneser's theorem (used centrally for n-fold Boolean and bounded-integer convolution, Bringmann-Nakos ICALP 2021). Algorithmically: sparse convolution, sumset estimates, and constructive/recursive recovery of progressions and their representations.
- **core_idea** (Method): In dense instances the subset-sumset necessarily contains a long arithmetic progression with a small step and small start; one finds such a progression (now constructively) and, because every term has a representation using few base elements, recovers an explicit witness. This replaces exponential enumeration over subset sums by near-linear-time sumset manipulation, which is why the dense case collapses to OTilde(n). Sparse instances have no long progressions in their sumsets, so the technique gives nothing there and cannot touch the 2^{n/2} worst case.
- **reduction_pipeline** (Method): Subset Sum -> sumset S(A) and its additive structure (long AP with small step) -> recover representation per AP term; convolution route: Subset Sum/knapsack counting -> n-fold Boolean / bounded-integer convolution solved via Kneser's theorem and additive structure. Chen-Lian-Mao-Zhang use Szemeredi-Vu for arithmetic progressions in the pseudopolynomial route.
- **constructive_vs_existential** (Method): Constructive. The key novelty of Chen-Mao-Zhang (STOC 2025) is turning the previously existential Sárközy addition theorems into constructive proofs that output the AP and explicit element-set representations, closing the decision-vs-search gap for dense Subset Sum.
- **search_vs_decision_witness** (Method): Returns an explicit witness for dense Subset Sum (each AP term's representation as a sum of base elements); prior additive-combinatorics algorithms handled only decision.
- **obstacle_to_2n3** (Frontier): The method is confined to the dense regime and gives near-linear time there, not an exponential-base saving on general instances. Sparse / low-density instances (density ~ 1, random knapsack) have sumsets with no long arithmetic progressions, so the additive structural hypothesis is vacuous; reaching O*(2^{n/3}) on general ({0,1}) Subset Sum would require handling instances where this toolkit provably does not apply. Moreover the near-linear guarantee requires t polynomially large relative to a_max * Sigma / n^2; below that threshold the method fails and a conditional lower bound rules out near-linear time.
- **potential_to_break_mitm** (Frontier): low for the general worst-case MITM barrier (it solves only the complementary dense regime, not sparse hard instances); medium-to-high only for the dense subproblem, where it already beats 2^{n/2} by an exponential margin.
- **barrier_evidence** (Frontier): Bringmann-Wellnitz prove a conditional lower bound: a subquadratic or near-linear algorithm for the regime t << a_max * Sigma_X / n^2 would contradict SETH and the Strong k-SUM Hypothesis, so the dense algorithm's threshold is essentially tight. The method's applicability condition is also a barrier: additive structure (long progressions in the sumset) simply fails for sparse/random instances, so the approach is structurally incapable of handling them.
- **open_questions** (Frontier): Can constructive addition theorems be extended to less dense / multi-dimensional settings with matching bounds (multi-dimensional dense subset sum)? Can the dense decision-vs-search gap be closed under weaker target conditions or for multisets where upper and lower bounds do not match? Can Kneser-theorem-style convolution methods be combined with worst-case representation/mixing techniques to attack sparse instances? Is there a deterministic near-linear search algorithm under minimal target assumptions?
- **conditional_hypothesis** (Assumptions): SETH and the Strong k-SUM Hypothesis underlie the matching conditional lower bound at the density threshold; Kneser's theorem and Sarkozy/Szemeredi-Vu addition theorems are unconditional additive-combinatorics ingredients (no hardness assumption for the positive dense result).
- **worst_case_vs_average_case_guarantee** (Assumptions): Worst-case within the restricted dense regime (guarantee conditional on t >> a_max * Sigma_X / n^2), and constructive. Not a general worst-case guarantee; it deliberately excludes the hard, sparse, worst-case instances.
- **cryptographic_regime** (Assumptions): Orthogonal/complementary to low-density knapsack cryptanalysis (Lagarias-Odlyzko, density d < 0.94): those attacks live in exactly the sparse regime this line cannot handle. Relevance is the density dichotomy itself, sharpening where dense methods stop and lattice/representation methods take over; no attack on cryptographic knapsacks.
- **pseudopolynomial_interaction** (Assumptions): Strong. The line is intertwined with pseudopolynomial algorithms: Chen-Lian-Mao-Zhang (FOCS 2024) give OTilde(n + sqrt(a_max t)) time for decision Subset Sum using the dense-or-sparse framework and Szemeredi-Vu, and the dense algorithms merge with DP/proximity to handle small-item regimes.

## Bit-Packing and Word-/Circuit-RAM Techniques for Worst-Case Subset Sum (Baran-Demaine-Patrascu adapted by Chen-Jin-Randolph-Servedio)

- **name** (Basic): Bit-Packing and Word-/Circuit-RAM Techniques for Worst-Case Subset Sum (Baran-Demaine-Patrascu adapted by Chen-Jin-Randolph-Servedio)
- **category** (Basic): word-ram-technique
- **description** (Basic): A word-level parallelism technique, originally introduced by Baran, Demaine and Patrascu (WADS 2005 / Algorithmica 2008) to obtain subquadratic 3SUM and 3XOR algorithms, that packs many small integers (subset-sum differences) into single machine words so that sorted-list merging/comparison in meet-in-the-middle runs many comparisons per word operation. Chen, Jin, Randolph and Servedio (APPROX/RANDOM 2023) adapted this bit-packing trick to Subset Sum, combining it with the representation method (Howgrave-Graham-Joux; Austrin-Kaski-Koivisto-Nederlof; Nederlof-Wegrzycki). The result is the first improvement in the worst case over the classical Horowitz-Sahni meet-in-the-middle bound: an algorithm running in O(2^{n/2} * n^{-gamma}) time for a constant gamma > 0.5023 in the standard word RAM and circuit RAM models. The gain is only a polynomial factor (the exponent base 2 and the n/2 exponent are unchanged in the limit), so it does not approach 2^{n/3}.
- **worst_case_time** (Complexity): O(2^{n/2} * n^{-gamma}) with gamma > 0.5023 for worst-case n-input Subset Sum (decision, and search with the same asymptotic runtimes), in standard word RAM and circuit RAM models (Chen-Jin-Randolph-Servedio, APPROX/RANDOM 2023). The pure bit-packing result before adding the representation method is O(2^{n/2} * n^{-1/2} * log n) in circuit RAM and OTilde(2^{n/2} * n^{-1/2}) in word RAM. This is a polynomial-factor improvement: asymptotically 2^{(1/2 - o(1))n}, not 2^{(1/2 - c)n} for a constant c.
- **model** (Complexity): Standard word RAM with w-bit words, and circuit RAM (with one nonstandard AC0 word-level operation); the models are inherited from Baran-Demaine-Patrascu's 3SUM algorithms.
- **randomized_or_deterministic** (Complexity): Randomized (Monte Carlo) with constant success probability; the decision algorithm is converted into a search algorithm with the same asymptotic runtimes, and the success probability can be amplified. The underlying meet-in-the-middle comparison step is deterministic, but the representation/mixing and bit-packing construction are randomized.
- **time_space_tradeoff_curve** (Complexity): single point
- **numerical_exponent_and_record_year** (Complexity): Base 2, leading exponent n/2 (unchanged) with an extra polynomial saving n^{-gamma}, gamma > 0.5023; record year 2023 (APPROX/RANDOM 2023, arXiv:2301.07134). Direct bit-packing-only record: n^{-1/2} factor (same paper).
- **problem_variant** (Scope): Vanilla (worst-case, n-input) Subset Sum, decision and search; the related representation-method work also treats worst-case subset balancing and Equal-Subset-Sum.
- **applies_to** (Scope): General worst-case Subset Sum instances with no density or distribution assumption; n integers and a target, standard word RAM / circuit RAM. Also applies to the associated list-merge primitive shared with 3SUM/4SUM and to subset-balancing variants.
- **coefficient_set** (Scope): {0,1} (each item used at most once); the technique is coefficient-set agnostic for the list-merge primitive.
- **density_regime** (Scope): General / worst-case, all densities (no dense or low-density assumption); the polynomial saving holds unconditionally in the word-RAM oracle model.
- **solution_regime** (Scope): General decision; also search/witness, since the randomized decision algorithm is shown to yield a randomized search algorithm with the same asymptotic runtimes.
- **cardinality_constraint** (Scope): No fixed-cardinality/Hamming-layer constraint in the vanilla formulation.
- **key_technique** (Method): Bit-packing / word-level parallelism (Baran-Demaine-Patrascu): encode many subset-sum values or differences as fields inside w-bit machine words and perform many comparisons/subtractions simultaneously; combined with the representation method (Howgrave-Graham-Joux and its Austrin-Kaski-Koivisto-Nederlof / Nederlof-Wegrzycki adaptations), sorted sum enumeration, and randomized list merging.
- **core_idea** (Method): Meet-in-the-middle is bottlenecked by comparing/merging two sorted lists of 2^{n/2} subset sums. Bit-packing lets w / (bits per field) comparisons happen per word operation, shaving a polynomial factor n^{Theta(1)} off the 2^{n/2} bound. The representation method then exploits the slack in the number of representations to reduce the effective list sizes further and push the saving to n^{-0.5023}. Because the saving is polynomial, the dominant exponential factor 2^{n/2} is untouched; only a super-constant sub-exponential (n^{-gamma} = 2^{-gamma log n}) factor is removed.
- **reduction_pipeline** (Method): Subset Sum -> meet-in-the-middle split into two half-size sorted sum lists -> word-RAM accelerated list comparison via bit-packing -> representation-method counting/mixing to shrink effective lists; the bit-packing primitive is transferred from the 3SUM/int3SUM/3XOR reduction line of Baran-Demaine-Patrascu.
- **constructive_vs_existential** (Method): Constructive algorithmic method: it yields an actual algorithm and (with the randomized decision-to-search conversion) an explicit witness; output is a solution set, not merely an existence proof.
- **search_vs_decision_witness** (Method): Both: the paper gives a randomized decision algorithm and shows how to obtain a randomized search algorithm returning a witness with the same asymptotic runtimes.
- **obstacle_to_2n3** (Frontier): The method only shaves a polynomial factor. Writing O(2^{n/2} n^{-gamma}) = 2^{(1/2)n - gamma log n}, the improvement is 2^{-Theta(log n)}, i.e. sub-exponential but not exponential; to reach O*(2^{n/3}) one needs a reduction of the leading exponent from 1/2 to 1/3, i.e. an exponential-factor saving that bit-packing/word parallelism cannot provide. The representation-method component that supplies the n^{-0.5023} factor is effective only when there are many representations (typically average-case / high-density of representations), and its worst-case replacement is exactly the open worst-case representation-mixing problem.
- **potential_to_break_mitm** (Frontier): low for reaching 2^{n/3}; medium as a building block, since it did (barely) break the exact Horowitz-Sahni worst-case bound and its word-RAM list-merge primitive could compose with other worst-case techniques.
- **barrier_evidence** (Frontier): The gain is provably only polynomial: no reduction of the leading n/2 exponent. The representation method's counting/mixing requires a surplus of representations, so purely worst-case instances lack the structure it exploits (this is why the γ is only ~0.5023, i.e. the same order as in average-case 2^{(1/2 - c)n} representation results). Any claim of breaking the MITM exponent meets the formal Meet-in-the-Middle conjecture and the SETH-based / k-SUM-conjecture lower bounds for Subset Sum. Bit-packing is also bounded by word size w = O(log n), so the parallel factor is at most poly(n).
- **open_questions** (Frontier): Can bit-packing be combined with a genuinely worst-case representation/mixing technique to get 2^{(1/2 - c)n} for a constant c > 0? Can the gamma > 0.5023 be substantially improved, or an unconditional lower bound on gamma be shown? Is the nonstandard AC0 operation in the circuit-RAM model necessary, or can the result be derandomized / done in plain word RAM? Does the word-RAM list-merge primitive help structured k-SUM/4SUM reductions toward a three-block 2^{n/3} split?
- **conditional_hypothesis** (Assumptions): No hardness assumption is needed for the upper bound (it holds unconditionally in word RAM / circuit RAM). Related lower bounds that bound further progress rest on SETH, the Strong k-SUM Hypothesis, and the formal Meet-in-the-Middle conjecture.
- **worst_case_vs_average_case_guarantee** (Assumptions): Explicitly worst-case: this is the first algorithm to improve the worst-case Horowitz-Sahni meet-in-the-middle bound. The representation-method ingredient classically relies on having many representations (average-case flavored), but the combined algorithm is presented with a worst-case running-time guarantee.
- **cryptographic_regime** (Assumptions): Not directly applicable: bit-packing accelerates the general meet-in-the-middle list merge used for worst-case Subset Sum and does not target low-density knapsack or decoding cryptanalysis regimes; its impact there is at most a polynomial-factor constant.
- **pseudopolynomial_interaction** (Assumptions): Limited/orthogonal to pseudopolynomial DP: it operates on the exponential meet-in-the-middle regime rather than on t-bounded dynamic programming. Its sorted-sum-enumeration and word-parallel comparison primitives could in principle be combined with proximity/representation-based pseudopolynomial routines, but no such combination is claimed.
- **implementation_artifact** (Evidence): none found
- **verification_method** (Evidence): Reproduce the bit-packing list-merge construction in a word-RAM model and count word operations; verify the n^{-0.5023} exponent by checking the representation-method counting argument and the sorted-sum-enumeration sizes; run the algorithm on random worst-case instances and compare timings to plain meet-in-the-middle; verify the reduction from the 3SUM bit-packing primitive and the decision-to-search conversion.
- **Uncertain fields**:
  - exact space complexity and whether bit-packing changes the space constant
  - the precise DOI for the Algorithmica 2008 version of Baran-Demaine-Patrascu
  - whether any empirical benchmarks exist
  - whether the gamma > 0.5023 bound can be made deterministic

## Algebraization, Inclusion-Exclusion and Convolution Methods for Subset Sum

- **name** (Basic): Algebraization, Inclusion-Exclusion and Convolution Methods for Subset Sum
- **category** (Basic): technique
- **description** (Basic): A line of algebraic techniques that evaluate a Subset Sum (or Knapsack) dynamic program without storing its pseudo-polynomial table. Lokshtanov and Nederlof (STOC 2010) formalize the DP as an arithmetic circuit over a ring of tables, where the expensive operation is convolution, then apply a linear transform (Discrete Fourier Transform for integer-indexed tables, zeta/Mobius transform - i.e. inclusion-exclusion over the subset lattice - for subset-indexed tables) so that convolution becomes pointwise multiplication; a single desired coefficient can then be computed in pseudo-polynomial time and polynomial space. This yields the first pseudo-polynomial-time, polynomial-space algorithms for Subset Sum and Knapsack, and via inclusion-exclusion the same idea gives polynomial-space algorithms for Weighted Set Cover, Weighted Steiner Tree and TSP. A parallel exponential-time line uses generating functions and inclusion-exclusion to attack worst-case instances in exponential time with polynomial space, culminating in the Bansal-Garg-Nederlof-Vyas O*(2^{0.86n})-time polynomial-space Monte Carlo algorithm.
- **worst_case_time** (Complexity): Two separate regimes. (1) Pseudo-polynomial: O~(n^3 t log t) time for Subset Sum and O~(n^4 log^2(vw) * v w) time for Knapsack (Lokshtanov-Nederlof, STOC 2010). (2) Exponential-time, polynomial-space: O*(2^{0.86n}) time for Subset Sum and Knapsack, assuming random read-only access to exponentially many random bits (Bansal-Garg-Nederlof-Vyas, FOCS 2017); randomized k-Sum variants use O(n^{k-0.5} polylog n) time. The best worst-case exponential time independently of space remains O*(2^{0.5n}) (Horowitz-Sahni 1974; Schroeppel-Shamir 1979), shaved only by polynomial factors in 2023 (Chen-Jin-Randolph-Servedio, 2^{n/2}/poly(n)).
- **space_complexity** (Complexity): Pseudo-polynomial regime: O~(n^2) space for Subset Sum and O~(n^2 log(vw)) for Knapsack (Lokshtanov-Nederlof, STOC 2010), replacing Bellman's O(t) / O(w) table space. Exponential regime: polynomial space, poly(n, log t) (Bansal-Garg-Nederlof-Vyas 2017); the low-space variant of Jin-Vyas (SODA 2021) uses O(log(nt)) space; Kane (2010) gave an earlier deterministic log-space algorithm. The inclusion-exclusion line for Steiner Tree uses O*(c) space (Nederlof, Algorithmica 2013).
- **time_space_tradeoff_curve** (Complexity): The algebraization framework exposes a tradeoff parameterized by the table dimension d and the ring/table size N: computing one output coefficient costs time O~(|C| * N * polylog N) and space O((|C| + log N) * polylog N), where |C| is the circuit size; space is essentially the circuit size, not the table size. Jin-Vyas give an explicit Subset Sum time-space tradeoff (e.g. O~(n t) time at O(log(nt)) space; O~(n^{1+eps} t) time for any eps>0). Otherwise each result is a single point: pseudo-polynomial O~(n^3 t) time / O~(n^2) space; exponential O*(2^{0.86n}) time / poly space; O*(2^{0.5n}) time / O*(2^{0.25n}) space (Schroeppel-Shamir).
- **numerical_exponent_and_record_year** (Complexity): Exponential regime: time exponent 0.86n with polynomial space, Bansal-Garg-Nederlof-Vyas, FOCS 2017 (SICOMP 2018). Pseudo-polynomial regime: O~(n^3 t log t) time with O~(n^2) space, Lokshtanov-Nederlof, STOC 2010. Best unconditional worst-case exponential time still 0.5n (1979/2023).
- **problem_variant** (Scope): Vanilla Subset Sum (decision) and Knapsack in the pseudo-polynomial regime; the algebraization/inclusion-exclusion framework also covers Weighted Set Cover, Weighted Steiner Tree, Traveling Salesman, Binary Linear Programming with few constraints, and k-Sum. The Bansal-Garg-Nederlof-Vyas result handles Subset Sum, Knapsack and Binary Linear Programming; its O(n^{k-0.5}) bound is for random k-Sum.
- **applies_to** (Scope): General (all) n-integer Subset Sum instances in the pseudo-polynomial-time / polynomial-space setting (Lokshtanov-Nederlof, Nederlof) and worst-case instances in the exponential-time / polynomial-space setting (Bansal-Garg-Nederlof-Vyas, Jin-Vyas). The generating-function coefficient-extraction technique in Jin-Vyas constructs a polynomial with a zero x^t coefficient for NO-instances and a nonzero x^t coefficient for YES-instances with high probability.
- **coefficient_set** (Scope): C = {0,1} for Subset Sum (each item chosen or not). Knapsack uses the same binary selection with different weight/value coefficients. The subset-indexed version works over the Boolean lattice (zeta/Mobius / inclusion-exclusion), and the integer-indexed version over products of cyclic groups (DFT).
- **density_regime** (Scope): Two faces. The pseudo-polynomial algorithms are efficient when the target t (or capacity w) is small, i.e. the low-density / small-item regime (polynomial in log t only). The Bansal-Garg-Nederlof-Vyas algorithm targets general worst-case instances and uses anti-concentration of subset sums, which is most useful in dense regimes; it is not density-restricted. The generating-function/Jin-Vyas approach also targets small t (pseudo-polynomial in t) with logarithmic space.
- **solution_regime** (Scope): General decision problem (no promise of many solutions) for both the pseudo-polynomial and the exponential polynomial-space algorithms.
- **cardinality_constraint** (Scope): No fixed-cardinality (Hamming-layer) constraint is assumed. Internally the subset-indexed transform (zeta/Mobius) works over the subset lattice and can encode cardinality when needed, but the target problems are unconstrained Subset Sum / Knapsack.
- **key_technique** (Method): Algebraization of dynamic programming: express the DP recurrence as an arithmetic circuit over the ring of tables R[S] (pointwise addition, convolution), then apply a linear transform that diagonalizes convolution - the Discrete Fourier Transform for tables indexed by Z_{N1} x ... x Z_{Nd}, and the zeta/Mobius (inclusion-exclusion) transform for tables indexed by subsets. Because the transformed circuit uses only pointwise operations and singleton constants, one output entry f[g] is recovered by the inverse transform sum f[g] = (1/N) * sum_j e^{-(g . t) . j} (F(f))[j], where each term (F(f))[j] is computed by a small O~(log N)-size circuit without materializing any table. Inclusion-exclusion / Mobius inversion and generating-function coefficient extraction are the subset-lattice and polynomial-product special cases.
- **core_idea** (Method): Convolution (adding two DP tables of subset sums) is the memory-hungry step, but it becomes pointwise multiplication after a Fourier/Mobius transform. Pointwise products need no intermediate tables, so the DP can be evaluated 'entry by entry' with space proportional to the circuit depth/size rather than to the table. In particular the generating function prod_i (1 + x^{a_i}) has x^t coefficient equal to the number of subsets summing to t, and extracting that single coefficient via the transform avoids storing the degree-t polynomial. The same diagonalization is why inclusion-exclusion turns subset-lattice convolutions into pointwise products. In the exponential setting, anti-concentration and implicit (cycle-finding) search over an exponentially large but implicitly represented space replace the table.
- **reduction_pipeline** (Method): Subset Sum / Knapsack DP -> arithmetic circuit over (R[S], circle-plus, convolution) with singleton constants -> DFT (integer-indexed) or zeta/Mobius inversion (subset-indexed) -> pointwise evaluation -> inverse transform to read one coefficient. Generating-function view: prod_{i} (1 + x^{a_i}) mod x^{t+1}, coefficient extraction by roots of unity / DFT. Exponential line: Subset Sum -> implicit large-list intersection / cycle finding -> O*(2^{0.86n}) poly-space. Inclusion-exclusion line: set covering / Steiner Tree -> subset-lattice zeta transform -> polynomial space.
- **constructive_vs_existential** (Method): Constructive: the algorithms compute the relevant coefficient / decide the instance, and standard self-reduction recovers an explicit witness. Bansal-Garg-Nederlof-Vyas is constructive (returns a witness list).
- **search_vs_decision_witness** (Method): Decides feasibility and, via self-reduction, returns an explicit witness; constructivity is established in the works (the coefficient is nonzero exactly when a solution exists, and Bansal-Garg-Nederlof-Vyas output an actual subset).
- **obstacle_to_2n3** (Frontier): The pseudo-polynomial algebraization algorithms run in time polynomial in t, which is exponential in n for large targets; they cannot give a 2^{c n} bound at all. The exponential polynomial-space line is much slower than the O*(2^{0.5n}) MITM barrier: Bansal-Garg-Nederlof-Vyas run in O*(2^{0.86n}) and Jin-Vyas in O~(n t) / O~(n^{1+eps} t), all well above 2^{n/2}, let alone 2^{n/3}. Algebraization saves space, not time: it diagonalizes the same exhaustive DP, so no parameter choice reduces the exponent below 0.5n. Reaching 2^{n/3} would require a genuine time breakthrough that the transform machinery does not provide.
- **potential_to_break_mitm** (Frontier): low
- **barrier_evidence** (Frontier): The algebraic method is a space-saving transformation of the same exhaustive DP, so it cannot beat the O*(2^{0.5n}) worst-case time barrier. Abboud, Bringmann, Hermelin and Shabtay (SODA 2019) give SETH-based lower bounds and time-space tradeoffs for Subset Sum (when time equals space, a t^{1-eps} 2^{o(n)} bound would refute SETH). The Bansal-Garg-Nederlof-Vyas result also depends on the random-read-only-bits assumption, and later work removed it using a pseudorandom hash family, indicating the assumption is mild but not vacuous.
- **open_questions** (Frontier): Can the polynomial-space exponential algorithms (Bansal-Garg-Nederlof-Vyas, Jin-Vyas) be derandomized / made independent of the random-bits assumption, or fully deterministic? Can the 0.86n exponent be pushed below 0.5n while retaining polynomial space? Is there a tight SETH-based lower bound for the time-space tradeoff of the exact decision problem matching the algebraic upper bounds? Can algebraization be combined with the representation technique / Howgrave-Graham-Joux filtering to gain both time and space?
- **conditional_hypothesis** (Assumptions): SETH underlies the conditional time-space lower bounds (Abboud-Bringmann-Hermelin-Shabtay). The upper bounds themselves are unconditional, except that Bansal-Garg-Nederlof-Vyas assume random read-only access to exponentially many random bits. No lattice or k-SUM hardness assumption is needed for the algebraic algorithms.
- **worst_case_vs_average_case_guarantee** (Assumptions): Lokshtanov-Nederlof and Nederlof are worst-case deterministic (all instances). Bansal-Garg-Nederlof-Vyas are Monte Carlo with high success probability on all instances (under the random-bits assumption); their k-Sum corollary is for random instances. Jin-Vyas is randomized with small error probability. So the line is predominantly worst-case (randomized) except for the explicit random-k-Sum statement.
- **cryptographic_regime** (Assumptions): Relevant to knapsack/subset-sum cryptanalysis: the pseudo-polynomial polynomial-space algorithm is efficient exactly in the low-target (small-density) regime where lattice and meet-in-the-middle attacks are classically applied, and the algebraic transforms are the same DFT/inclusion-exclusion tools used in representation-technique attacks. Bansal-Garg-Nederlof-Vyas's anti-concentration perspective is used to argue about density-1 and dense knapsack instances. These are asymptotic complexity results and not concrete attacks.
- **pseudopolynomial_interaction** (Assumptions): This is the central interaction: the algebraization framework is precisely a pseudo-polynomial-time, polynomial-space replacement for Bellman's pseudo-polynomial-space DP, and the generating-function/coefficient-extraction method is pseudopolynomial in t. It combines naturally with DP over subset-sum values and with inclusion-exclusion counting, and it is the space analogue of the ordinary O(nt) DP.

## Wagner's Generalized Birthday Problem / k-Tree and Modular Linear Algebra over Z_m

- **name** (Basic): Wagner's Generalized Birthday Problem / k-Tree and Modular Linear Algebra over Z_m
- **category** (Basic): cryptanalytic
- **description** (Basic): Wagner's generalized birthday problem (GBP) asks, given k lists of n-bit values, for one element from each list whose sum (XOR in (Z_2)^n, or addition mod m) is zero. Wagner's k-tree algorithm solves it by repeatedly merging pairs of lists and filtering on prescribed low-order bits, keeping list sizes balanced; heuristically it runs in time and memory O(k * 2^{n/(1+log k)}) (for k a power of two), so k=4 gives O(2^{n/3}) and larger k drives the exponent down. The modular version solves constrained subset-sum-like equations over Z_m (Random Modular Subset Sum, multi-set dense subset sum) and is the source of 2^{n/log n}-style subexponential bounds for dense instances: Lyubashevsky (2005) proves a modified k-tree solves Random Modular Subset Sum with modulus M = 2^{n^eps} (eps<1) in time and space 2^{O(n^eps / log n)} = M^{O(1/log n)}, and Shallue (ANTS 2008) refines this for asymptotic density below n/(log n)^2. The technique has become a standard cryptanalytic tool for knapsack, SIS, hash collisions and Equihash. Crucially, these are average-case / many-solution results and do not break the O*(2^{n/2}) worst-case barrier for Subset Sum.
- **worst_case_time** (Complexity): k-tree (Wagner, CRYPTO 2002): for k = 2^d lists of n-bit values, time (and memory) O(k * 2^{n/(d+1)}) under the heuristic list-size assumption; equivalently O(k * M^{1/(1+log k)}) group operations for modulus M = 2^n. For k = 4 this is O(2^{n/3}); for k = 2 lists it recovers the classical birthday O(2^{n/2}). Lyubashevsky's provable variant (2005): Random Modular Subset Sum with M = 2^{n^eps}, eps<1, in time 2^{O(n^eps/log n)} = M^{O(1/log n)} with success probability 1 - 2^{-Omega(n^eps)}. Shallue (ANTS 2008): fastest known for asymptotic density below n/(log n)^2, again 2^{O(n^eps/log n)}. All are average-case over random inputs, not worst-case.
- **space_complexity** (Complexity): k-tree uses memory of the same order as its running time, O(k * 2^{n/(d+1)}); reducing memory is Wagner's first open problem. Tradeoffs (Nikolic-Sasaki, Biryukov-Khovratovich, Dinur 2018) give curves such as T^2 M^{floor(log K)-1} = N and T^{ceil((log K)/2)+1} M^{floor((log K)/2)} = N. Dinur improves small K: K=6 with T=N^{1/3}, M=N^{1/6}; K=14 with T=N^{1/4}, M=N^{1/8}. Lyubashevsky's algorithm uses 2^{O(n^eps/log n)} time and space.
- **model** (Complexity): Classical random-access machine / word RAM with sorting, merging and group operations (XOR over (Z_2)^n, or addition in Z_m). The rigorous analyses model the input as independent uniform random values; the k-tree success is a high-probability average-case statement. Some cryptographic applications use a random function H (random-oracle heuristic).
- **randomized_or_deterministic** (Complexity): Randomized (Monte Carlo): succeeds with high probability on random instances. Wagner's original analysis is heuristic; rigorous high-probability analyses were given by Lyubashevsky (2005), Shallue (2008), Minder-Sinclair (SODA 2009) and Lin-Vasudevan (2024). It is not deterministic and not worst-case.
- **time_space_tradeoff_curve** (Complexity): A full family parameterized by the number of lists k (K in Dinur's notation) and the memory M. Wagner's k-tree sits at T = M = N^{1/(floor(log K)+1)} (N = 2^n). Dinur (2018) improves the curve to T^{ceil((log K)/2)+1} M^{floor((log K)/2)} = N for K >= 8 and to T^2 M^{floor(log K)-1} = N, e.g. K=8: T^3 M = N (from the previous T^2 M^2 = N), K=32: T^4 M^2 = N. For non-powers of two, K in {6,7,14,15} match the k-tree time with much less memory. For k=4 the single point is T = M = N^{1/3}.
- **numerical_exponent_and_record_year** (Complexity): k=4: O(2^{n/3}) (Wagner, CRYPTO 2002) - the source of 2^{n/3} for 4-list problems. Lyubashevsky (2005): 2^{O(n^eps/log n)} for M = 2^{n^eps}, giving a 2^{O(n/log n)}-style bound for dense modular subset sum. Shallue (ANTS 2008): multi-set improvement for density < n/(log n)^2. Dinur (2018): K=6 -> T=N^{1/3}, M=N^{1/6}; K=14 -> T=N^{1/4}, M=N^{1/8}.
- **problem_variant** (Scope): Generalized birthday problem / k-SUM / k-XOR (one element from each of k lists summing to zero); Random Modular Subset Sum (RMSS); multi-set / dense subset sum; and constrained subset-sum-like linear equations over Z_m. Also used for SIS, low-weight knapsack, subset/product problems, and hash-collision (Equihash).
- **applies_to** (Scope): Random high-density modular subset sum with modulus M = 2^{n^eps}, eps<1 (Lyubashevsky); dense / multi-set subset sum of asymptotic density below n/(log n)^2 (Shallue); the k-list GBP over (Z_2)^n or Z_m for arbitrary k (Wagner, Minder-Sinclair, Dinur); cryptanalytic instances where the solution set is large (many representations). It does not solve unique-solution worst-case Subset Sum.
- **coefficient_set** (Scope): The underlying selection is binary: each list contributes at most one chosen element, so the equation sum_i x_i a_i = t (mod m) has x_i in {0,1} with exactly k chosen terms in the k-list formulation. This is a 0/1 coefficient set with a fixed-cardinality (k-selection) structure. For multi-set dense subset sum, coefficients are bounded multiplicities.
- **density_regime** (Scope): High / medium density. RMSS density is d = n/log2(M); Lyubashevsky targets M = 2^{n^eps}, i.e. high density with many solutions, and assumes n^eps = omega(log n). Shallue's variant targets asymptotic density below n/(log n)^2. The method presupposes that the expected number of solutions is at least one (pigeonhole), so it is fundamentally a high-density / many-solution technique.
- **solution_regime** (Scope): Promised / numerous-solution regime. The birthday filter only helps when solutions are abundant; it finds one of many rather than certifying a unique solution, and it gives no worst-case guarantee.
- **cardinality_constraint** (Scope): Yes at the structural level: the k-list GBP fixes that exactly one element is chosen from each of the k lists, i.e. a fixed-cardinality (Hamming-weight-k) selection over the list positions. This structure is what makes the pairwise merge and modular filtering work.
- **key_technique** (Method): Wagner's k-tree / generalized birthday algorithm: partition the input into k lists, then build a balanced binary merge tree; at each internal node merge two child lists and keep only pairs whose value matches a prescribed set of low-order bits (or coordinates) modulo the modulus. The list-merging (birthday) lemma keeps the expected list sizes geometrically balanced so that lists of size about M^{1/(1+log k)} suffice, and the final merge yields the global zero. The modular variant performs the merges with modular addition and filters on residue classes, effectively solving a constrained linear/subset-sum equation over Z_m.
- **core_idea** (Method): Filtering each merge on a fraction of the n bit positions forces the number of surviving pairs to shrink by a controlled factor. Starting from k lists of size M^{1/(1+log k)}, the expected count of partial collisions at each level stays constant, so the birthday effect guarantees many partial matches and a final solution. Because the filtering is over modular residues, this is a combinatorial way to solve linear equations over Z_m without Gaussian elimination on an exponentially large solution space, and increasing k lowers the exponent toward n/log n.
- **reduction_pipeline** (Method): Dense / Random Modular Subset Sum -> split the n items into k groups -> constrained k-sum / generalized birthday over Z_m -> Wagner k-tree pairwise modular filtering -> witness. Multi-set dense subset sum -> multi-set birthday (Shallue). Knapsack / SIS / low-weight syndrome decoding -> modular linear equation -> GBP (with representation techniques for low density).
- **constructive_vs_existential** (Method): Constructive: the algorithm outputs the explicit list of k elements (a witness array of indices), not merely a proof of existence.
- **search_vs_decision_witness** (Method): It is a search algorithm: it returns an explicit witness (the chosen elements) with high probability, rather than deciding feasibility.
- **obstacle_to_2n3** (Frontier): The method relies on there being many solutions (high density / pigeonhole). For unique-solution or low-density worst-case Subset Sum, the number of candidates is too small for the birthday filter to make progress, and the lists remain large, so the algorithm degenerates to (or is worse than) 2^{n/2} meet-in-the-middle; no worst-case 2^{n/3} bound follows. Even at k=4, reaching 2^{n/3} would require solving a hard 4-list instance, and the k-tree's success at that size needs balanced lists of length ~2^{n/3} plus rigorous slack, which is not available in the unique-solution regime. Thus the 2^{n/log n} bounds apply only to dense/random instances, not to the worst-case problem where the MITM barrier (and the 2^{n/3} question) lives.
- **potential_to_break_mitm** (Frontier): medium for average-case / random high-density instances (it genuinely beats 2^{n/2} there, giving 2^{n/log n}-style bounds); low for worst-case Subset Sum, which is the setting of the 2^{n/3} question.
- **barrier_evidence** (Frontier): The k-tree is an average-case algorithm; the k-SUM conjecture and SETH-based lower bounds constrain worst-case improvements. Wagner's heuristic analysis was shown by Lyubashevsky, Shallue, Minder-Sinclair and Lin-Vasudevan to require strictly larger lists for high success probability, so the heuristic exponent understates the rigorous cost. Dinur-Keller-Klein and related work give lower bounds showing the k=3,4,5 list-algorithm complexities are optimal in certain density regimes. No worst-case reduction from Subset Sum to dense GBP is known.
- **open_questions** (Frontier): Wagner's two stated open problems: (1) efficient time-memory tradeoffs for GBP (progress by Nikolic-Sasaki, Biryukov-Khovratovich, Dinur 2018; still open in general); (2) complexity for K not a power of two (progress for K in {6,7,14,15} by Dinur). Further: can the average-case 2^{n/log n} bounds be extended to worst-case or unique-solution instances? Can the modular variant be derandomized? Can the rigorous list-size slack be eliminated (Lin-Vasudevan 2024 give asymptotically tight bounds for a wide range)?
- **conditional_hypothesis** (Assumptions): The positive average-case results assume uniformly random instances (and a random function H in cryptographic applications, i.e. a random-oracle heuristic); there is no lattice assumption. The surrounding worst-case hardness context uses the k-SUM conjecture and SETH.
- **worst_case_vs_average_case_guarantee** (Assumptions): Average-case only. Guarantees hold for random modular subset sum / random dense instances with high probability; no worst-case guarantee is claimed.
- **cryptographic_regime** (Assumptions): Directly cryptanalytic. Wagner motivated GBP by a subexponential attack on Schnorr and Okamoto-Schnorr blind signatures over elliptic curves (suggesting 1600-bit moduli). The k-tree underpins attacks on knapsack encryption, low-weight / inhomogeneous SIS (which formalizes collision finding), code-based schemes (Wave, CROSS, LESS), hash-based designs, and Equihash/Zcash proof-of-work. Density: high-density RMSS (d<1); for low-density knapsack, generalized-birthday/representation methods (Howgrave-Graham-Joux, Becker-Coron-Joux) give 2^{0.29n}-style results rather than the dense 2^{n/log n}.
- **pseudopolynomial_interaction** (Assumptions): Complements DP / pseudopolynomial methods: for small moduli M = 2^{O(log^2 n)} polynomial-time algorithms exist (Flaxman-Przydatek, STACS 2005; Lyubashevsky generalizes to M = 2^{c log^2 n}) and ordinary DP solves M = poly(n). The generalized birthday fills the medium/high-density gap between DP and lattice / meet-in-the-middle methods, and multi-set variants handle bounded multiplicities.

## Lattice Reduction for Subset Sum (LLL, BKZ, Lagarias-Odlyzko)

- **name** (Basic): Lattice Reduction for Subset Sum (LLL, BKZ, Lagarias-Odlyzko)
- **category** (Basic): cryptanalytic
- **description** (Basic): Lattice reduction attacks embed a subset-sum instance into an integer lattice so that the planted 0/1 solution corresponds to an unusually short (or close) lattice vector; running LLL or BKZ then recovers the solution. Lagarias and Odlyzko (JACM 1985) built the canonical lattice and showed that with an exact shortest-vector oracle almost all instances of density d < 0.6463 are solved in polynomial time; Coster, Joux, LaMacchia, Odlyzko, Schnorr and Stern (1991/1992) modified the lattice and raised the density threshold to d < 0.9408. In practice one replaces the SVP oracle by LLL (polynomial time, weak approximation) or BKZ with block size beta (exponentially better quality at exponential cost). These methods are average-case/heuristic: they succeed on almost all random low-density knapsacks, degrade near density 1 (the hardest regime), and give no worst-case algorithm for general Subset Sum. They are a main source of conditional hardness for knapsack cryptosystems and are directly cryptanalytic rather than an exponential-time worst-case technique.
- **worst_case_time** (Complexity): As an exact worst-case Subset Sum algorithm there is no proven bound: general Subset Sum is NP-hard and the lattice reduction step (SVP) is NP-hard. LLL itself is polynomial time, O(n^5 B^3) bit operations for an n-dimensional basis with B-bit entries (space O(n^2) integers), but it only gives a 2^{O(n)}-approximate shortest vector. BKZ with block size beta costs roughly 2^{O(beta log beta)} per tour with an enumeration SVP oracle, or 2^{Theta(beta)} (about 2^{0.292 beta} with sieving) per SVP call, plus poly(n) per tour; this is super-polynomial in beta. Conditional guarantee: if a perfect SVP/CVP oracle is available, almost all random instances with density d < 0.9408 are solved in polynomial time. No O*(2^{c n}) worst-case bound for general Subset Sum follows.
- **space_complexity** (Complexity): LLL: polynomial, O(n^2) lattice memory (O(n^2 log B) bits). BKZ: polynomial O(n^2) memory for the basis plus the enumeration tree; enumeration variants are polynomial-space. Sieving-based BKZ (e.g. G6K) trades time for memory and uses about 2^{Theta(beta)} space. No exponential space is inherent to LLL/BKZ enumeration.
- **model** (Complexity): Classical RAM / real-number (exact integer or rational) arithmetic on lattice bases; bit-complexity measured in bit operations. Sieving variants use large random-access memory. Classical only; quantum lattice reduction (e.g. quantum sieving) can speed the SVP subroutine but is not the classical attack considered here.
- **randomized_or_deterministic** (Complexity): LLL is deterministic. BKZ exists in deterministic and randomized forms; practical/high-quality BKZ (Schnorr-Euchner, BKZ 2.0, progressive BKZ) is randomized (random sampling, extreme pruning, rerandomization). The subset-sum attack itself is heuristic: it is expected to succeed with high probability on random low-density instances, and there is no proven worst-case success guarantee.
- **time_space_tradeoff_curve** (Complexity): Parameterized by the BKZ block size beta: larger beta gives a better approximation factor (roughly beta^{n/(2 beta)} root-Hermite factor) at exponentially higher time, and for sieving-based SVP also higher memory. Standard enumeration BKZ is polynomial-space with 2^{O(beta log beta)} time; sieving BKZ is 2^{Theta(beta)} time and 2^{Theta(beta)} space. This is a quality/cost tradeoff for the lattice primitive, not a subset-sum time-space tradeoff curve.
- **problem_variant** (Scope): Random low-density / hard-knapsack Subset Sum (cryptanalytic regime), including the Merkle-Hellman and related knapsack cryptosystems. The hardest knapsacks have density slightly above 1 (about 1 + log2(n/2)/n). Not Equal-Subset-Sum / Pigeonhole ESS, not Partition, and not the general worst-case decision problem.
- **applies_to** (Scope): Subset Sum with {0,1} coefficients on large integers (sparse/low-density instances), for which almost all instances of density below the threshold are solved given a sufficiently strong SVP/CVP oracle. Practical LLL/BKZ performs well for low density and dimensions up to a few hundred; it fails or becomes infeasible near density 1 and in high dimension. Extended variants with coefficients {-1,0,1} are covered by related analyses (Li-Ma, d < 0.488).
- **coefficient_set** (Scope): C = {0,1} for the standard attack (solution vector e in {0,1}^n, mapped to a short vector with entries e_i - 1/2 up to scaling). Extended low-density analyses use ternary coefficients C = {-1,0,1} (e.g. Li-Ma, with density threshold 0.488).
- **density_regime** (Scope): Low density d = n / log2(max_i a_i). SOLVED regimes under an SVP oracle: d < 0.6463 (Lagarias-Odlyzko 1985) and d < 0.9408 (Coster et al. 1991/1992). HARD regime: density close to 1 (empirically hardest around d ~ 1 + log2(n/2)/n), where the planted vector is no longer uniquely shortest and LLL/BKZ fail. High density (d > n/(n - log2 n), i.e. small numbers) is easier via DP/pseudopolynomial methods and cannot be injective for encryption. This is explicitly an average-case/density dichotomy, not a worst-case guarantee.
- **solution_regime** (Scope): Average-case / almost-all low-density instances, treated as promised or unique-solution (for sparse knapsacks the solution is unique with high probability). Not a pigeonhole/many-solution regime and not a general decision procedure for arbitrary instances.
- **cardinality_constraint** (Scope): No. The basic lattice attacks do not impose a fixed-cardinality (Hamming-weight) constraint; the solution weight is determined by the instance. Low-weight knapsack variants (e.g. Stern) are a separate line.
- **key_technique** (Method): Construct a lattice whose short vectors encode subsets (the Lagarias-Odlyzko lattice; Coster et al.'s CJLOSS modification, often with an extra coordinate to turn the inhomogeneous equation into a homogeneous short-vector problem) and run lattice basis reduction (LLL/BKZ, or an exact SVP/CVP oracle) to find the target short vector. BKZ generalizes LLL: for block size beta it repeatedly finds a shortest vector in each projected beta-dimensional block using an SVP subroutine (enumeration or sieving) and LLL-reduces, trading exponential time for a better approximation factor and hence a higher solvable density.
- **core_idea** (Method): The a_i and target T define an affine lattice in which the characteristic subset vector e corresponds to a lattice vector that is much shorter than generic vectors when the density is low; if this vector is the unique shortest one, an exact SVP solver returns it and the subset is read off. LLL finds only an approximate shortest vector but is cheap and suffices well below the threshold; larger BKZ blocks approximate SVP better, extending the density range at exponential cost. Above the density threshold the planted vector's length is comparable to that of other lattice vectors, so no reduction algorithm can reliably isolate it - this is exactly why density-1 knapsacks are cryptographically 'hard'.
- **reduction_pipeline** (Method): Subset Sum -> shortest/closest vector problem in a constructed integer lattice (Lagarias-Odlyzko lattice / Coster et al. modification; also modular variants with an extra congruence coordinate). Direction: Subset Sum reduces to lattice SVP/CVP; solve SVP by LLL/BKZ/enumeration/sieving. Related to simultaneous Diophantine approximation and to Coppersmith/Howgrave-Graham small-root methods.
- **constructive_vs_existential** (Method): Constructive: when lattice reduction (or an SVP oracle) returns the planted short vector, the attack outputs an explicit 0/1 witness. The guarantee is conditional on the reduction being strong enough and the instance being low-density/random; there is no existential-only variant.
- **search_vs_decision_witness** (Method): Search/witness: the successful attack returns the subset e in {0,1}^n. There is no worst-case decision guarantee; for hard instances the method simply fails to find a solution.
- **obstacle_to_2n3** (Frontier): Lattice reduction gives a polynomial-time average-case solution for low-density instances and a super-polynomial (but cryptanalytically practical) approach near the edge; it does not yield any worst-case exponential speedup. Near density 1 the planted vector is not uniquely shortest, so there is nothing for the reduction to find, and the general problem remains NP-hard. Consequently this line provides no O*(2^{(1/2-eps)n}) worst-case algorithm, let alone 2^{n/3}; it is orthogonal to the worst-case MITM barrier and mostly serves to explain why certain knapsacks are easy (low density) and why hard knapsacks (density ~1) resist lattice attacks.
- **potential_to_break_mitm** (Frontier): Low. It is an average-case/polynomial-time cryptanalytic technique for a restricted density regime; it neither targets the worst-case general problem nor improves the 2^{n/2} worst-case baseline, so it is unlikely to break the worst-case MITM barrier.
- **barrier_evidence** (Frontier): The density thresholds (0.6463 for Lagarias-Odlyzko, 0.9408 for Coster et al.) are asymptotic average-case guarantees that have resisted worst-case transfer; SVP is NP-hard and no polynomial algorithm solves it exactly. Above density ~0.94 the target vector is not uniquely shortest, and no known lattice algorithm recovers it in high dimension. Lattice methods inherently need random-like instances. Independent conditional lower bounds (SETH-based, Abboud-Bringmann-Hermelin-Shabtay) show Subset Sum cannot be solved in near-linear/near-quadratic time, and average-case k-SUM/hard-knapsack conjectures define hardness at density 1.
- **open_questions** (Frontier): Can the low-density threshold be pushed closer to 1 (and past it)? Is there a rigorous theory of BKZ on density-1 instances and its scaling in n and beta? What is the exact practical crossover between BKZ and generalized-birthday/representation attacks at density 1? Can lattice attacks be turned into worst-case algorithms or connected to the worst-case MITM barrier? Can sieving-based BKZ solve density-1 instances at cryptographically relevant dimension, and how do quantum sieving algorithms change this?
- **worst_case_vs_average_case_guarantee** (Assumptions): Average-case only, and heuristic. The density-threshold theorems say 'almost all' random instances of density below the threshold are solved (given a sufficiently strong SVP oracle). There is no worst-case guarantee: adversarial dense/structured instances and density-~1 instances are not covered.
- **cryptographic_regime** (Assumptions): Directly cryptanalytic. The Lagarias-Odlyzko / Coster et al. attacks broke Merkle-Hellman and many knapsack public-key cryptosystems, and low-density knapsack instances with n public weights can be solved in polynomial time when d < 0.9408 (with an SVP oracle). Hard knapsacks at density ~1 are the target regime where representation/birthday attacks (HGJ/BCJ/BBSS) take over; lattice reduction is the reason those cryptosystems are insecure at low density and the reason density-1 parameter choices are used.
- **pseudopolynomial_interaction** (Assumptions): Complementary regime split. Dynamic-programming/pseudopolynomial algorithms solve dense instances (small integers, high/medium density); lattice reduction solves sparse low-density instances (large integers). The two families meet around density ~1, which is empirically the hardest regime. Lattice reduction does not combine with DP in a single algorithm; it is the 'large-number' counterpart to the 'small-number' DP approach.

## Average-Case Modular Cryptanalysis of Subset Sum (Joux-Wegrzycki, modular arithmetic approach)

- **name** (Basic): Average-Case Modular Cryptanalysis of Subset Sum (Joux-Wegrzycki, modular arithmetic approach)
- **category** (Basic): cryptanalytic
- **description** (Basic): Average-case modular/representation cryptanalysis concerns the sparse, low-density regime of Subset Sum where one either (a) solves almost all random instances by reducing them to a lattice problem, or (b) for the hardest density-~1 regime, breaks the 2^{n/2} barrier heuristically using representation/birthday techniques with ternary coefficient sets. The focal recent result is Joux and Wegrzycki (STACS 2026), which improves the classical Lagarias-Odlyzko average-case algorithm by a modular arithmetic approach: lattice reduction is used to solve a linear system modulo a suitably large prime p, and by bounding the LLL-reduced basis vectors of the primal and dual lattices simultaneously, the admissible size of the integers drops from Omega(Gamma_LO) to Omega(sqrt(Gamma_LO)) - roughly doubling the density of solvable instances. The resulting tester is deterministic, works for all targets after a single lattice reduction, and yields polynomial-size certificates. On the density-1 frontier, ternary representations (coefficients in {-1,0,1} and {-1,0,1,2}) drive the best heuristic subset-sum attacks, e.g. Li (2025) reaches time O~(2^{0.2400n}) classically and O~(2^{0.1843n}) quantumly at density d = 1. All of this is average-case/heuristic and does not give a worst-case algorithm.
- **worst_case_time** (Complexity): Polynomial (average-case result): after a single call to a basis-reduction algorithm with parameter gamma, the algorithm builds a polynomial-time deterministic tester for the random instance, and every target T can be decided in polynomial time. Concretely, for any fixed constant c > 0, average-case instances with numbers in {1,...,Gamma_c}, log2(Gamma_c) = n^2 log log n / (c log n), are solved in n^{c+O(1)} time by the Lagarias-Odlyzko approach and in n^{c/2+O(1)} time by the Joux-Wegrzycki modular approach. No worst-case bound: for adversarial instances there is no guarantee, and the general problem remains NP-hard.
- **space_complexity** (Complexity): Polynomial in n and log(max a_i); the certificate/data structure behind the tester requires essentially a single matrix-vector multiplication (an n x n modular matrix M_p and its inverse). Lattice reduction itself uses polynomial space.
- **model** (Complexity): Classical RAM / real-number (exact integer and modular) arithmetic; lattice basis reduction with a quality parameter gamma (LLL, or textbook block reduction a la Gama-Nguyen with parameter Upsilon > 1). Randomness comes only from the uniform choice of the integers a_i; the algorithm is otherwise deterministic.
- **randomized_or_deterministic** (Complexity): The tester and its construction are deterministic; the success probability is over the random choice of the instance a_1,...,a_n and is at least 1 - 2^{-Omega(n log n)}. So it is an average-case guarantee with a deterministic algorithm and exponentially small failure probability (Las Vegas-style with a deterministic output once the matrix is built).
- **time_space_tradeoff_curve** (Complexity): Not a subset-sum time-space tradeoff; the result is polynomial time and space. The relevant parameter tradeoff is in the lattice-reduction strength: using reduction with parameter gamma -> 1 (stronger, more expensive) lets the algorithm handle a wider density range, giving running time n^{c/2+O(1)} for the density range log2(Gamma_c) = n^2 log log n / (c log n). Single point in terms of space.
- **problem_variant** (Scope): Average-case / random Subset Sum (RSSP) in the sparse low-density regime, with a unique solution with high probability; also the hard-knapsack density-~1 regime for the representation attack. Not Equal-Subset-Sum / Pigeonhole ESS, not Partition, not the general worst-case problem.
- **applies_to** (Scope): Instances with a_i chosen uniformly at random from {1,...,ceil(sqrt(Gamma_LO))} (improved bound), for which the algorithm decides for every target T whether a {0,1} subset sums to T. The density-1 ternary-representation algorithms apply to random knapsacks of density d = 1 with exactly one expected solution, and to syndrome/information-set decoding and LWE-style problems by adaptation.
- **coefficient_set** (Scope): The base Subset Sum has C = {0,1}. The cryptanalytic frontier uses larger signed/ternary coefficient sets: {-1,0,1} (BCJ), {-1,0,1,2} (BBSS), and the ternary tree representation of Li (2025); the extended low-density analysis of Li-Ma uses variables in {-1,0,1} with density threshold 0.488. These coefficient sets are design parameters of the representation, not the input domain.
- **solution_regime** (Scope): Average-case / almost-all inherent-solution regime: for sparse instances the solution is unique with overwhelming probability, and the modular tester decides every target. The density-1 representation algorithms assume a solution exists (expected count one).
- **cardinality_constraint** (Scope): No fixed-cardinality/Hamming-layer constraint is imposed in the modular arithmetic approach or the standard representation attacks; balanced solutions arise internally in the representation technique but the problem itself is unconstrained weight.
- **key_technique** (Method): Modular arithmetic approach: (1) reduce the integers modulo a prime p multiplied by a chosen scalar mu, using lattice reduction to build an n x n matrix M_p = ([mu_i a_j]_p) of centered residues with full rank and small l_1 norm (norm < p/2, i.e. no modular overflow); (2) then e is a solution iff M_p e = t_p = ([mu_i T]_p), so invert M_p and check whether the unique solution lies in {0,1}^n. The key technical step is a simultaneous length analysis of the primal and dual Lagarias-Odlyzko-style lattices (inspired by Coppersmith/Howgrave-Graham small-root methods) to construct suitable mu_i when the a_i are only sqrt(Gamma_LO) large. The density-1 frontier uses the representation technique: represent one solution in many ways over signed/ternary coefficient sets, filter pseudo-solutions by modular/parity constraints, and merge lists.
- **core_idea** (Method): If one can find multipliers mu_i so that all centered residues [mu_i a_j]_p are small (sum of |[mu_i a_j]_p| < p/2), then the modular linear system has no wraparound and exactly replicates the integer subset-sum equation; solving the modular linear system then recovers the 0/1 solution. Bounding both primal and dual lattice vectors under LLL supplies such multipliers whenever the inputs are small enough - half the bit-length that Lagarias-Odlyzko needed - which doubles the density. Because the resulting M_p depends only on the a_i and not on T, one reduction serves all targets. On density-1 instances the analogous idea is to inflate the search space with ternary representations so each true solution has many encodings, which can then be pruned.
- **reduction_pipeline** (Method): Subset Sum -> linear system modulo a large prime p, built via lattice reduction (a modular Lagarias-Odlyzko/Coppersmith-style lattice) -> invert the modular matrix and test e in {0,1}^n. Equivalent to a lattice SVP/CVP reduction with a modular twist; the density-1 branch reduces Subset Sum to generalized-birthday/representation collision finding with ternary coefficient sets.
- **constructive_vs_existential** (Method): Constructive: the algorithm outputs the multipliers/matrix and (by inversion) the subset vector, and the tester answers for every target. The guarantee is average-case (over random a_i); there is no worst-case constructivity claim.
- **search_vs_decision_witness** (Method): Both. Builds a polynomial-time deterministic decision tester valid for every T (oblivious to the target), and returns an explicit solution e in {0,1}^n when one exists (and certifies non-existence when the unique modular solution is not in {0,1}^n). Constructivity is proved for the average-case input distribution.
- **obstacle_to_2n3** (Frontier): This is an average-case, polynomial-time line of work for the sparse/low-density regime; it does not produce a worst-case exponential algorithm and therefore cannot by itself reach O*(2^{n/3}) for worst-case Subset Sum. Even after doubling the density, the cryptographic hard regime at d ~ 1 lies above the provable threshold, so the worst-case/general problem remains out of reach. The density-1 representation attacks are heuristic and are still at exponent ~0.24n (far above 1/3), and their analyses rely on randomness and well-distributedness assumptions. Thus the approach advances the cryptanalytic frontier but is orthogonal to the worst-case MITM barrier.
- **potential_to_break_mitm** (Frontier): Low. It is an average-case polynomial-time enhancement of a low-density attack plus a heuristic density-1 improvement; it does not attack the worst-case general problem or improve the worst-case 2^{n/2} baseline, so it is unlikely to break the worst-case MITM barrier. Its main value is in cryptanalysis and in sharpening the density frontier.
- **barrier_evidence** (Frontier): The Lagarias-Odlyzko density guarantee stayed unimproved for nearly 40 years (1985-2024), illustrating how hard the threshold is to move. The modular improvement still only doubles the admissible density and requires random instances; adapting it to arbitrary block-reduction algorithms is technical and not fully general. Density-1 attacks are heuristic (well-distributedness assumptions) and their exponents remain well above 1/3. Independent barriers: Subset Sum is NP-hard in the worst case; SETH-based lower bounds (Abboud-Bringmann-Hermelin-Shabtay) rule out near-linear/near-quadratic algorithms; the average-case k-SUM conjecture and planted k-SUM equivalence (Saha-Schwartzbach-Vasudevan) indicate hardness at density 1; and public-key encryption can be based on the hardness of dense/planted subset sum (Lyubashevsky-Palacio-Segev), ruling out worst-case-to-average-case collapse.
- **open_questions** (Frontier): Can the modular arithmetic approach be extended rigorously to all block-reduction algorithms (not just LLL and textbook block reduction)? Can the density threshold be pushed past the hard regime at d ~ 1, and can modular ideas be combined with ternary representation attacks? Is there a worst-case or planted-instance version of the modular tester? How far can the ternary representation exponent be lowered below 0.2400n classically / 0.1843n quantumly, and does it approach 1/3 or the MITM barrier? Can the Joux-Wegrzycki argument be applied to decoding/LWE analogues?
- **conditional_hypothesis** (Assumptions): The positive results assume uniformly random input integers (average-case) and rely on LLL/block-reduction quality estimates (Hermite-factor heuristics). Hardness/limitedness statements rest on NP-hardness of Subset Sum, SETH-based lower bounds (Abboud et al.), the average-case k-SUM conjecture and planted-k-SUM equivalence, and the existence of public-key encryption from planted/dense subset sum (Lyubashevsky-Palacio-Segev). The density-1 representation analyses additionally assume well-distributed lists and a prescribed representation count.
- **worst_case_vs_average_case_guarantee** (Assumptions): Average-case only. The Joux-Wegrzycki theorem is stated for uniformly random integers in {1,...,ceil(sqrt(Gamma_LO))} and gives success probability at least 1 - 2^{-Omega(n log n)} over the instance; the algorithm is deterministic given the instance. No worst-case guarantee, and no claim for adversarially structured instances.
- **cryptographic_regime** (Assumptions): Directly cryptanalytic. It sharpens the low-density attack on knapsack cryptosystems (density threshold roughly doubled relative to Lagarias-Odlyzko) and makes the attack oblivious to the target, so one lattice reduction can test many targets (relevant when an attacker sees many ciphertexts). At density ~1 the ternary-representation attacks are the state of the art for hard knapsacks and are also applied to information-set decoding and LWE-style problems.
- **pseudopolynomial_interaction** (Assumptions): Complementary: this line targets sparse instances with large integers (small density), whereas dynamic programming/proximity methods target dense instances with small integers. The Joux-Wegrzycki extension explicitly studies the boundary via the density range log2(Gamma_c) = n^2 log log n / (c log n) and running time n^{c/2+O(1)}, connecting the sparse lattice regime to pseudopolynomial-style parameter tradeoffs. It does not itself use DP.

## Quantum Subset Sum and k-SUM (Bernstein-Jeffery-Lange-Meurer; Chukhin-Kulikov-Levitskii-Mihajlin)

- **name** (Basic): Quantum Subset Sum and k-SUM (Bernstein-Jeffery-Lange-Meurer; Chukhin-Kulikov-Levitskii-Mihajlin)
- **category** (Basic): quantum
- **description** (Basic): Quantum algorithms for worst-case Subset Sum and its parameterized k-SUM version. Bernstein, Jeffery, Lange and Meurer (PQCrypto 2013) gave the long-standing worst-case quantum upper bound O*(2^(n/3)) by splitting the input into three blocks, listing 2^(n/3) subset sums per block, and using quantum search / claw finding to match two lists against the third; the same paper also gave a heuristic O*(2^0.241n) random-instance algorithm combining Howgrave-Graham-Joux with a quantum-walk data structure on Johnson graphs. In 2026 Chukhin, Kulikov, Levitskii and Mihajlin replaced Wagner-style merging with a single four-block decomposition plus modular filtering by a random prime, obtaining a worst-case quantum k-SUM algorithm in time O~(n^{Psi_k}) with Psi_k = 2k/7 + O(1); instantiating it at k=7 and composing with the standard 7-block reduction yields an O*(2^(2n/7)) = O*(2^0.2857n) worst-case quantum algorithm for Subset Sum, improving the classical 2^(n/2) MITM baseline and the previous quantum 2^(n/3).
- **worst_case_time** (Complexity): Subset Sum: O*(2^(n/3)) worst-case (Bernstein-Jeffery-Lange-Meurer, 2013), improved to O*(2^(2n/7)) = O*(2^0.28571n) worst-case (Chukhin-Kulikov-Levitskii-Mihajlin, arXiv 2608.07309, Aug 2026) by reduction to worst-case 7-SUM. Worst-case k-SUM: O~(n^{Psi_k}) with Psi_k = (2k - floor(k/7) - floor((k+3)/7))/6 - [k=3 mod 7]/9 - [k=6 mod 7]/18, asymptotic to 2k/7 + O(1); this improves Tani's O~(n^{k/3}) for every k>3. For k=2, Ambainis (2007) gives O~(n^{2/3}). Pigeonhole Modular Equal Subset Sum: O*(2^(0.453n)) quantum by reduction to k-SUM.
- **randomized_or_deterministic** (Complexity): Bounded-error (Monte Carlo) quantum algorithms: quantum search, quantum walk (MNRS), amplitude amplification, phase estimation and Claw Finding give success probability at least 2/3 by standard amplification. Chukhin et al. additionally use a random prime and random m-element subsets, still with constant success probability; the guarantee is worst-case (over instances).
- **time_space_tradeoff_curve** (Complexity): BJLM's worst-case 3-block method is a tradeoff family: storing a table of 2^k sums (memory O*(2^k)) and quantum-searching the complementary 2^(n-k) choices in time O*(2^((n-k)/2)); balanced at k=n/3 gives O*(2^(n/3)) time and O*(2^(n/3)) memory. The simpler quantum MITM gives a 2^(n/3) time / 2^(n/3) space point. Chukhin et al. do not state a time-space tradeoff family (single point).
- **numerical_exponent_and_record_year** (Complexity): Worst-case Subset Sum quantum exponent: 1/3 = 0.33333 (Bernstein-Jeffery-Lange-Meurer, 2013); improved to 2/7 = 0.28571 (Chukhin-Kulikov-Levitskii-Mihajlin, Aug 2026). Random-instance quantum heuristic exponents reported: 0.241 (BJLM 2013 / Howgrave-Graham-Joux walk), 0.218 (BBSS 2020, as reported in arXiv:2608.07309), 0.1843 (Li 2025, heuristic ternary representation). Worst-case quantum k-SUM exponent Psi_k -> 2k/7.
- **problem_variant** (Scope): Vanilla exact worst-case Subset Sum (arbitrary n integers and target); parameterized k-SUM (k lists of size n, pick one entry per list summing to target); Pigeonhole Modular Equal Subset Sum. The earlier random-instance results (Schrottenloher 2021, BBSS 2020, Li 2025) target single-solution random k-SUM/k-XOR.
- **applies_to** (Scope): Exact feasibility/decision and search for arbitrary-input Subset Sum; k-SUM for all k>3 (Chukhin Theorem 1.2 improves Tani for every k>3); Pigeonhole Modular Equal Subset Sum (quantum O*(2^(0.453n))). The BJLM O*(2^(n/3)) result applies to worst-case (not merely random) inputs.
- **coefficient_set** (Scope): C = {0,1} for Subset Sum. k-SUM selects exactly one element from each of k lists (an indicator vector with one 1 per list). Modular filtering works modulo a random prime p and keeps the canonical representative of each nonzero residue. Pigeonhole Equal Subset Sum implicitly uses coefficients {-1,0,1} on two subsets.
- **density_regime** (Scope): Density-agnostic for the worst-case quantum bounds (they hold for arbitrary integers of any density d = n/log2(max|a_i|)). The random-instance algorithms (HGJ/quantum-walk line: 0.241, 0.218, 0.1843) target random, density~1 instances.
- **solution_regime** (Scope): Worst-case decision/search with no promise on the number of solutions (Chukhin et al. explicitly give a worst-case, not single-solution-random, guarantee). The single-solution random regime is the domain of the earlier Schrottenloher O~(n^{Phi_k}) bound.
- **cardinality_constraint** (Scope): No fixed cardinality for Subset Sum; k is exactly the cardinality parameter for k-SUM (choose one entry from each of k lists, i.e. a star of k chosen indices), and the algorithm's four blocks have prescribed sizes 3k/14, 4k/14, 3k/14, 4k/14.
- **key_technique** (Method): BJLM 2^(n/3): split into three blocks, enumerate 2^(n/3) subset sums per block, and use quantum search / claw finding (Tani-style) to find a pair matching the third list. Their random-instance algorithm combines Howgrave-Graham-Joux with a streamlined quantum-walk data structure (quantum radix trees) on a product Johnson graph. Chukhin et al. 2026: group the k lists into four consecutive blocks (~3k/14, 4k/14, 3k/14, 4k/14); choose small m-element subsets S2, S4 of the two large blocks; filter by a random prime p=O~(m) keeping one canonical representative per residue bucket; run a quantum walk over pairs (S2,S4) to rebuild coherent dictionaries cheaply across neighbouring states; use quantum search for the left residue q and Claw Finding to match exact sums.
- **core_idea** (Method): Grover/quantum search gives a quadratic speedup over naive exhaustive search: if one block is enumerated into a table of 2^(n/3) sums, the complementary 2^(2n/3) candidates can be searched in time 2^((2n/3)/2) = 2^(n/3). The k-SUM advance avoids Wagner's merging tree (whose analysis needs the partial sums to be well distributed) by using a single four-block decomposition plus a random-prime modular filter: with constant probability the relevant block-2 and block-4 sums land in the canonical residue classes, so the filter isolates exact matches without distribution assumptions. The quantum walk keeps dictionary-update cost low when moving between neighbouring (S2,S4) states. Asymptotically Psi_k = 2k/7, so the 7-SUM-to-Subset-Sum block reduction gives exponent 2/7, the natural limit of this pipeline.
- **reduction_pipeline** (Method): Subset Sum -> k-SUM by the standard block reduction: partition n integers into k blocks, list all 2^(n/k) subset sums of each block, then solve the resulting k-SUM. Chukhin et al. instantiate k=7 (lists of size 2^(n/7)); their worst-case quantum 7-SUM runs in O~(n^2), giving O*(2^(2n/7)). Within k-SUM they reduce to an unbalanced 4-SUM plus modular filtering, solved by quantum search and Claw Finding. BJLM instead reduce Subset Sum to a 3-block (3-SUM) instance and apply quantum claw finding.
- **constructive_vs_existential** (Method): Constructive/algorithmic: the procedures return an explicit k-tuple of indices (a witness subset) with constant success probability; they are search algorithms, not existence proofs. Chukhin et al. state their algorithm 'solves' k-SUM, i.e. finds a solution.
- **search_vs_decision_witness** (Method): Returns an explicit witness (the chosen indices / subset); both feasibility (decision) and search are covered. The Pigeonhole Modular Equal Subset Sum application is also a search for two equal-sum subsets.
- **obstacle_to_2n3** (Frontier): For the quantum line the 2^(n/3) threshold is already surpassed (Chukhin et al. give 2^(2n/7) < 2^(n/3)); the precise remaining obstacle is going substantially below 2^(2n/7) toward 2^o(n). Within the 7-SUM pipeline the Subset Sum exponent is pinned to (1/7)*log2-time exponent of 7-SUM, and the best worst-case quantum k-SUM exponent is Psi_k ~ 2k/7, so one would need a better worst-case quantum k-SUM algorithm or a fundamentally different reduction; Tani's near-optimal claw-finding bound O~(n^{k/3}) limits the final matching primitive, and Wagner/merging-tree barriers constrain the random-instance techniques that do not give worst-case guarantees. For the classical target 2^(n/3), quantum speedups do not transfer to classical worst-case algorithms.
- **potential_to_break_mitm** (Frontier): High in the quantum model: both 2^(n/3) and 2^(2n/7) strictly beat the classical worst-case MITM baseline 2^(n/2) (and 2^(2n/7) beats the previous quantum record). Medium-to-low for pushing the quantum exponent far below 2/7 without a new worst-case quantum k-SUM breakthrough. This has essentially no bearing on whether the classical worst-case MITM barrier can be broken.
- **barrier_evidence** (Frontier): Tani (2009) gave a near-optimal quantum Claw Finding algorithm in O~(n^{k/3}) with a matching-type lower bound, so improvements must come from better reductions/structure rather than a faster claw-finding primitive. The classical k-SUM conjecture asserts meet-in-the-middle O~(n^{ceil(k/2)}) is optimal (its quantum analogue is less developed). Schrottenloher/Wagner-style merging trees face distribution and barrier constraints and only give random-instance guarantees. No unconditional quantum lower bound rules out 2^o(n) for Subset Sum; ETH/SETH give classical, not quantum, conditional lower bounds.
- **open_questions** (Frontier): Can the worst-case quantum k-SUM exponent be reduced below Psi_k (equivalently below 2k/7 + O(1))? Does a worst-case quantum Subset Sum algorithm in O*(2^(cn)) with c < 2/7 exist? Can the modular-filtering quantum walk be derandomized or made space-efficient? ## Pseudopolynomial-Regime Algorithms and Proximity for Subset Sum

- **name** (Basic): Pseudopolynomial-Regime Algorithms and Proximity for Subset Sum
- **category** (Basic): pseudopolynomial
- **description** (Basic): The pseudopolynomial line for Subset Sum studies running times polynomial in the number n of items and in the target t (or the maximum item size), as opposed to the exponential-in-n worst-case regime. Bellman's 1957 DP solves Subset Sum in O(nt); Bringmann (SODA 2017) gave the first randomized O~(n+t) algorithm via two-level color coding and sparse convolution, and Chan (SODA 2026) gave the first deterministic O~(t) algorithm, derandomizing both Bringmann's and the more recent output-sensitive algorithms using (min,+) matrix multiplication. The output-sensitive refinement was driven by Bringmann-Nakos (STOC 2020, O~(|S(X,t)|^{4/3})) and Bringmann-Fischer-Nakos (SODA 2025, O~(|S(X,t)|·sqrt(n))), which beats Bellman in every regime using a new additive-combinatorics sumset estimate. In parallel, proximity techniques (Eisenbrand-Weismantel's Steinitz-lemma proximity theorem and its algorithmic descendants, including small-item algorithms and l0-proximity) bound how far an optimal integer solution can be from a fractional/LP solution, reducing subset-sum-like problems with small items or bounded coefficients to small residual searches. Together these results show that the dense/small-value corner is essentially solved in near-linear time and use conditional lower bounds to delineate exactly where the remaining exponential hardness (and hence any 2^(n/3) target) must live.
- **worst_case_time** (Complexity): Bellman DP: O(nt) deterministic. Best randomized pseudopolynomial: Bringmann (SODA 2017) O~(n+t). Best deterministic: Chan (SODA 2026) O~(t); previously Koiliaris-Xu (SODA 2017) deterministic O~(t·sqrt(n)). Output-sensitive: Bringmann-Nakos (STOC 2020) O~(|S(X,t)|^{4/3}); Bringmann-Fischer-Nakos (SODA 2025) O~(|S(X,t)|·sqrt(n)), which beats Bellman's O(n|S(X,t)|) in all regimes. Small items: Polak-Rohwedder-Wegrzycki (ICALP 2021) O~(n+s^{5/3}) for Subset Sum (and O(n+s^3) for Knapsack), where s is the maximum item size; l0-proximity gives O~(n+w_max^{1.5}).
- **model** (Complexity): Classical word RAM / unit-cost RAM with word size O(log(nt)) (needed for FFT-based convolution, bitset DP, and (min,+) matrix multiplication). No quantum model; all results here are classical and deterministic or randomized as noted.
- **time_space_tradeoff_curve** (Complexity): Single points for the pseudopolynomial algorithms above. The broader exact-subset-sum literature has rich time-space tradeoffs (Schroeppel-Shamir T=2^n/S^2, Lokshtanov-Nederlof algebraization, Nederlof-Wegrzycki), but the pseudopolynomial/proximity results are not parameterized by a space budget. Bellman O(nt)/O(t) is the baseline point; output-sensitive algorithms range over the output size |S(X,t)|.
- **numerical_exponent_and_record_year** (Complexity): No exponential-in-n exponent: complexity is pseudopolynomial (polynomial in n and t). Timeline of constants: Bellman 1957 O(nt); Koiliaris-Xu 2017 deterministic O~(t sqrt n); Bringmann 2017 randomized O~(n+t); Jin-Wu SOSA 2019 simpler randomized O~(n+t); Bringmann-Nakos STOC 2020 O~(|S|^{4/3}); Bringmann-Fischer-Nakos SODA 2025 O~(|S| sqrt n); Chan SODA 2026 deterministic O~(t). These give O(2^{(1/3+o(1))n}) whenever t <= 2^{(1/3+o(1))n}, i.e. they meet the 2^(n/3) target throughout the small-value regime.
- **problem_variant** (Scope): Vanilla Subset Sum computing the set S(X,t) of all attainable sums up to t (output-sensitive / counting via generating functions); 0-1 Knapsack; Unbounded Subset Sum; a vector/generalized Subset Sum (BFN extend their ideas); Subset Sum with small items; C-Subset Sum / bounded ILP via proximity.
- **applies_to** (Scope): Given n positive integers X and target t, compute or decide the attainable subset sums S(X,t). Bringmann-Fischer-Nakos additionally handle a vector variant and Unbounded Subset Sum. Proximity results apply to bounded ILP, C-Subset Sum with constant coefficient set, and n-fold IP formulations of subset sum.
- **coefficient_set** (Scope): C = {0,1} for standard 0-1 Subset Sum; {0,...,c} (bounded variable values) for C-Subset Sum / bounded ILP; {-1,0,1} for Equal Subset Sum. Proximity bounds are stated in terms of the constraint dimension m and the maximum coefficient Delta = max|a_i|; small-item results are stated in terms of s = max a_i.
- **density_regime** (Scope): Targets the dense / small-value / small-item regimes: near-linear when t or the maximum item is small or polynomially bounded, output-sensitive in |S(X,t)|, and bounded-coefficient/constant-dimension for the ILP-proximity line. Crucially it does NOT address the low-density (n-bit, large-value) regime d = n/log2(max|a_i|) near or below ~1, which is exactly where the exponential-in-n algorithms (2^(n/2) MITM, 2^(n/3) target) are relevant.
- **solution_regime** (Scope): General decision/output of all attainable sums with no promise on the number of solutions; also the counting/output variant. No pigeonhole promise (Pigeonhole Equal Subset Sum is a separate promise problem).
- **cardinality_constraint** (Scope): No fixed-cardinality/Hamming-layer constraint; standard Subset Sum and Knapsack. (Cardinality-constrained variants are handled elsewhere.)
- **key_technique** (Method): Bellman DP. Bringmann: two-level color coding partitions items so each color class is small enough that its sumset is computed by sparse convolution / FFT, and the class sumsets are combined. Bringmann-Nakos: sparse convolution plus additive-combinatorics sumset estimates (sub-multiplicativity of sumsets) for output-sensitive computation. Bringmann-Fischer-Nakos: color coding + sparse convolution + a new additive-combinatorics estimate that bounds the cost of computing a sumset only inside the target box (without generating the much larger unrestricted sumset). Chan: derandomization using the Chan-Williams deterministic (min,+) matrix multiplication and a deterministic version of the Cygan et al. reduction from 0-1 Knapsack to (min,+) convolution. Proximity: Eisenbrand-Weismantel's Steinitz-lemma proximity theorem bounds the l1-distance between an optimal integer solution and an optimal LP solution; l0-proximity bounds the number of differing coordinates.
- **core_idea** (Method): Pseudopolynomial DP costs O(nt); color coding shrinks each color class enough that its sumset can be computed by FFT and the sumsets combined, yielding O~(n+t) for small t. Additive combinatorics supplies that sumsets cannot grow faster than a controlled function of the number of terms, enabling output-sensitive bounds that beat the O(n|S|) DP whenever the attainable-sum set is sparse. Proximity says an optimal solution differs from a fractional/LP solution in only a few coordinates (l0) or by a small l1 amount, so most items can be fixed and only a small residual instance remains to be searched (small-item DP). Constraint on the 2^(n/3) target: when t <= 2^{(1/3+o(1))n} the pseudopolynomial algorithms already run in O*(2^(n/3)) or faster, so a 2^(n/3) algorithm only adds value in the large-value/low-density regime; and SETH lower bounds rule out naive pseudo-poly x exponential hybrids.
- **reduction_pipeline** (Method): Subset Sum computes S(X,t) directly. Fine-grained reductions: 0-1 Knapsack reduces to (min,+) convolution (Cygan-Mucha-Wegrzycki-Wlodarczyk, ICALP 2017; derandomized by Chan, SODA 2026); C-Subset Sum reduces to bounded ILP / n-fold IP (proximity line); Subset Sum reduces to computing sumsets / sparse convolution. These reductions transfer upper bounds and conditional lower bounds between Subset Sum, Knapsack, (min,+) convolution, and ILP.
- **constructive_vs_existential** (Method): Constructive: the algorithms output the full set S(X,t) (and can return a witness subset). Proximity arguments are constructive in that they bound and locate the residual search; some proximity theorems are existence statements about a close optimal solution that then drive an algorithm.
- **search_vs_decision_witness** (Method): Primarily computes all attainable sums (a superset of deciding feasibility), from which a decision and a witness subset are immediate; some proximity-based methods return only the optimum/witness. Output-sensitive statements refer to listing S(X,t).
- **obstacle_to_2n3** (Frontier): Pseudopolynomial and proximity methods are polynomial in t (and/or s) and therefore give no O*(2^{(1/2-eps)n}) or O*(2^{n/3}) worst-case bound in the n-bit/low-density regime; they settle the dense/small-value corner, not the hard large-value corner. Precise constraint on a 2^(n/3) algorithm: it must strictly beat these methods exactly when t is large (near 2^n), where O~(t) is about 2^n; in the range t <= 2^{n/3} the pseudopolynomial algorithms already match the target, so a 2^(n/3) result must come from exploiting low-density structure. Moreover SETH-based lower bounds of the form 'no O(t^{1-eps} 2^{delta n})' show that one cannot obtain 2^(n/3) by combining the fastest pseudopolynomial algorithm (O~(t)) with a generic exponential search; and the Cygan et al. reduction to (min,+) convolution ties further progress to subquadratic (min,+) convolution, which is not known and is conjectured impossible.
- **potential_to_break_mitm** (Frontier): Low directly: these algorithms have polynomial exponent in t and do not change the 2^(n/2) worst-case exponent for large values. High indirectly: they clarify that the only remaining hard regime is large values / low density and provide the additive-combinatorics and proximity toolkit used by output-sensitive and representation/mixing approaches. The 2^(n/3) target, if reachable, must come from the low-density representation line, not from faster pseudopolynomial algorithms.
- **barrier_evidence** (Frontier): Abboud-Bringmann-Hermelin-Shabtay (SODA 2019 / ACM TALG 2022; arXiv:1704.04546) prove, under SETH, that Subset Sum cannot be solved in O(t^{1-eps} 2^{delta n}) time (a pseudo-polynomial x exponential lower bound). Bringmann-Wellnitz (SODA 2021; arXiv:2010.09096) prove the near-linear dense-subset-sum regime is optimal under SETH plus a strong k-SUM hypothesis. Cygan et al. (ICALP 2017) show 0-1 Knapsack is equivalent to (min,+) convolution, so barriers for convolution transfer. Polak-Rohwedder-Wegrzycki derive Min-Plus-Convolution-Conjecture-conditional lower bounds (no O((nt)^{0.99}) / O((st)^{0.99}) Knapsack algorithms). Proximity bounds limit ILP approaches to bounded coefficients/constant dimension.
- **open_questions** (Frontier): Is deterministic near-linear O~(n+t) time possible (Chan's O~(t) is deterministic but not O~(n+t))? Can the output-size exponent be pushed below 1, e.g. O~(|S(X,t)| n^{1/2-eps})? Can the proximity bound for unbounded-variable / general Subset Sum be improved (optimal proximity bounds)? Does an output-sensitive improvement translate into a better worst-case exponential exponent? How do proximity and additive-combinatorics tools interact with the low-density/high-value regime that governs the 2^(n/3) question?
- **conditional_hypothesis** (Assumptions): SETH (via the Abboud-Bringmann-Hermelin-Shabtay pseudo-polynomial lower bounds), the strong k-SUM hypothesis (Bringmann-Wellnitz dense-subset-sum lower bound), the (min,+) convolution conjecture (via the Cygan et al. equivalence), and ETH for the exponential regime. The proximity results themselves are unconditional (Steinitz lemma).
- **worst_case_vs_average_case_guarantee** (Assumptions): Worst-case guarantees: Chan is deterministic O~(t) on every instance; Bringmann/BN/BFN are randomized with high-probability worst-case guarantees. Output-sensitive bounds hold for every instance given its value of |S(X,t)|. Small-item algorithms give worst-case bounds but may use random partitioning inside. Proximity bounds are unconditional and worst-case for bounded ILP. None of these degrade to average-case-only.
- **cryptographic_regime** (Assumptions): Indirect. Low-density (high-value) knapsacks, where lattice attacks operate, are outside the pseudopolynomial regime: DP is exponential in n when t ~ 2^n. Pseudopolynomial algorithms apply to dense/small-item instances and thus do not break lattice-hard knapsacks; the proximity/ILP connection (n-fold IP) has not yielded knapsack-cryptosystem breaks. The pseudo-polynomial lower bounds do constrain the design space for attacks on small-value instances.
- **pseudopolynomial_interaction** (Assumptions): This item is the pseudopolynomial regime itself. The key interaction is hybrid algorithm design: run DP / color-coding / output-sensitive convolution when t or the items are small, and switch to MITM or representation/mixing when values are large. SETH lower bounds formalize that neither technique alone breaks the 2^(n/2) barrier. Proximity (Eisenbrand-Weismantel, l0-proximity, small items) directly connects the bounded-coefficient / small-item regime to bounded ILP and to the cardinality/coefficient-set structure exploited in worst-case representation mixing.

## N-fold / Hyperplane-Constrained ILP Equivalence and Proximity for Subset Sum

- **name** (Basic): N-fold / Hyperplane-Constrained ILP Equivalence and Proximity for Subset Sum
- **category** (Basic): ilp-equivalence
- **description** (Basic): This line views Subset Sum as the feasibility of an integer linear program and imports the structure theory of integer programming. Vanilla subset sum is exactly a hyperplane-constrained binary ILP (HBILP): find x in {0,1}^n with <a,x> = t, a single linear (hyperplane) constraint, i.e., an ILP with m=1 row and constraint entries bounded by Delta = max|a_i|. Two bodies of work are joined. (1) Proximity via the Steinitz lemma: Eisenbrand and Weismantel showed that an optimal integer solution of a standard-form ILP is within l1-distance m(2m*Delta+1)^m of an optimal fractional (LP) solution, a bound independent of the number of variables n, and used it to solve ILP in time (m*Delta)^{O(m)} * ||b||_inf^2, improving Papadimitriou's (m*Delta)^{O(m^2)}. (2) N-fold / block-structured IP: De Loera-Hemmecke-Onn-Weismantel defined n-fold IPs (a constraint matrix consisting of a first row of blocks A1 and a block-diagonal A2), Hemmecke-Onn-Romanchuk gave an O(n^3 L) algorithm with cubic dependence on the number n of blocks when the block type is fixed, and later work (Eisenbrand et al., Knop-Koutecky-Mnich) extended this to combinatorial/4-block settings. Randolph and Wegrzycki (ESA 2024) connect the two worlds to subset sum via the additive-combinatorics notion of doubling constant C=|A+A|/|A|: they prove that bounded ILP feasibility is tractable when the column set has small doubling, that Subset Sum with bounded doubling is solvable in XP time n^{O_C(1)} (and Unbounded Subset Sum in n^{O_C(log log log n)}), and, most importantly, that attaining an FPT algorithm for bounded-doubling Subset Sum is equivalent to attaining a milestone result for the parameterized complexity of Box ILP, namely solving a hyperplane-constrained binary ILP in time Delta^{O(m)} * poly(|I|). Thus the exponential difficulty of subset sum is recast as a question about the dimension (number of constraints m) and additive structure of an integer program, not about enumerating subsets.
- **worst_case_time** (Complexity): No worst-case exponent below the meet-in-the-middle 2^{n/2} is obtained for vanilla {0,1} Subset Sum by this line. The concrete bounds are parameterized/pseudo-polynomial: standard-form ILP in (m*Delta)^{O(m)} * ||b||_inf^2 (Eisenbrand-Weismantel 2017/2020); n-fold IP in O(n^3 L) for fixed block type and ||A||_inf (Hemmecke-Onn-Romanchuk 2013); bounded-doubling Subset Sum in n^{O_C(1)} * poly(|I|) (an XP bound, not FPT) and Unbounded Subset Sum in n^{O_C(log log log n)} (Randolph-Wegrzycki ESA 2024). Instantiated for subset sum (m=1, Delta=max|a_i|) this is Delta^{O(1)} * poly(n), i.e., pseudo-polynomial in the item magnitudes.
- **model** (Complexity): Integer-arithmetic / unit-cost and word RAM (random-access machine with unit-cost integer arithmetic); ILP algorithms are stated in standard matrix form over Z with arithmetic operations counted, and the parameterized FPT/XP statements use the standard parameterized-complexity model. Not a quantum or circuit model.
- **randomized_or_deterministic** (Complexity): Deterministic. The n-fold and proximity algorithms (De Loera et al.; Hemmecke-Onn-Romanchuk; Eisenbrand-Weismantel) and the bounded-doubling algorithms and constructive Freiman theorem (Randolph-Wegrzycki) are deterministic; no randomness is required for the equivalence.
- **time_space_tradeoff_curve** (Complexity): single point (no explicit time-space tradeoff family is reported for this line; the results are parameterized running-time bounds rather than a space-budget curve).
- **problem_variant** (Scope): Vanilla 0/1 Subset Sum (the m=1 hyperplane constraint) and Unbounded Subset Sum; generalized C-Subset Sum with coefficient set C; k-SUM (near-linear algorithms and tight 4-SUM / near-tight k-SUM lower bounds under the k-SUM conjecture); and the general feasibility problem for bounded integer programs (Box ILP / hyperplane-constrained binary ILP, HBILP), including n-fold and block-structured IPs.
- **applies_to** (Scope): Exact feasibility/decision. The equivalence is between C-Subset Sum with bounded doubling constant and HBILP feasibility in time Delta^{O(m)} * poly(|I|); the small-doubling algorithm covers Subset Sum and Unbounded Subset Sum. N-fold IP covers integer programs whose constraint matrix is block-structured (a first row of block columns A1 plus a block-diagonal part A2 repeated n times). Restrictions: bounded doubling (substantial additive structure) is required for the FPT/XP subset-sum results; small m is required for the pseudo-polynomial ILP bounds.
- **coefficient_set** (Scope): C = {0,1} for vanilla Subset Sum, so |C| = 2 (variables x in {0,1}^n). Generalized/balancing variants use C subset of Z (e.g., C={-1,0,1} for Equal Subset Sum). The hyperplane constraint <Ax,s> = t is a single linear functional; |C| is not the parameter (the doubling constant C of the input set is).
- **density_regime** (Scope): Density-agnostic in intent: the parameter is the additive doubling constant C = |A+A|/|A| of the column/input set, not density d = n/log2(max|a_i|). Small doubling captures highly structured, low-additive-complexity sets (arithmetic-progression-like, including some low-density instances), while random dense instances with all-distinct sums have C ~ n/2 and lie outside the tractable regime. The worst-case dense regime is precisely where this line does not help.
- **solution_regime** (Scope): General decision/feasibility with no solution promise. The equivalence concerns deciding feasibility of HBILP / Box ILP and C-Subset Sum; no pigeonhole or numerous-solutions promise is assumed.
- **cardinality_constraint** (Scope): No fixed-cardinality/Hamming-layer constraint is part of the base problem; the binary ILP formulation leaves Hamming weight free. Adding a cardinality constraint would add a row, increasing m (relevant because the ILP bounds depend on m).
- **key_technique** (Method): Reduction of Subset Sum to feasibility of a hyperplane-constrained binary ILP (HBILP); a new efficiently constructive proof of Freiman's theorem (additive combinatorics) to algorithmically exploit bounded doubling; n-fold / block-structured ILP augmentation with Graver bases; LP rounding for n-fold IP; and proximity theorems proved via the Steinitz lemma, which orders a norm-bounded multiset of vectors summing to zero so that all partial sums stay bounded, yielding rounding bounds independent of n.
- **core_idea** (Method): Subset Sum is the feasibility of a one-row binary ILP: is there x in {0,1}^n with <a,x> = t? Integer-programming theory says a fractional LP optimum lies within a bounded l1-distance of an integer optimum (Steinitz-lemma proximity), so one can round and then augment locally along Graver-basis directions. When the input set has small additive doubling, the augmenting steps live in a low-dimensional generalized arithmetic progression of small volume, which makes the search space collapse and the problem tractable in the parameter C. This reframes the exponential hardness of subset sum as a question about the dimension/structure of the associated integer program rather than about enumerating all subsets, and gives a precise equivalence between the FPT status of bounded-doubling subset sum and a Box-ILP milestone.
- **reduction_pipeline** (Method): Subset Sum (C-Subset Sum) -> HBILP feasibility (Randolph-Wegrzycki Lemma 11, via the constructive Freiman theorem); bounded-doubling Subset Sum FPT <-> Box ILP milestone (Delta^{O(m)} * poly). N-fold IP block structure: constraint matrix [A1 A1 ... A1; A2 0 ... 0; 0 A2 ... 0; ...]. Proximity direction: optimal LP solution -> nearby optimal integer solution via Steinitz-ordered partial sums. k-SUM is handled by near-linear algorithms with lower bounds transferred under the k-SUM conjecture.
- **constructive_vs_existential** (Method): Constructive/algorithmic. The reductions are effective (given by explicit procedures), the ILP and n-fold algorithms return a feasible x, and the constructive Freiman theorem is a central new tool. The FPT equivalence is an algorithmic statement: a sufficiently fast HBILP/Box-ILP algorithm would yield an FPT subset-sum algorithm and vice versa.
- **search_vs_decision_witness** (Method): Decision/feasibility is the primary object, and a witness subset is read directly off the support of the ILP solution x, so constructivity is explicit and unconditional; the equivalence is between decision procedures, with witness recovery immediate from the returned vector.
- **obstacle_to_2n3** (Frontier): The framework does not lower the worst-case exponent for vanilla {0,1} subset sum. With m=1 the proximity/augmentation bound is exponential only in the (constant) number of constraints but polynomial in Delta=max|a_i|, giving a pseudo-polynomial Delta^{O(1)} * poly(n) algorithm; when the item magnitudes are exponential in n this is no better than Bellman's DP and far from 2^{n/3}. The tractable regime requires constant doubling, which fails exactly for the random/dense worst-case instances that drive the hardness of subset sum, and even then plain Subset Sum is only XP (n^{O_C(1)}), not FPT. The pivotal Box-ILP/HBILP milestone (feasibility in Delta^{O(m)} * poly, i.e., FPT with no super-polynomial Delta-factor beyond m) is open; until it is resolved this line yields no sub-2^{n/2} worst-case algorithm.
- **potential_to_break_mitm** (Frontier): Low for vanilla {0,1} subset sum: the line produces pseudo-polynomial or structure-restricted (FPT/XP in doubling) algorithms, not a sub-2^{n/2} worst-case bound. Medium as a structural bridge, because it precisely identifies which integer-programming structures (small m and small doubling) would have to be exploited, and could be combined with representation/mixing or additive-energy methods.
- **barrier_evidence** (Frontier): Constraints on this line: (i) tight ETH-based double-exponential lower bounds for the harder 2-stage stochastic ILP (Jansen-Klein-Lassota, Math. Program. 2023), showing block-ILP structure is not universally tractable and that n-fold may be a special, easier case; (ii) tight lower bounds for several ILP parameterizations (Knop et al.); (iii) the proximity bound m(2m*Delta+1)^m is exponential in Delta when m grows, so constant-m subset sum remains pseudo-polynomial; (iv) ETH/SETH lower bounds forbid 2^{o(n)} subset-sum algorithms, and no reduction from ILP complexity is known to give a 2^{Omega(n)} unconditional bound. No barrier specific to this line is known; it does not by itself break or prove the MITM barrier.
- **open_questions** (Frontier): Is bounded-doubling Subset Sum FPT, equivalently is HBILP/Box ILP solvable in Delta^{O(m)} * poly(|I|)? Can the doubling-constant parameterization be pushed from XP to a fixed exponential-base algorithm for arbitrary {0,1} instances? Can constructive Freiman + Steinitz proximity be combined with representation/mixing or additive-energy methods to reach 2^{(1/2-epsilon)n}? Does the HBILP/Box-ILP equivalence transfer ILP lower bounds (e.g., ETH-based block-ILP hardness) to subset sum? Can the cubic-in-n n-fold bound be made single-exponential in the block type while remaining practical?
- **conditional_hypothesis** (Assumptions): The algorithmic and equivalence results are unconditional. Hardness context uses ETH and SETH for subset sum and the k-SUM conjecture for the k-SUM lower bounds; the double-exponential tightness for 2-stage stochastic ILP is under ETH. No lattice or knapsack-cryptanalytic hardness assumption is invoked.
- **worst_case_vs_average_case_guarantee** (Assumptions): Worst-case over instances in the stated class (bounded doubling for the FPT/XP subset-sum results; arbitrary bounded ILPs for the proximity bounds). No average-case or random-instance assumption is used; the tractability is a worst-case guarantee within the structured regime.
- **cryptographic_regime** (Assumptions): Indirect. This line does not target random density~1 knapsacks and is not a knapsack-cryptanalysis attack; it concerns structured (small-doubling) instances and general ILP feasibility. Its cryptanalytic relevance is limited to clarifying the structure of the single-constraint knapsack ILP rather than to breaking lattice- or knapsack-based cryptosystems.
- **pseudopolynomial_interaction** (Assumptions): Central and explicit: the ILP viewpoint is a pseudo-polynomial/FPT question. For m=1 the algorithm is Delta^{O(1)} * poly(n), matching Bellman's O(nT) regime, and the Randolph-Wegrzycki equivalence states exactly when the pseudo-polynomial dependence on Delta can be removed (FPT for Box ILP <-> FPT for bounded-doubling subset sum). ## Conditional Lower Bounds and Barriers for Subset Sum

- **name** (Basic): Conditional Lower Bounds and Barriers for Subset Sum
- **category** (Basic): barrier
- **description** (Basic): This item collects the conditional lower bounds, fine-grained reductions, and hardness hypotheses that constrain exact subset sum and thus define what a hypothetical O*(2^{n/3}) algorithm would and would not contradict. Unlike NP-completeness, which only says no polynomial algorithm unless P=NP, fine-grained complexity conditions the exponent itself. The relevant assumptions are: ETH (no 2^{o(n)} algorithm for 3-SAT, hence none for non-sparse subset sum); SETH and its variants; the k-SAT-to-dense-Subset-Sum reduction of Abboud, Bringmann, Hermelin and Shabtay, which makes Bellman's O*(T) pseudo-polynomial algorithm conditionally optimal up to a T^{1-epsilon} * 2^{o(n)} factor; the k-SUM conjecture (no randomized O(n^{ceil(k/2)-epsilon}) algorithm), which predicts meet-in-the-middle optimality for k-SUM; the 3SUM conjecture (no truly subquadratic algorithm); the (min,+)-convolution hypothesis, tied to knapsack by Cygan-Mucha-Wegrzycki-Wlodarczyk and by Kuennemann-Paturi-Schneider; and the Orthogonal Vectors conjecture. The formal/empirical 'Meet-in-the-Middle barrier' for subset sum -- no O*(2^{(1/2-epsilon)n}) worst-case algorithm -- is a conjecture rather than a theorem; in Randolph's 2024 thesis it is treated with the dignity of a fine-grained hypothesis and even stated optimistically as a conjecture that subset sum CAN be solved in 2^{(0.5-epsilon)n}. The crucial takeaway: current assumptions rule out 2^{o(n)} (ETH) and pin the pseudo-polynomial T-dependence (SETH), but none of them is known to force a 2^{Omega(n)} lower bound with a constant below 1/2, so a 2^{n/3} algorithm would be a major breakthrough yet would not falsify any established hypothesis.
- **worst_case_time** (Complexity): Best proven worst-case upper bound: O*(2^{n/2}) (Horowitz-Sahni 1974), with only polynomial-factor improvement to O(2^{n/2}/n^{gamma}) for a constant gamma >= 0.5023 (Chen-Jin-Randolph-Servedio, APPROX/RANDOM 2023; randomized). Conditional lower bounds: under ETH no 2^{o(n)} algorithm; under SETH no T^{1-epsilon} * 2^{o(n)} algorithm for n items and target T (Abboud-Bringmann-Hermelin-Shabtay, SODA 2019 / TALG 2022); under the k-SUM conjecture no randomized O(n^{ceil(k/2)-epsilon}) algorithm for k-SUM; under the 3SUM conjecture no truly subquadratic 3SUM; under the (min,+)-convolution hypothesis no truly subquadratic (min,+) convolution. No unconditional 2^{Omega(n)} lower bound for subset sum is known beyond NP-hardness.
- **space_complexity** (Complexity): Not applicable to the lower bounds themselves. For context, the best space for a 2^{n/2}-time algorithm is O*(2^{n/4}) (Schroeppel-Shamir 1981), improved to O*(2^{0.249999n}) (Nederlof-Wegrzycki, STOC 2021) and O*(2^{0.246n}) (Belova et al., ESA 2024); space is an independent axis from the time-exponent barrier.
- **model** (Complexity): Word RAM / random-access machine and Turing machine for the algorithmic upper bounds; fine-grained reductions over these models for the conditional lower bounds. Randomized vs deterministic matters: the k-SUM conjecture is explicitly about randomized algorithms succeeding with high probability, while SETH/ETH-based bounds apply to both deterministic and randomized algorithms.
- **time_space_tradeoff_curve** (Complexity): The barrier concerns the time exponent 1/2 and is orthogonal to space: Schroeppel-Shamir give time O(2^n/S^2) for any space budget S <= O*(2^{n/4}); space can be driven down to 2^{0.246n} while the time exponent stays 0.5. No time-space tradeoff family crosses the 1/2 time exponent.
- **numerical_exponent_and_record_year** (Complexity): Time exponent record: 0.5 (Horowitz-Sahni 1974; Schroeppel-Shamir 1981 kept 0.5 with far less space). Only polynomial shaving is known: 2^{n/2}/n^{gamma}, gamma >= 0.5023 (Chen-Jin-Randolph-Servedio 2023). Space exponent record: 0.246 (Belova et al., ESA 2024). No confirmed time exponent strictly below 0.5 for worst-case vanilla subset sum.
- **problem_variant** (Scope): Vanilla exact/decision Subset Sum (dense instances for the SETH bound), Equal Subset Sum / Subset Balancing, Partition (C={-1,0,1}), k-SUM, 3SUM, (min,+)-convolution, Orthogonal Vectors, and parameterized k-SUM (k part of the parameter). Cardinality-constrained / fixed-Hamming-weight variants inherit the same barriers.
- **applies_to** (Scope): Worst-case exact subset sum. The SETH-based lower bound already applies to dense instances (large target), which is the hard regime for pseudo-polynomial methods. The meet-in-the-middle barrier is stated for the general worst case and the promise-free decision problem; it is density-agnostic for the exponent.
- **coefficient_set** (Scope): C = {0,1} for vanilla subset sum, so |C| = 2. Generalized/balancing variants use C subset of Z, e.g., C={-1,0,1} for Equal Subset Sum / Partition. k-SUM has no coefficient restriction (one item chosen from each of k lists).
- **density_regime** (Scope): The MITM barrier is density-agnostic (it bounds the 2^{n/2} enumeration regardless of density). The SETH T^{1-epsilon}2^{o(n)} lower bound holds for dense instances, the regime where Bellman's pseudo-polynomial algorithm is the relevant competitor. Low-density knapsacks admit lattice/reduction attacks (LLL/BKZ, Lagarias-Odlyzko), but those are average-case or heuristic and do not yield worst-case hardness or algorithms.
- **solution_regime** (Scope): General decision with no promise. Pigeonhole / numerous-solution variants (Pigeonhole Equal Subset Sum, Equal Subset Sum) admit algorithms below the MITM baseline, showing the barrier is regime-specific and does not automatically transfer to promised-solution versions.
- **cardinality_constraint** (Scope): A fixed Hamming weight can be imposed cheaply (adding a 0-value item lifts subset sum to a fixed-cardinality instance), so cardinality-constrained subset sum is at least as hard and inherits the meet-in-the-middle and SETH barriers. Cardinality is relevant because balanced solutions are the hardest case for MITM.
- **key_technique** (Method): Fine-grained reductions and equivalences: k-SAT -> dense Subset Sum (SETH); OR-Subset-Sum and AND-Subset-Sum / Direct-OR theorems; (min,+)-convolution <-> Unbounded Knapsack (and 0-1 Knapsack); 3SUM reductions; k-SUM meet-in-the-middle with the k-SUM conjecture; Orthogonal Vectors; and the formalization of a Meet-in-the-Middle optimality statement as a fine-grained hypothesis.
- **core_idea** (Method): Every known barrier is conditional: each hypothesis (ETH, SETH, k-SUM, 3SUM, min-plus convolution, OV) rules out a family of algorithms. Because subset sum is not known to be tightly equivalent to any single core problem at the level of the exponential exponent, the exact complexity between 2^{o(n)} and 2^{n/2} is not pinned down. The MITM barrier is a conjecture, and ETH/SETH/3SUM/min-plus do not imply a constant-below-1/2 exponent lower bound. A 2^{n/3} algorithm would therefore be a breakthrough but would refute only the (informal) claim that 2^{(1/2-epsilon)n} is impossible -- not ETH, SETH, 3SUM, min-plus, or NP != P.
- **reduction_pipeline** (Method): k-SAT -> dense Subset Sum (Abboud-Bringmann-Hermelin-Shabtay) yields the SETH lower bound and the Direct-OR theorem; (min,+)-convolution -> Unbounded Knapsack and back (Cygan-Mucha-Wegrzycki-Wlodarczyk; independently Kuennemann-Paturi-Schneider) ties knapsack to a quadratic MinConv barrier; 3SUM <-> many geometric/weighted problems (Gajentaan-Overmars, modern Patrascu/Vassilevska Williams formulation); k-SUM is the natural MITM target for subset sum and other reductions; OV conjecture under SETH.
- **constructive_vs_existential** (Method): The lower bounds are conditional/existential: they assert that no algorithm of a certain complexity class exists if a hypothesis holds. The reductions used to derive them are explicit and constructive, but they do not construct an unconditionally hard instance.
- **search_vs_decision_witness** (Method): Most statements concern the decision problem; the search/witness version is at least as hard. Some bounds (AND-Subset-Sum, Direct-OR) explicitly involve deciding whether one out of many instances is a YES instance, a strengthening relevant to search and to scheduling applications.
- **obstacle_to_2n3** (Frontier): There is no unconditional obstacle. ETH only forbids 2^{o(n)}, which a 2^{n/3} algorithm satisfies. The SETH-based subset-sum bound is about the pseudo-polynomial dependence (no T^{1-epsilon} * 2^{o(n)}) and permits 2^{Omega(n)} algorithms. The 3SUM, k-SUM, and (min,+)-convolution conjectures are not known to imply a 2^{Omega(n)} lower bound for subset sum (no tight exponential-exponent reduction is known). The only statement a 2^{(1/3)n} algorithm would contradict is the explicit Meet-in-the-Middle optimality hypothesis (no O*(2^{(1/2-epsilon)n}) algorithm), which is unproven and, in Randolph's thesis, even framed as an optimistic conjecture that subset sum CAN be solved in 2^{(0.5-epsilon)n}. The precise obstacle is thus the absence of a reduction making subset sum equivalent to 3SUM/k-SUM/OV/MinConv at the exponential-exponent level.
- **potential_to_break_mitm** (Frontier): Low as a route to breaking MITM -- this is a barrier line, and its role is to delimit which methods are ruled out. Its diagnostic value is high: it shows the MITM barrier is soft (not implied by any established hypothesis), so a 2^{n/3} algorithm is not blocked by current theory, only by the lack of a technique and by the specific, unproven MITM conjecture.
- **barrier_evidence** (Frontier): ETH: subset sum has no 2^{o(n)} algorithm (Impagliazzo-Paturi). SETH: Bellman's O*(T) cannot be improved to T^{1-epsilon} * 2^{o(n)} (Abboud-Bringmann-Hermelin-Shabtay, SODA 2019 / TALG 2022), with Direct-OR and AND-Subset-Sum corollaries. k-SUM conjecture: no randomized O(n^{ceil(k/2)-epsilon}) for k-SUM (Abboud-Lewi, ICALP 2013), implying MITM optimality for k-SUM. 3SUM conjecture: no truly subquadratic 3SUM. (min,+)-convolution hypothesis: no truly subquadratic (min,+) convolution, equivalent to subquadratic Unbounded Knapsack (Cygan et al.; Kuennemann-Paturi-Schneider). Orthogonal Vectors conjecture under SETH. On the algorithmic side, the best worst-case bound remains 2^{n/2}/n^{gamma} (CJR+S 2023), and MITM has resisted an exponent improvement for 50 years.
- **open_questions** (Frontier): Can ETH or SETH be strengthened to rule out 2^{(1/2-epsilon)n} (or even 2^{(1-epsilon)n}) for subset sum? Is there a tight reduction between subset sum and k-SUM or Orthogonal Vectors that transfers those conjectures to the exponential exponent? Is the Meet-in-the-Middle barrier provable under any standard assumption, or only an empirical regularity? Does the subset-balancing progress (Randolph-Wegrzycki 2025 / STOC 2026) extend to C={0,1} vanilla subset sum? Can the (min,+)-convolution equivalence be lifted from pseudo-polynomial knapsack to the exponential subset-sum regime? What is the exact relative complexity of Equal-Subset-Sum and subset sum?
- **conditional_hypothesis** (Assumptions): ETH (Impagliazzo-Paturi 1999/2001), SETH and forall-exists-SETH, the k-SUM conjecture (Abboud-Lewi 2013), the 3SUM conjecture, the (min,+)-convolution hypothesis, the Orthogonal Vectors conjecture, and the informal/formal Meet-in-the-Middle (Subset Sum) hypothesis. The last is not a standard assumption and is sometimes framed in the opposite (optimistic) direction.
- **worst_case_vs_average_case_guarantee** (Assumptions): All barriers are worst-case statements. The average-case picture differs sharply: average-case Equal Subset Sum / Subset Balancing is solvable in O(3^{0.387n}) (Chen-Jin-Randolph-Servedio, SODA 2022), below the average-case MITM benchmark, and recent worst-case algorithms beat MITM for broad coefficient sets (Randolph-Wegrzycki 2025). This shows the barrier is specific to worst-case vanilla subset sum.
- **cryptographic_regime** (Assumptions): Highly relevant. The SETH-based T^{1-epsilon} * 2^{o(n)} lower bound is the theoretical basis for the security margin of knapsack-based cryptosystems (e.g., Merkle-Hellman type) and matches the practical attack complexity; density~1 random knapsacks are the cryptanalytic hard case, where MITM is the standard attack. At low density, lattice (LLL/BKZ) attacks apply, so the conditional hardness is regime-dependent. The barriers bound feasible key sizes under the assumptions stated.
- **pseudopolynomial_interaction** (Assumptions): Central. Bellman's O(nT) pseudo-polynomial algorithm is conditionally optimal in its T-dependence under SETH (no T^{1-epsilon} * 2^{o(n)}). Bringmann-Fischer-Nakos (SODA 2025) beat Bellman in all regimes for the output-sensitive parameter |S(X,t)| but do not contradict SETH. The (min,+)-convolution equivalence ties Unbounded Knapsack to a quadratic barrier. Any 2^{n/3} algorithm would have to beat these pseudo-polynomial methods precisely in the dense regime where the SETH bound lives, while remaining consistent with it (since 2^{n/3} is not 2^{o(n)} * T^{1-epsilon} for polynomial T).

## Either-Or Subset Sum (EOSS)

- **name** (Basic): Either-Or Subset Sum (EOSS)
- **category** (Basic): problem-variant
- **worst_case_time** (Complexity): O*(2^{0.461n}) randomized worst-case (Theorem 6 of Randolph's thesis), i.e. O(2^{(0.5-eps)n}) with eps = 0.039 > 0.03. This beats both the meet-in-the-middle barrier O*(2^{0.5n}) and the then-best worst-case Equal-Subset-Sum algorithm O*(3^{0.488n}) = O*(1.7088^n) of Mucha-Nederlof-Pawlewicz-Wegrzycki (ESA 2019). The thesis also reports, in a remark, that a careful modification of Algorithm 1 of Austrin-Kaski-Koivisto-Nederlof (2016) yields a full EOSS solution in O*(2^{0.421n}) (and that the decision variant is implicit in that work at O*(2^{0.480n})).
- **model** (Complexity): Standard word RAM / unit-cost RAM with O(log(sum of inputs))-bit words; the EOSS result is a classical (non-quantum) exponential-time algorithm.
- **randomized_or_deterministic** (Complexity): Monte Carlo with one-sided error: never returns a false positive and succeeds with probability 1 - o(1) on every input (internal randomness: a random prime p, random residue r, and random subsampling; success can be amplified by repetition).
- **time_space_tradeoff_curve** (Complexity): single point (no time-space tradeoff family is presented for EOSS).
- **numerical_exponent_and_record_year** (Complexity): Base 2, exponent 0.461 (equivalently 0.5 - eps with eps = 0.039), from Randolph's 2024 thesis / 2023 preprint; an alternative claimed bound of 2^{0.421n} is noted. Record year: 2023/2024.
- **applies_to** (Scope): Given n integers X and target t, return either A with sum(A) = t or two distinct A, B with sum(A) = sum(B). No density restriction and no promise on the input; the guarantee is only that a witness for whichever sub-problem admits one is returned with high probability.
- **coefficient_set** (Scope): C = {0,1} for the Subset Sum branch (|C| = 2) and C = {-1,0,1} for the Equal Subset Sum branch (|C| = 3); EOSS is the task of solving Generalized Subset Sum on either coefficient set.
- **density_regime** (Scope): Density-agnostic: EOSS is a worst-case statement over all inputs, with no assumption on d = n/log2(max|a_i|).
- **solution_regime** (Scope): Hybrid / no promise. Unlike Pigeonhole Equal Subset Sum, existence is not guaranteed; the algorithm may answer 'No' when neither an SS nor an ESS solution exists.
- **cardinality_constraint** (Scope): No fixed-cardinality or Hamming-layer constraint is imposed.
- **key_technique** (Method): Structure-vs-randomness dichotomy combined with an adaptation of the Howgrave-Graham-Joux Representation Method to worst-case (not average-case) inputs: (i) modified meet-in-the-middle if a small Subset Sum solution exists; (ii) modified meet-in-the-middle if a small ESS solution exists; (iii) a structural lemma proving that an SS instance whose solution has few distinct subset sums is an easy ESS instance; (iv) otherwise, hashing partial candidate solutions into residue classes modulo a large random prime so that many distinct small subset sums 'mix' and many residue pairs (r, t-r) contain a solution pair; (v) a recovery step that either finds a pair or, if it sees too many colliding partial candidates, returns those collisions as an ESS solution.
- **core_idea** (Method): Partition instances into random-like and structured. Random-like/large-signature instances let the representation method's partial candidates hash evenly modulo a random prime, so a matching pair is found by MITM and pairwise candidate checks; structured instances, where a Subset Sum solution admits only few distinct subset sums, are shown to automatically yield a small Equal Subset Sum solution that MITM recovers. In the only remaining case the collisions encountered during recovery themselves constitute an ESS witness. The hybrid output ('either-or') is what allows the algorithm to keep the worst-case guarantee below 2^{n/2}.
- **reduction_pipeline** (Method): No reduction to an external problem. Internally it combines (a) a two-half meet-in-the-middle over the n inputs, (b) bucketing partial candidate solutions by their value modulo a random prime p (random restriction to a residue class), and (c) the representation method's signature/collision machinery. Conceptually EOSS is a 'sum-flavored' specialization of the Pigeon problem / PPP circuitry C(X): {0,1}^n -> {0,1}^n.
- **constructive_vs_existential** (Method): Constructive: on success it returns an explicit witness (a subset summing to t, or a colliding pair of subsets).
- **search_vs_decision_witness** (Method): Returns an explicit witness for either sub-problem; it never outputs a false positive and may output 'No'. Constructivity is proved for the randomized algorithm (probability 1 - o(1)).
- **obstacle_to_2n3** (Frontier): EOSS reaches exponent 0.461 (eps = 0.039) but does not solve vanilla Subset Sum (C = {0,1}); the 'either-or' escape to an ESS witness is essential. Structural results of the thesis indicate that instances defeating the current MITM/representation approaches are exactly those admitting small ESS solutions, so a 2^{(0.5-eps)n} bound for vanilla Subset Sum would require exploiting structure in the remaining hard regime without an ESS fallback. The exponent is small (0.039) and not shown optimal, and no time-space tradeoff is derived.
- **potential_to_break_mitm** (Frontier): Medium for the programme, low-to-medium for vanilla Subset Sum. EOSS is direct evidence that a natural sibling of Subset Sum can be solved below 2^{n/2} unconditionally, sharpening the circumstantial case for the (positive) formal MITM conjecture; but the two hard cases remain C = {-1,1} (Partition / Subset Sum) and C = {-2,-1,1,2}, where MITM has still not been beaten in the worst case (Randolph-Wegrzycki, STOC 2026).
- **barrier_evidence** (Frontier): There is no unconditional 2^{Omega(n)} lower bound for Subset Sum and ETH only rules out 2^{o(n)}; SETH gives pseudo-polynomial conditional lower bounds (Abboud-Bringmann-Hermelin-Shabtay) that do not forbid 2^{(1/2-eps)n}. Consequently the formal Meet-in-the-Middle conjecture (Randolph's thesis, Conjecture 1: there exists eps > 0 such that vanilla Subset Sum can be solved in time O(2^{(0.5-eps)n})) is an open positive conjecture, not a barrier. EOSS itself is a barrier-softening result: it shows a close variant breaks 2^{n/2} in the worst case, while the 3SUM/4SUM and k-SUM conjectures constrain only the structured-matching steps a general 2^{n/3} algorithm would need.
- **open_questions** (Frontier): Can the structure-vs-randomness approach be extended from EOSS to vanilla Subset Sum (or Partition), i.e. remove the ESS escape hatch? What is the best achievable exponent for EOSS (0.461, or the reported 0.421 via AKKN16 techniques, or lower)? Can EOSS be derandomized? Is there a matching conditional lower bound pinning the EOSS exponent? Can EOSS techniques combine with the worst-case representation/mixing machinery (Randolph-Wegrzycki) or log-shaving (Chen-Jin-Randolph-Servedio) to push vanilla Subset Sum?
- **conditional_hypothesis** (Assumptions): No assumption is needed for the EOSS upper bound (unconditional, randomized, one-sided error). The result is offered as evidence for the positive formal Meet-in-the-Middle conjecture of Randolph's thesis (Conjecture 1), which is itself unproven. Lower bounds for related problems rest on ETH, SETH (pseudo-polynomial regime) and PPP-completeness conjectures (Papadimitriou 1994).
- **worst_case_vs_average_case_guarantee** (Assumptions): Worst-case guarantee: for every n-integer instance the randomized algorithm succeeds with probability 1 - o(1) (amplifiable) and never returns a false positive. Randomness is internal to the algorithm, not assumed on the input.
- **cryptographic_regime** (Assumptions): Indirect. EOSS uses and adapts the representation technique that underlies hard-knapsack cryptanalysis (Howgrave-Graham-Joux, Becker-Coron-Joux), and its dichotomy is relevant to density ~1 knapsacks, but it is an exact worst-case algorithmic result rather than an attack; no specific density/sample-key parameters are given.
- **pseudopolynomial_interaction** (Assumptions): None in the stated result (EOSS ignores the numeric magnitude of items). The related number-balancing / Karmarkar-Karp differencing ideas appear in the same thesis but are not combined with EOSS.

## Equal-Subset-Sum and Pigeonhole Equal Subset Sum

- **name** (Basic): Equal-Subset-Sum and Pigeonhole Equal Subset Sum
- **category** (Basic): problem-variant
- **description** (Basic): Two closely related subset-balancing variants whose exponential target of O*(2^{n/3}) has already been reached for the pigeonhole case, while the unrestricted case still lags far behind. Equal-Subset-Sum (ESS): given n integers w_1,...,w_n with |w_i| <= 2^{poly(n)}, find two distinct subsets A, B with sum_{i in A} w_i = sum_{i in B} w_i. Pigeonhole Equal Subset Sum (PESS, Papadimitriou 1994): given n positive integers with total sum < 2^n - 1, find two distinct subsets with equal sum; a solution is guaranteed by the pigeonhole principle, so PESS is a total-search problem in the class PPP. The known exponential records are: PESS solved by a randomized algorithm in O*(2^{n/3}) (Stan Zhang, MIT Master's thesis 2024; refined by Ce Jin, Ryan Williams, Stan Zhang, ESA 2025), improving Jin and Wu's O*(2^{0.4n}) (ICALP 2024) and the O*(2^{n/2}) meet-in-the-middle baseline. For unrestricted ESS the best worst-case time is O*(1.6994^n) (Yamano-Shibuya 2026), improving O*(1.7067^n) (Randolph-Wegrzycki, STOC 2026) and O*(1.7088^n) (Mucha-Nederlof-Pawlewicz-Wegrzycki, ESA 2019). A recent FOCS 2026 paper (Bhati-Dutta-Joux-Rajasree-Wegrzycki) gives a deterministic poly(n)*M^{o(1)} pseudopolynomial algorithm for dense PESS (M = 2^{o(n)}), an average-case poly(n)*M^{1/4} algorithm, and a conditional lower bound tying substantially faster PESS algorithms to breakthroughs on approximate lattice problems (including finding short lattice vectors). For vanilla Subset Sum, by contrast, O*(2^{n/3}) remains far out of reach and even an O(2^{(1/2-eps)n}) worst-case algorithm is open.
- **model** (Complexity): Classical word RAM / unit-cost RAM (integer inputs of |w_i| <= 2^{poly(n)}). PESS is additionally studied as a TFNP total-search problem and is conjectured PPP-complete (Papadimitriou 1994); it is not a quantum result.
- **randomized_or_deterministic** (Complexity): Mixed by result. PESS O*(2^{n/3}) and O*(2^{2n/3}) are randomized (Monte Carlo, succeeded up to poly(n) factors); Jin-Wu O*(2^{0.4n}) is randomized. The FOCS 2026 dense M = 2^{o(n)} algorithm is deterministic; its poly(n)*M^{1/4} algorithm is randomized and holds in the average case. Unrestricted ESS algorithms (MNPW, Randolph-Wegrzycki, Yamano-Shibuya) are randomized/one-sided; the original MNPW 2019 result is randomized as well.
- **problem_variant** (Scope): Equal-Subset-Sum (ESS) and its pigeonhole-promised special case PESS. Both are Subset Balancing instances with coefficient set C = {-1,0,1} and target 0 (assign c_i in {-1,0,1}, not all zero, with sum c_i w_i = 0). Related to Partition (C = {-1,1}) and to the total-search class PPP.
- **applies_to** (Scope): ESS: n integers w_1,...,w_n with |w_i| <= 2^{poly(n)}, find distinct A, B with equal sum (if one exists). PESS: n positive integers w_1 < ... < w_n with total sum < 2^n - 1, find distinct A, B with equal sum (always exists). The pseudopolynomial FOCS 2026 results are stated for PESS with weights bounded by M in the dense regime M = 2^{o(n)} and in the average case.
- **coefficient_set** (Scope): C = {-1,0,1} for ESS/PESS (|C| = 3); PESS additionally restricts to positive weights and the promise sum w_i < 2^n - 1. It is the 'symmetric' family [-1:1] of Subset Balancing, as opposed to Subset Sum / Partition with C = {0,1} or {-1,1}.
- **density_regime** (Scope): PESS spans all densities but has a distinguished dense/pseudopolynomial regime: with M = max w_i, density d = n/log2 M. When M = 2^{o(n)} (high density, small bit-length) the FOCS 2026 algorithm runs deterministically in poly(n)*M^{o(1)} = 2^{o(n)} time; the average-case bound is poly(n)*M^{1/4}, improving poly(n)*M^{1/3}. The exponential O*(2^{n/3}) result is density-agnostic under the pigeonhole promise.
- **solution_regime** (Scope): ESS is general decision/search (a solution may not exist); PESS is a promised many-solution / total-search regime where a solution is guaranteed by pigeonhole and the goal is only to find one (PPP total search).
- **cardinality_constraint** (Scope): No fixed-cardinality constraint is imposed; solutions A, B may have any sizes (and can be assumed disjoint since (A\B, B\A) preserves equality).
- **key_technique** (Method): PESS (Jin-Wu -> Jin-Williams-Zhang): a structural characterization via F = sum_t max(0, f_t - 1), the number of colliding subset-sum pairs. If F is small the input must be close to the geometric progression 1,2,4,...,2^{n-1} up to additive error F; this bounds |w_i - 2^{i-1}| and forces every solution to come from a poly(n)-sized set of 'close pairs' X,Y of high-index elements, reducing the task to a much smaller Equal Subset Sum instance on the low k+1 elements with large F; if F is large, subsampling hits a solution and mod-p dynamic programming solves it. Jin-Williams-Zhang exploit the structural property even in the many-solution case, reducing to a small number of smaller ESS instances and balancing to 2^{n/3}. FOCS 2026 (Bhati-Dutta-Joux-Rajasree-Wegrzycki) uses block merging and modular pruning for the deterministic dense M = 2^{o(n)} algorithm, a birthday-paradox-based algorithm for the weak-pigeonhole regime, and Karmarkar-Karp differencing, plus an average-case analysis.
- **core_idea** (Method): The number of equal-sum pairs F measures how far the input is from the worst-case geometric progression. Small F means the numbers are nearly 1,2,4,...,2^{n-1}, so any equal-sum relation is tightly constrained and involves few 'close' high-order choices; this collapses PESS to a tiny ESS instance. Large F means solutions are abundant, so random subsampling and mod-p subset-sum counting find one quickly. Jin and Wu used the small-F structure but handled large F by subsampling; Jin-Williams-Zhang reused the structure in the large-F case to shrink the effective instance size, which is what buys the clean 2^{n/3} exponent. The FOCS 2026 line instead works in the pseudopolynomial parameter M and shows the M^{1/4} barrier is essentially tight under lattice hardness.
- **reduction_pipeline** (Method): PESS -> smaller Equal Subset Sum: guess poly(n) many 'close pairs' (X,Y) of elements outside the low block [k] (with k ~ log2 F), then solve an Equal Subset Sum instance on k+1 integers with large F via subsampling + mod-p dynamic programming (Jin-Wu Lemma 5/6). The FOCS 2026 conditional lower bound goes the other direction, reducing (approximate) lattice problems to fast PESS algorithms, i.e. a fast PESS algorithm would yield a breakthrough for finding short lattice vectors.
- **constructive_vs_existential** (Method): Constructive: the algorithms return an explicit pair of distinct subsets A, B with equal sum. PESS guarantees existence, and the algorithms produce the witness.
- **search_vs_decision_witness** (Method): Search/witness: PESS and ESS algorithms return the actual two subsets; PESS never returns a false witness. Constructivity is proved for the randomized PESS algorithm (success probability 1 - o(1) after amplification).
- **obstacle_to_2n3** (Frontier): For PESS the 2^{n/3} target is already attained but not beaten; the exponential algorithm is not known to be optimal and going below 2^{n/3} is open. The FOCS 2026 lattice-based conditional lower bound indicates that large further improvements in the pseudopolynomial parameter would imply breakthroughs on approximate lattice problems, so progress is expected to be constrained unless lattice hardness is circumvented. For unrestricted ESS the gap is much larger: the best worst case is around 1.6994^n (exponent ~0.7664 in base 2), so the 2^{n/3} target is not attained at all; the ESS techniques (representation method, bounded-space tradeoffs) do not obviously transfer to vanilla Subset Sum or reach 2^{n/3}.
- **potential_to_break_mitm** (Frontier): High for PESS (meet-in-the-middle already broken: 2^{n/2} -> 2^{0.4n} -> 2^{n/3}) and high for unrestricted ESS (1.7321^n MITM beaten to 1.6994^n). Low/medium as a route to vanilla Subset Sum: the structural pigeonhole promise and the {-1,0,1} coefficient set are used essentially, and no transfer to C = {0,1} or C = {-1,1} is known.
- **open_questions** (Frontier): Can PESS be solved faster than O*(2^{n/3}) (e.g. O*(2^{0.3n}) or better) and can the O*(2^{n/3}) algorithm be derandomized? What is the exact lattice assumption, reduction, and running-time threshold of the FOCS 2026 conditional lower bound, and does it extend to the exponential regime? Can the PESS structural technique (near-geometric input structure) or the block-merging/modular-pruning method be applied to unrestricted Equal-Subset-Sum, Partition, or vanilla Subset Sum? Can the poly(n)*M^{1/4} average-case bound be made worst-case, or proven tight unconditionally? Is the claimed O((5/3)^n) Monte Carlo ESS algorithm correct (it would supersede the currently cited state of the art if verified)?
- **conditional_hypothesis** (Assumptions): Lattice hardness (hardness of approximating shortest-vector problems / finding short lattice vectors) underlies the FOCS 2026 PESS conditional lower bound; PPP-completeness of PESS (Papadimitriou 1994) underlies the belief that no polynomial-time algorithm exists; SETH gives conditional lower bounds in the pseudopolynomial regime for Subset Sum (Abboud-Bringmann-Hermelin-Shabtay). The O*(2^{n/3}) upper bound for PESS is unconditional (randomized).
- **worst_case_vs_average_case_guarantee** (Assumptions): PESS O*(2^{n/3}) and the unrestricted-ESS algorithms are worst-case bounds (with internal randomness, one-sided error). The poly(n)*M^{1/4} FOCS 2026 result is explicitly average-case; the deterministic poly(n)*M^{o(1)} result holds worst-case but only for the dense regime M = 2^{o(n)}. The lattice conditional lower bound constrains algorithms in the average/pseudopolynomial regime.
- **cryptographic_regime** (Assumptions): Relevant via the conditional lower bound connecting fast PESS to approximate lattice problems / finding short lattice vectors (FOCS 2026), linking the problem to the hardness assumptions underlying lattice-based cryptography. ESS and Subset Balancing are also connected to knapsack cryptanalysis through the representation technique, but the exponential algorithms here are worst-case and not direct attacks; no density/sample-key parameters are specified.
- **pseudopolynomial_interaction** (Assumptions): Central. The FOCS 2026 results are formulated in the pseudopolynomial parameter M = max w_i: deterministic poly(n)*M^{o(1)} when M = 2^{o(n)}, and average-case poly(n)*M^{1/4} (improving poly(n)*M^{1/3}). The PESS structural lemma (near-geometric progression) and mod-p dynamic programming are pseudopolynomial techniques, and the same Jin-Wu subsampling lemma works for general Equal Subset Sum (the pigeonhole promise is not used in that step). This contrasts sharply with vanilla Subset Sum, where SETH rules out O(W^{1-eps}) pseudo-polynomial algorithms.

## Cardinality-Constrained / Fixed-Cardinality Subset Sum (the Hamming layer of Subset Sum; k-item subset sum; (C,k)-SUM)

- **name** (Basic): Cardinality-Constrained / Fixed-Cardinality Subset Sum (the Hamming layer of Subset Sum; k-item subset sum; (C,k)-SUM)
- **category** (Basic): problem-variant
- **description** (Basic): Cardinality-constrained subset sum asks, given n integers a_1,...,a_n, a target t, and a cardinality k (or a vector of k targets for k-Subset Sum), whether some subset S of exactly k items satisfies sum_{i in S} a_i = t. Equivalently, the search is restricted to the Hamming layer of weight k inside {0,1}^n. It is a distinct structural variant because the cardinality (support size / Hamming weight) is an additive resource that can be tracked alongside the sum: the pair (sum, |S|) is additive under disjoint union, so both dynamic programming and meet-in-the-middle extend to it cheaply. It appears in the literature in several guises: (i) k-Subset Sum with k disjoint subsets and k targets (Antonopoulos-Pagourtzis-Petsalakis-Vasilakis); (ii) (C,k)-SUM, the subset-balancing problem with coefficient set C whose solutions have exactly k nonzero coefficients (Randolph-Wegrzycki); (iii) low/fixed Hamming-weight subset sum, as used in low-weight discrete-logarithm and decoding cryptanalysis (Esser-May); and (iv) the Pigeonhole/Either-Or regime where a solution of cardinality about n/2 is guaranteed. In the representation/mixing technique for worst-case subset balancing, the algorithm guesses the solution's cardinality/support profile, and the 'mixing' step is precisely about spreading candidate vectors across Hamming layers and residue classes; cardinality control (via random restrictions) is therefore intrinsic to the mixing argument rather than an afterthought.
- **worst_case_time** (Complexity): There is no single canonical bound; the answer depends on whether k is a constant, part of the input, or about n/2. (a) For constant k in the k-SUM parameterization, meet-in-the-middle gives O_k(n^{ceil(k/2)}) time (the classical k-SUM bound; recorded for (C,k)-SUM as MITM running in O_k(n^{ceil(k/2)}) in Randolph's thesis). (b) For general k given as input, the standard exact pseudo-polynomial algorithm is a Bellman-style DP with an extra cardinality dimension, O(n k t) time (equivalently O(n t) per fixed cardinality), where t = target; exhaustive enumeration costs O(C(n,k)) = O(n^k) for small k. (c) Cardinality-constrained k-Subset Sum (k disjoint target subsets, with cardinality constraints on the solution subsets) can be solved in deterministic O~(n^{k/(k+1)} t^k) and randomized O~(n + t^k) time by FFT/color-coding methods building on Koiliaris-Xu and Bringmann (Antonopoulos et al., JOCO 2023/arXiv 2112.04244). (d) For the low-Hamming-weight cryptanalytic regime, the best known subset-sum algorithm is heuristic and runs in 2^{0.645n} with polynomial memory (Esser-May, EUROCRYPT 2020), improving BCJ's 2^{0.72n} random-subset-sum bound; it requires many solutions and is not a worst-case exact bound. (e) For k = Theta(n) in the worst case the problem inherits the general Subset Sum barrier: no O*(2^{(1/2-eps)n}) algorithm is known.
- **space_complexity** (Complexity): Cardinality-augmented DP: O(k t) (or O(t) with a decision-only formulation plus implicit cardinality tracking; the natural table storing both sum and count is O(k t) = O(n t)). Explicit O(t) space with recursive divide-and-conquer is achievable for the boolean version. Meet-in-the-middle: O(n^{ceil(k/2)}) pair storage for constant k, or O(2^{n/2}) for the vanilla split with cardinality pairs. The Esser-May low-weight algorithms use polynomial memory O(n^{Theta(1)}), which is their main selling point over memory-heavy representation methods.
- **model** (Complexity): Unit-cost RAM / word RAM for DP and meet-in-the-middle (the cardinality coordinate is an O(log n)-bit integer, so it fits word operations cheaply). The FFT/color-coding k-Subset Sum algorithms (Koiliaris-Xu, Bringmann, Antonopoulos et al.) are stated on the word RAM / algebraic (FFT) model. Esser-May is stated in the generic group/collision-finding model with polynomial memory.
- **randomized_or_deterministic** (Complexity): Mixed. DP and the plain cardinality-filtered meet-in-the-middle are deterministic. The k-Subset Sum algorithms of Antonopoulos et al. come in both a deterministic O~(n^{k/(k+1)} t^k) variant and a randomized O~(n + t^k) variant. Esser-May's low-weight subset-sum algorithms are randomized heuristics (collision finding).
- **numerical_exponent_and_record_year** (Complexity): Constant-k k-SUM/(C,k)-SUM meet-in-the-middle exponent ceil(k/2) in the number of items (classical, Horowitz-Sahni 1974 for k=2; recorded for (C,k)-SUM in Randolph's 2024 thesis). Low-Hamming-weight subset sum base-2 exponent 0.645 (Esser-May, EUROCRYPT 2020, record year 2020), improving 0.72 (Becker-Coron-Joux 2011). k-Sum with constant doubling constant C: O~(C^{ceil(k/2)} 2^{O(k)} n), matching the k-SUM-conjecture lower bound up to a C factor (Randolph-Wegrzycki, ESA 2024). Cardinality-constrained k-Subset Sum is pseudo-polynomial, so its 'exponent' is in t, not in n (Antonopoulos et al., 2023).
- **problem_variant** (Scope): Cardinality-constrained / fixed-cardinality Subset Sum (exactly k items), k-Subset Sum (k disjoint subsets with k targets), (C,k)-SUM (exactly k nonzero coefficients over coefficient set C), low/fixed Hamming-weight Subset Sum, and the balanced-solution slice (k ~ n/2) of vanilla Subset Sum, Partition and Equal-Subset-Sum.
- **applies_to** (Scope): Exact decision and search when the cardinality of the chosen subset is fixed to k (or is one of a small set of allowed cardinalities), including the search restricted to a single Hamming layer of {0,1}^n and the multiple-target k-Subset Sum. Also applies to subset balancing with bounded coefficient set C when the number of nonzero coefficients is fixed. Restriction: fixing the cardinality does not by itself remove worst-case hardness.
- **coefficient_set** (Scope): C = {0,1} for vanilla fixed-cardinality Subset Sum (each item chosen at most once, exactly k chosen). C = {-1,0,1} for fixed-support Equal-Subset-Sum / Partition formulations. General constant-size C (e.g. C = [-d:d] or C = [±d]) for (C,k)-SUM, where the cardinality is the number of nonzero coefficients; |C| affects the k-SUM base (C^{ceil(k/2)}).
- **density_regime** (Scope): Density-agnostic in the worst-case parameterization; the cardinality constraint is a Hamming-weight restriction, not a density restriction. The low-Hamming-weight cryptanalytic algorithms (Esser-May) target dense random instances with a_i in Z_{2^n} (many representations), which is the opposite of the low-density lattice-solvable regime.
- **solution_regime** (Scope): General decision/search for arbitrary k. A special promised regime is the pigeonhole/balanced case k ~ n/2, where a solution is frequently guaranteed and where representation/mixing methods count overlapping Hamming balls; this is the regime relevant to Equal-Subset-Sum and Pigeonhole Equal Subset Sum. Randolph's 'Either-Or' subset sum is a related 1-bit random-restriction variant.
- **cardinality_constraint** (Scope): Yes - the fixed-cardinality/Hamming-layer constraint is the defining feature of this item. Cardinality is treated as an explicit additive coordinate in DP and meet-in-the-middle, and as the solution profile/support size that is guessed and controlled in the representation-mixing technique and in bounded-coefficient balancing.
- **key_technique** (Method): Track cardinality as a second additive dimension: (i) Bellman/DP with a count coordinate, O(n k t); (ii) meet-in-the-middle matching pairs with equal (sum, cardinality), giving the k-SUM O_k(n^{ceil(k/2)}) bound; (iii) color coding for disjoint target subsets (CardColorCodingLayer, Antonopoulos et al.) and FFT-based modified characteristic polynomials with one extra variable per cardinality; (iv) in subset balancing, guess the solution's support/profile and use random restrictions to force the candidate solution into a chosen Hamming layer, with a mixing dichotomy ensuring that failure-to-mix implies an unbalanced or numerous-solution instance solvable elsewhere; (v) nested collision finding with polynomial memory for the low-weight regime (Esser-May).
- **core_idea** (Method): Cardinality is additive and cheap: |S| obeys |S ∪ T| = |S| + |T| for disjoint S, T, so the pair (subset sum, subset size) behaves like a two-coordinate knapsack and can be stored/enumerated as easily as the sum alone. Meet-in-the-middle over (sum, cardinality) reduces fixed-cardinality Subset Sum to a member of the k-SUM family, where the birthday tradeoff gives the n^{ceil(k/2)} exponent. In the balanced case k ~ n/2 the largest Hamming layer has size about 2^n/sqrt(n), which is within a polynomial factor of 2^n and of the MITM space, so the cardinality restriction alone provides essentially no worst-case savings; the useful structure comes from controlling which layer the solution lies in and how many representations it has.
- **reduction_pipeline** (Method): Fixed-cardinality Subset Sum -> k-SUM / (C,k)-SUM by appending the cardinality as a coordinate (and, for disjoint targets, by dimensional lifting to k sum-coordinates plus cardinality coordinates). In the representation/mixing direction the pipeline is reversed: a bounded-coefficient Subset Balancing instance is analyzed layer by layer over candidate Hamming weights, random restrictions pin the candidate weight, and modular filtering (representation technique) selects vectors that can recombine into a weight-k solution. Low-weight Subset Sum is also the search problem underlying low-weight discrete-logarithm cryptanalysis.
- **constructive_vs_existential** (Method): Constructive: all the algorithmic variants (DP, MITM, color coding, collision finding) can return the actual k-subset when one exists; the pigeonhole/existential arguments for guaranteed solutions are converted into witnesses by the corresponding constructive algorithms.
- **search_vs_decision_witness** (Method): Both: decides whether a k-item subset sums to t and, because the methods are constructive, returns an explicit witness (the k-subset, or the k disjoint subsets for k-Subset Sum). Constructivity is direct and unconditional for the deterministic algorithms.
- **obstacle_to_2n3** (Frontier): Fixing the cardinality does not by itself lower the exponent of vanilla worst-case Subset Sum: the hard balanced case k ~ n/2 lives in the largest Hamming layer, and the fixed-cardinality problem there is essentially the original problem with a polynomial-factor change in list size. The k-SUM conjecture asserts that the O_k(n^{ceil(k/2)}) meet-in-the-middle bound is optimal for k-SUM up to polynomial factors, so the cardinality parameterization is expected to be a barrier, not a route, toward 2^{n/3}. Any attempt to exploit cardinality to reach O*(2^{n/3}) must additionally leverage structure (small doubling constant, bounded coefficient set, or many representations), which is exactly where the worst-case representation-mixing line operates and where the C = [±1] Partition case currently resists.
- **potential_to_break_mitm** (Frontier): Low for the general fixed-cardinality problem in isolation. Medium as an analytical lens and as a component: cardinality control is central to the mixing step of the worst-case representation technique and to bounded-coefficient balancing, and (C,k)-SUM is provably easier when the doubling constant is small (Randolph-Wegrzycki). On sparse, unstructured, balanced-cardinality instances the MITM barrier is expected to remain.
- **barrier_evidence** (Frontier): The k-SUM conjecture (for every k >= 3 there is no O(n^{ceil(k/2)-eps}) algorithm) and the 3SUM conjecture constrain the constant-k case; SETH and the Strong k-SUM Hypothesis give matching conditional lower bounds for the pseudopolynomial/dense regime. Cardinality-constrained optimization parameterized by k alone is W[1]-hard / W-hard in general (naive enumeration is XP, O(n^k)), so no fixed-parameter tractable algorithm in k alone is expected for arbitrary binary-encoded weights. No unconditional lower bound rules out a 2^{(1/2-eps)n} worst-case algorithm for fixed-cardinality Subset Sum.
- **open_questions** (Frontier): Is there a worst-case O*(2^{(1/2-eps)n}) algorithm for fixed-cardinality Subset Sum with k ~ n/2? Can the cardinality-controlled mixing dichotomy and random-restriction machinery be pushed from bounded-coefficient balancing to C = [±1] (Partition) and fixed-cardinality {0,1} Subset Sum? Are there matching lower bounds for fixed-cardinality Subset Sum beyond the k-SUM conjecture? Can polynomial-memory low-weight techniques (Esser-May) be derandomized or given worst-case guarantees? Does parameterizing by both k and the doubling constant yield optimally efficient algorithms (the current (C,k)-SUM bound has a C-factor gap)? How do bounded-coefficient balancing algorithms behave when the solution's Hamming layer is sparse?
- **conditional_hypothesis** (Assumptions): The k-SUM conjecture (no O(n^{ceil(k/2)-eps}) for constant k), the 3SUM conjecture, SETH and the Strong k-SUM Hypothesis (pseudopolynomial/dense lower bounds), and the unproven Meet-in-the-Middle / Subset Sum hypothesis for the 2^{n/2} exponent. No hardness assumption is needed for the positive algorithms.
- **worst_case_vs_average_case_guarantee** (Assumptions): DP, meet-in-the-middle and the deterministic k-Subset Sum algorithms give worst-case guarantees. The Esser-May 2^{0.645n} low-weight result is a heuristic/average-case bound for random subset-sum instances with many representations, not a worst-case guarantee. The (C,k)-SUM constant-doubling algorithm is worst-case within its structural restriction (bounded doubling constant).
- **cryptographic_regime** (Assumptions): Relevant. Low-Hamming-weight subset sum and low-weight discrete logarithm are the cryptanalytic face of the cardinality-constrained problem; Esser-May (EUROCRYPT 2020) use low-weight subset-sum/dlog algorithms in the dense random regime (a_i in Z_{2^n}) to attack cryptographic parameters, and representation/collision methods with cardinality control are standard in knapsack and decoding (syndrome decoding finds low-weight vectors). The relevant regime is dense/random with many solutions, contrasting with the low-density lattice-solvable regime.
- **pseudopolynomial_interaction** (Assumptions): Strong and intrinsic. The most direct exact algorithm is the cardinality-augmented pseudo-polynomial DP, O(n k t); the k-Subset Sum FFT/color-coding algorithms of Antonopoulos et al. are pseudo-polynomial O~(n^{k/(k+1)} t^k) and O~(n + t^k); and the whole pseudopolynomial theory of Subset Sum (Bellman, Koiliaris-Xu, Bringmann) extends to the cardinality-constrained version by carrying a count coordinate. This is complementary to the exponential meet-in-the-middle regime.

## Practical Hybrids for Subset Sum: Branch-and-Bound, Horowitz-Sahni Variants, SAT/ILP Encodings, and Empirical Speedups

- **name** (Basic): Practical Hybrids for Subset Sum: Branch-and-Bound, Horowitz-Sahni Variants, SAT/ILP Encodings, and Empirical Speedups
- **category** (Basic): practical
- **description** (Basic): A large body of engineering work makes exact subset sum and 0-1 knapsack solvable in practice far beyond the regime suggested by worst-case O*(2^{n/2}) or pseudo-polynomial O(nt) bounds, by combining several algorithmic families and exploiting instance structure. The main ingredients are: (i) branch-and-bound with strong upper/lower bounds (LP relaxation, Lagrangian and cardinality-constraint bounds) and the 'core' concept, where a small subset of items around the greedy split item carries the optimal solution (Martello-Toth; Pisinger's expanding-core minknap/Balsub/combo); (ii) Horowitz-Sahni meet-in-the-middle and its decomposition/balancing variants (Pisinger's decomp), often hybridized with dynamic programming; (iii) pseudo-polynomial DP refinements (Bellman, word-RAM, balanced DP, Koiliaris-Xu O~(sqrt(n) t), Bringmann O~(n+t)); (iv) SAT/MaxSAT/ILP encodings with pseudo-Boolean and cardinality encodings (sequential counters, sorting networks, BDDs) and ILP solvers such as GUROBI; (v) lattice reduction (LLL/BKZ, Lagarias-Odlyzko) for low-density instances; and (vi) modern structure-aware and parallel solvers, including unique-subset-sum enumerators with controlled aliasing and GPU implementations of the two-list/Schroeppel-Shamir schemes. The recurring empirical lesson is that real difficulty is governed less by n than by structure: density, profit/weight correlation, the number of distinct subset sums (small doubling constant / high additive energy), the number/size of solutions, and whether the instance is 'ill-conditioned' (large LP-to-integer gap). Pisinger's 'Where are the hard knapsack problems?' shows that classic random benchmarks are easy while strongly correlated, inverse strongly correlated, almost strongly correlated and pure subset-sum instances remain hard, motivating robust hybrids.
- **worst_case_time** (Complexity): No practical hybrid improves the worst-case asymptotic bound. The best proven worst-case guarantees remain O*(2^{n/2}) via Horowitz-Sahni meet-in-the-middle (deterministic), O~(sqrt(n) t) deterministic pseudopolynomial (Koiliaris-Xu, SODA 2017), and O~(n + t) randomized pseudopolynomial (Bringmann, SODA 2017). Branch-and-bound, core algorithms, SAT/ILP encodings and lattice methods have no useful worst-case bounds (exponential in the worst case). Polynomial-factor improvements over 2^{n/2} exist (Chen-Jin-Randolph-Servedio, RANDOM 2023, O(2^{n/2}/n^{gamma}), gamma > 0.5023).
- **space_complexity** (Complexity): Varies by family: DP tables O(t) with space-reduction or O(nt) naively (balanced/minknap DP O(n w_max) or word-RAM O(n m / log m), m = max(c, z*)); branch-and-bound O(n) plus the current incumbent; meet-in-the-middle O(2^{n/2}) (or O(2^{n/4}) with Schroeppel-Shamir); low-space GPU implementations trade parallel work for reduced memory; the adaptive unique-sum enumerator stores only distinct sums O(|Sigma(S)|).
- **model** (Complexity): Practical implementations run on real word RAM / unit-cost RAM with word-level parallelism and cache/memory hierarchies; SAT/ILP solvers and GPU kernels add their own computational models. GPU work assumes a large number of parallel processors with limited per-thread memory and high memory-bandwidth pressure.
- **randomized_or_deterministic** (Complexity): Mixed: branch-and-bound, core DP and most SAT/ILP solvers are deterministic (with heuristic branching/polarity choices); Koiliaris-Xu is deterministic, Bringmann's near-linear algorithm is randomized (Monte Carlo); lattice reduction (LLL, BKZ) is polynomial-time but heuristic/approximate, so its success on low-density instances is not a worst-case guarantee; GPU and adaptive solvers are deterministic given their pruning rules.
- **time_space_tradeoff_curve** (Complexity): Well studied empirically and theoretically within families. Meet-in-the-middle/Schroeppel-Shamir gives T = O(2^n / S^2) for space S. DP admits space-time tradeoffs (full table vs. Hirschberg-style divide and conquer vs. balanced DP). The expanding-core approach itself trades a larger core (more enumeration) for stronger bounds, adapting at runtime. A single global practical time-space curve across hybrid solvers is not available.
- **numerical_exponent_and_record_year** (Complexity): No reduction of the leading 2^{1/2} worst-case exponent has been replaced by practical hybrids. Pseudopolynomial record: O~(sqrt(n) t) deterministic (Koiliaris-Xu, SODA 2017) and O~(n + t) randomized (Bringmann, SODA 2017); deterministic near-linear remains open (Jin-Wu, SOSA 2019, gave a simple near-linear randomized algorithm). Structural solver: adaptive unique-sum enumeration O*(U n^2) with U = |Sigma(S)| and a controlled-aliasing constant-factor sub-2^{n/2} guarantee (Salas, arXiv 2025).
- **problem_variant** (Scope): Vanilla decision/optimization Sunbset Sum and 0-1 Knapsack (weights = profits for subset sum), Partition / Number Partitioning, Multiple Subset Sum, Multiple Knapsack, k-Subset Sum, market split, cardinality-constrained packing, and the decision vs. optimization distinction.
- **applies_to** (Scope): General integer subset-sum/knapsack instances, with families where particular hybrids dominate: uncorrelated and weakly correlated instances (B&B), subset-sum and strongly correlated instances (core DP/combo, exhaustive/hybrid methods), low-density instances (lattice reduction), dense/small-item instances (DP and dense additive-combinatorics algorithms), and instances with few distinct subset sums or many solutions (unique-sum enumerators).
- **coefficient_set** (Scope): C = {0,1} for subset sum / 0-1 knapsack; C = {-1,0,1} for partition and equal-subset-sum. Some hybrid solvers add a cardinality/resource dimension but the base coefficient set remains {0,1} or {-1,0,1}.
- **density_regime** (Scope): Empirically the central axis. Low density (d = n / log2(max a_i) < ~0.94) is typically easy via lattice reduction; high density / dense instances (small item sizes, target poly(n)) are easy via DP and near-linear dense subset-sum algorithms; the hard middle is density around 1 (random knapsack-like, pure subset-sum instances) and strongly correlated knapsack data, where no structure is exploitable.
- **solution_regime** (Scope): General decision and optimization. Many practical instances have numerous solutions (especially randomly generated subset-sum/uncorrelated instances), which branch-and-bound exploits to find an optimal/feasible solution quickly, but proving optimality or infeasibility remains hard. Larger strongly/inverse-strongly correlated instances remain unsolved in practice.
- **cardinality_constraint** (Scope): Not part of the base problem, but cardinality constraints are a standard practical device: Martello-Toth and Pisinger use Lagrangian relaxation of cardinality constraints to strengthen upper bounds, and cardinality-aware DP/ILP is common in packing/portfolio/best-subset-selection applications.
- **key_technique** (Method): Hybrid algorithm engineering: (1) branch-and-bound with LP/Lagrangian bounds, surrogate relaxation and cardinality-constraint bounds, organized around a dynamically expanding 'core' of items near the greedy split item (Pisinger minknap/expknap/combo, Martello-Toth mtm/mt2); (2) dynamic programming refinements (Bellman, balanced/word-RAM, Koiliaris-Xu divide-and-conquer over realizable sums, Bringmann color coding); (3) Horowitz-Sahni meet-in-the-middle plus Pisinger decomposition/balancing; (4) SAT/MaxSAT/ILP encodings using pseudo-Boolean equality and cardinality encodings (sequential counter, sorting network, BDD), solved by CDCL/MaxSAT or integer-programming solvers (GUROBI); (5) lattice reduction (LLL/BKZ/Lagarias-Odlyzko) for low density; (6) parallel/GPU two-list and Schroeppel-Shamir variants; (7) structure-aware unique-subset-sum enumeration with duplicate pruning and controlled aliasing.
- **core_idea** (Method): Instead of attacking the worst case, exploit whatever structure the instance has: if items are uncorrelated, bounds prune almost everything; if a small core around the greedy solution contains the optimum, only the core need be solved exactly; if the number U of distinct subset sums is small (small doubling constant, high additive energy, duplicates, arithmetic progressions), enumerate only distinct sums rather than all 2^n subsets; if density is low, lattice reduction recovers the solution; if density is high, DP/convolution is near-linear. Different hybrids dominate different structure classes, and robust solvers test for structure and switch strategies, which is why practical hard families are exactly those that defeat all of these (strongly/inverse-strongly correlated, near-density-1, low-solution, ill-conditioned instances).
- **reduction_pipeline** (Method): Subset Sum <-> 0-1 Knapsack (equal weights and profits); Partition -> Number Partitioning (Complete Karmarkar-Karp); Subset Sum -> ILP/MaxSAT (pseudo-Boolean equality sum a_i x_i = t with cardinality encodings); Subset Sum -> SAT via an addition/comparison circuit or the classic 3-SAT-to-Subset-Sum digit/positional reduction in reverse; low-density Subset Sum -> lattice CVP/SVP (Lagarias-Odlyzko embedding, LLL/BKZ); market split -> ILP; dense Subset Sum -> sumset/convolution and additive-combinatorics algorithms.
- **constructive_vs_existential** (Method): Constructive: all practical solvers return an explicit subset (or knapsack solution) and a proof of optimality/feasibility; no purely existential results here.
- **search_vs_decision_witness** (Method): Both. Decision solvers answer feasibility; optimization solvers return an optimal witness and can certify optimality via bounds; meet-in-the-middle, core DP and dense algorithms all recover explicit witnesses.
- **obstacle_to_2n3** (Frontier): Practical hybrids are engineering optimizations, not exponent reductions. Their pruning and structure exploitation have no worst-case effect on the 2^{n/2} MITM barrier, and the instances that remain hard (Pisinger's strongly/inverse-strongly correlated and pure subset-sum families, near density 1, sparse random knapsacks without many representations) are precisely the unstructured worst-case-like instances. Reaching O*(2^{n/3}) requires an algorithmic exponent breakthrough on those instances, which hybrid pruning cannot supply; conversely, hard practical instances are a reality check that any claimed sub-2^{n/2} algorithm must survive.
- **potential_to_break_mitm** (Frontier): Low. Practical speedups of orders of magnitude come from constants, bounds, cores, memory hierarchy and parallelism, not from a better exponent; they do not chip away at the worst-case MITM barrier. Their value for the research program is as (a) a source of realistic hard-instance generators and (b) a baseline that any theoretical improvement should also beat in practice.
- **barrier_evidence** (Frontier): Pisinger's 'Where are the hard knapsack problems?' constructs structurally difficult instance families that defeat state-of-the-art bounds: strongly correlated and inverse strongly correlated cases (large LP-integer gap, low weight variation in the core), almost strongly correlated cases, and pure subset-sum instances where most upper bounds return the trivial value and cannot prune. Martello-Toth/Pisinger show no single bound dominates, motivating hybrids but not a complexity improvement. The generic 3-SAT-to-Subset-Sum reduction and the pseudo-Boolean nature of subset sum mean SAT/ILP solvers inherit exponential behavior on hard families; encoding choice (cardinality/pseudo-Boolean) changes constants and propagation but not the worst case. Density thresholds from lattice attacks (d < ~0.94) mark where one hybrid's power ends.
- **open_questions** (Frontier): Can robust practical solvers be designed that are simultaneously competitive on all of Pisinger's hard families and on modern cryptanalytic/benchmark instances? Can structure detection (doubling constant, additive energy, density, core size) be automated for online strategy switching? How far do GPU parallel two-list and Schroeppel-Shamir implementations scale in n, and what memory-bandwidth barriers are hit? Do strong SAT/pseudo-Boolean encodings plus CDCL ever provably dominate branch-and-bound on some family? Can the O~(sqrt(n) t) and O~(n+t) pseudopolynomial algorithms be made practical and deterministic? What is the true practical hardness curve for fixed-cardinality/market-split instances?
- **conditional_hypothesis** (Assumptions): SETH and the Strong k-SUM Hypothesis underlie the conditional lower bounds that say near-linear-time dense/pseudopolynomial subset sum is essentially optimal (Bringmann-Wellnitz, Abboud-Bringmann et al.); no hardness assumption is needed for the positive worst-case guarantees of MITM/DP. Lattice-based low-density success is heuristic (no worst-case guarantee).
- **worst_case_vs_average_case_guarantee** (Assumptions): The guarantees are split. DP and meet-in-the-middle are worst-case; Koiliaris-Xu is deterministic worst-case pseudo-polynomial; Bringmann's near-linear algorithm is randomized with a worst-case time guarantee (Monte Carlo correctness). Branch-and-bound, core algorithms, SAT/ILP, lattice reduction and adaptive/unique-sum solvers give only average-case or instance-specific performance, and their worst case is exponential (or, for LLL/BKZ, heuristic correctness on low-density instances).
- **cryptographic_regime** (Assumptions): Strongly relevant. Low-density subset-sum instances (d < ~0.94) are solvable in practice by LLL/BKZ lattice reduction (Lagarias-Odlyzko embedding), which is exactly the practical attack on Merkle-Hellman-type knapsack cryptosystems; density ~1 instances require meet-in-the-middle/representation attacks. ISD-style collision algorithms (Becker-Coron-Joux, Esser-May, MMT/BJMM with Schroeppel-Shamir tradeoffs) are the practical cryptanalytic hybrids for decoding/hard knapsacks and guide secure parameter choices.
- **pseudopolynomial_interaction** (Assumptions): Central. Practical hybrid design is largely about choosing between pseudo-polynomial DP (Bellman, balanced, minknap, Koiliaris-Xu, Bringmann) and exponential search (MITM, B&B, SAT/ILP), and combining them (DP inside branch-and-bound, core DP, hybrid B&B+DP as in Martello-Toth 1984). This interaction is the main reason real instances are easy: when t or the item sizes are small, DP collapses the problem to polynomial time.

- **empirical_evidence** (Evidence): Extensive. Pisinger (2003/2005) reports average solution times for uncorrelated, weakly/strongly/inverse-strongly/almost-strongly correlated, pure subset-sum and similar-weight classes across n up to 10,000, showing uncorrelated/weakly correlated instances solve in milliseconds while inverse-strongly correlated and pure subset-sum instances blow up (e.g. times of seconds to tens of seconds at n=100-1000 and unsolved at n>=200). Martello-Pisinger-Toth's combo solves large 0-1 knapsack instances (up to about 10,000 variables) in a fraction of a second on standard benchmarks. GPU two-list implementations report roughly 26x speedups on large instances, and low-space GPU variants report over 1000x in their best cases (workload-specific, not typical). The adaptive structure-aware solver (Salas 2025) reports near-dynamic-programming performance on instances with small doubling constant, duplicates or arithmetic progressions, and a guaranteed constant-factor sub-2^{n/2} speedup via controlled aliasing. LASSO (listing all subset sums with branch and bound) is reported faster than competitors on bounded subset sum when a solution exists, but with poorer growth when the target admits no subset.
